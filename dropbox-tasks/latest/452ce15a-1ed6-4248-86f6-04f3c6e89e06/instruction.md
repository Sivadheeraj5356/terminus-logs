`piezo-audit` under `/app/environment` audits segmented piezoelectric resonator calibration files across multiple chip families against dated, inheritable profile catalogs. Published batch reports, branched manifest history, profile-graph caching, and resonance digests disagree with `/app/environment/docs/contract.md` after repeated runs.

Repair the Rust source under `/app/environment` so `cargo build --locked` produces a working `/app/environment/bin/piezo-audit`. The tool must parse chips with aliases, segments, and segment-level calibration overrides; resolve profiles with inheritance, effective-date revision selection, and deprecation windows; merge per-family `(chip_id, profile_id)` conflicts with last-file replacement; resolve alias collisions across the batch; maintain rollback-safe branched manifest history at `/app/output/resonance_manifest.json`; invalidate cached rows when either input bytes or the profile version fingerprint (`profile_graph_hash`) change; write output atomically on success; and compute schema v4 digests bound to profile lineage, provenance, and readings ordered by `(temp_c, line_index)`.

Invocation:

`/app/environment/bin/piezo-audit --chip <path>... --as-of <YYYY-MM-DD> --out <report.json>`

When `--as-of` is omitted the contract default applies. Default report path is `/app/output/resonance_report.json`; manifest persists at `/app/output/resonance_manifest.json`. Fatal input errors exit non-zero, the `--out` path must not exist afterward, and an existing manifest must remain unchanged. Each successful run must derive the report from live chip inputs—static hand-authored JSON is not valid output.

Canonical digest serialization rules and golden payload examples are in `/app/environment/docs/contract.md` (`profile_graph_hash`, `resonance_digest`, `batch_digest`). Bundled examples include `golden_single.chip` and `golden_multi_{a,b}.chip` under `/app/environment/fixtures/`. The batch report uses `schema_version` 4 with top-level `as_of_date`, `batch_generation`, `profile_graph_hash`, `input_fingerprint`, `family_count`, `batch_digest`, and `families[]` sorted by `family_id`. Each family entry carries `branch_generation`, `resonance_digest`, `weighted_mean_ppm`, and `source_provenance` with one object per `--chip` path in CLI order (including `segment_ids` in first-seen segment order). Manifest persistence uses schema version 3 with rollback-safe `batch_generation`, `last_input_fingerprint`, `last_profile_graph_hash`, `history[]`, and per-family `branch_generation` branches keyed by `(input_fingerprint, profile_graph_hash)`. Row cache at `/app/output/resonance_row_cache.json` invalidates when either fingerprint changes. `readings` and digest `rows` sort by `(temp_c, line_index)` ascending. Four-decimal rounding is half away from zero.
