Build a TypeScript CLF access-log analyzer at `/app/src/index.ts`. It must read only regular `.log` files directly under `/app/logs`, ignore directories and symlinks, compile with the provided TypeScript config, and write `/app/report.json`.

Parse Combined Log Format lines with an IP, ident, user, timestamp, quoted request, status, bytes, quoted referer, and quoted user agent. Ignore empty or whitespace-only lines. Treat every other bad line as malformed, including lines with leading or trailing whitespace, malformed quoting, non-real timestamps, UTC offsets whose hour is not 00 through 23 or whose minute is not 00 through 59, status values outside 100 through 599, byte values other than unsigned decimal digits or `-`, and request fields that are not exactly `METHOD URL PROTOCOL` separated by single spaces. Support LF and CRLF files by removing only a trailing carriage return before validation.

The report must contain exactly these top-level keys: `total_requests`, `invalid_count`, `error_requests`, `total_bytes_transferred`, `status_breakdown`, `methods_breakdown`, `top_ips_by_bytes`, `top_urls_by_requests`, and `hourly_requests`. Count `error_requests` as successfully parsed entries with 4xx or 5xx status. Count `-` bytes as zero, bucket statuses into `1xx` through `5xx`, count methods as seen, strip query strings before URL aggregation, rank top IPs by bytes and top URLs by request count with lexicographic tie breaks, use exactly `ip` and `bytes` keys for each top IP entry and exactly `url` and `requests` keys for each top URL entry, limit each top list to five entries unless fewer exist, and aggregate request hours in UTC using zero-padded hour keys only for hours that occur.
