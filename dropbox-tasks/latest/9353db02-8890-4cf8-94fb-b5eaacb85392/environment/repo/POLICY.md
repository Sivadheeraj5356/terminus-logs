# Offline DNSSEC delegation policy

The input is exactly one JSON object with `now` (an unsigned Unix timestamp), `zone`, `parent_ds`, `dnskeys`, and `rrsets`. Object member names must be unique at every nesting level; duplicate members, unknown members, missing members, `null`, and a trailing JSON value are structural errors. Names are absolute ASCII DNS names: they must end in `.`, each label is 1–63 bytes, the full wire name is at most 255 bytes, and comparison/canonical encoding lowercases ASCII letters. The zone itself may not be `.`. Base64 fields use standard padded base64.

A DS has `key_tag`, `algorithm`, `digest_type`, and hexadecimal `digest`. Only algorithm 8 (RSA/SHA-256) and digest type 2 (SHA-256) are supported. A DNSKEY has `flags`, `protocol`, `algorithm`, and base64 `public_key`. Its RDATA is the two-byte big-endian flags, protocol byte, algorithm byte, then decoded public-key bytes. Its key tag is RFC 4034 Appendix B's alternating-byte checksum over that RDATA, including the carry. A delegating key is eligible only when flags are exactly 257 and protocol is 3. A DS digest is SHA-256 over the canonical wire encoding of the zone name followed by DNSKEY RDATA. At least one supported DS must exactly match an eligible supported DNSKEY; unsupported DS entries do not authenticate a key. RSA public keys use RFC 3110 encoding: a one-byte exponent length unless that byte is zero, in which case the next two bytes give the length, followed by exponent and modulus. Reject exponents below 3, even exponents, empty moduli, and malformed lengths.

Each RRset contains `owner`, `type`, `ttl`, `records`, and `signatures`. `type` is the numeric DNS type in 1–65535, `ttl` is unsigned, and each record is base64 wire-format RDATA. An RRset owner must be at or below the zone. Empty record sets are invalid. Every RRset needs at least one accepted signature. A signature has `type_covered`, `algorithm`, `labels`, `original_ttl`, `expiration`, `inception`, `key_tag`, `signer`, and base64 `signature`. It is eligible only if it covers the RRset type; uses algorithm 8; has the RRset TTL as original TTL; has a canonical signer equal to the zone; uses an authenticated DNSKEY; and satisfies `inception <= now <= expiration` with no serial-number wrap interpretation. `labels` is the count of labels in the signed owner name: it must equal the owner's label count, or be exactly one less for a wildcard proof. In the wildcard case the signed owner is formed by replacing the unmatched leftmost label with `*`; no other labels value is valid.

RSA/SHA-256 verification follows RFC 4034. The signed bytes begin with the RRSIG fields excluding the signature: type covered (2 bytes), algorithm (1), labels (1), original TTL (4), expiration (4), inception (4), key tag (2), and canonical wire signer name. Append every RR in canonical order. An RR is canonical signed owner name, type (2), class IN (2), original TTL (4), RDATA length (2), and RDATA. Sort these complete RR byte strings lexicographically and retain duplicate records. Verify SHA-256 with PKCS#1 v1.5.

The output reason codes are `bad_name`, `malformed_key`, `no_ds_match`, `bad_rrset`, `bad_signature`, and `invalid_input`. Report every applicable code once, sorted lexicographically. Structural JSON/type errors produce only `invalid_input`. Name errors add `bad_name`; malformed base64, DNSKEY material, signatures, or RSA encodings add `malformed_key`; an absent authenticated delegation adds `no_ds_match`; invalid owner/type/TTL/empty-record structure adds `bad_rrset`; and an RRset without an accepted signature adds `bad_signature`.
