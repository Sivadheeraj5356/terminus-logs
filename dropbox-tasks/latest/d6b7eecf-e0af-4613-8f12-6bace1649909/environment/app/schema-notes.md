# BookSort Game Contract

This document is authoritative for the puzzle engine. The public task description intentionally stays compact; implement every rule below exactly.

## Runtime and command surface

The environment is offline. Do not add third-party Go modules or use runtime downloads. Use only the Go standard library and the installed `sqlite3` command-line tool. Build the executable at `/app/bin/booksort`.

The required commands are:

- `new --db PATH --seed-db PATH --level ID`
- `show --db PATH`
- `move --db PATH --from SHELF --to SHELF`
- `undo --db PATH`
- `redo --db PATH`
- `status --db PATH`
- `history --db PATH`
- `hint --db PATH`
- `solve --db PATH [--max-depth N]`
- `audit --db PATH --seed-db PATH --level ID`
- `apply-plan --db PATH --file PATH`
- `apply-batch --db PATH --file PATH`
- `verify-ledger --db PATH --seed-db PATH --level ID`

The seed database schema is fixed: seed_levels(level_id TEXT PRIMARY KEY), seed_shelves(level_id TEXT, shelf_id TEXT, position INTEGER, capacity INTEGER, required_genre TEXT, sort_mode TEXT), seed_books(level_id TEXT, book_id TEXT, title TEXT, genre TEXT, sort_key INTEGER, shelf_id TEXT, slot INTEGER), and seed_edges(level_id TEXT, from_shelf TEXT, to_shelf TEXT). The new command creates or replaces the runtime database at --db from one level in --seed-db; if the runtime database already exists, discard its previous shelves, books, edges, and history.

Runtime state must stay in SQLite and must leave these tables available for inspection: shelves(shelf_id TEXT PRIMARY KEY, position INTEGER, capacity INTEGER, required_genre TEXT, sort_mode TEXT), books(book_id TEXT PRIMARY KEY, title TEXT, genre TEXT, sort_key INTEGER, shelf_id TEXT, slot INTEGER), edges(from_shelf TEXT, to_shelf TEXT), move_history(id INTEGER PRIMARY KEY AUTOINCREMENT, book_id TEXT, from_shelf TEXT, to_shelf TEXT, from_slot INTEGER, to_slot INTEGER, before_digest TEXT, after_digest TEXT, undone INTEGER), plan_runs(plan_id TEXT PRIMARY KEY, start_digest TEXT, final_digest TEXT, move_count INTEGER), batch_runs(batch_id TEXT PRIMARY KEY, start_digest TEXT, final_digest TEXT, step_count INTEGER), plan_steps(plan_id TEXT, step_index INTEGER, history_id INTEGER, after_digest TEXT), batch_steps(batch_id TEXT, step_index INTEGER, operation_id TEXT, history_id INTEGER, after_digest TEXT). Successful moves insert a move_history row with undone = 0 and the board digests described below. Undo restores the most recent row with undone = 0 and keeps that row by marking undone = 1; it should not delete history rows. The history command prints all move_history rows ordered by id as a JSON array to stdout, including undone rows, with keys id, book_id, from_shelf, to_shelf, from_slot, to_slot, before_digest, after_digest, and undone. Numeric fields must be JSON numbers, not strings; digests are 64-character lowercase hex strings.

For each successful move, before_digest is the SHA-256 hex digest of the canonical board snapshot immediately before the move, and after_digest is the digest immediately after the book row is moved. The canonical snapshot is the UTF-8 text made from these newline-separated sections with a trailing newline: SHELVES, then shelves ordered by position and shelf_id as shelf_id|position|capacity|required_genre|sort_mode; BOOKS, then books ordered by containing shelf position, shelf_id, slot, and book_id as book_id|title|genre|sort_key|shelf_id|slot; EDGES, then edges ordered by source shelf position, from_shelf, target shelf position, and to_shelf as from_shelf|to_shelf. Undo must first compare the current canonical digest with the selected history row's after_digest. If they differ, undo exits non-zero with ERROR: on stderr and does not mutate books or history.

Shelf slots are 0-based. The top book on a source shelf is the book with the highest slot number, even if slots have gaps. When a book moves to a target shelf, it lands at COALESCE(MAX(slot) + 1, 0). The show command prints shelves by position, then shelf_id, and prints books on each shelf by ascending slot using this exact line format: Shelf <shelf_id> [genre=<required_genre> sort=<sort_mode> cap=<capacity>]: <book_id>(<genre>:<sort_key>) | ... Empty shelves end immediately after the colon.

A move must be rejected without changing state or writing history if a shelf is missing, the source and target shelf are the same shelf even when a self-edge exists, the source is empty, the route is not allowed, the target is full, the book genre does not match the target shelf required_genre unless the shelf uses ANY, or the target shelf would break its ordering rule. ASC means sort keys must be nondecreasing by slot, DESC means nonincreasing by slot, and NONE means no ordering constraint. Successful moves print OK moved <book_id> from <from> to <to> to stdout. Invalid moves and empty undo attempts exit non-zero and write a message beginning with ERROR: to stderr.

The status command prints WIN only when all of the following are true: every non-ANY shelf is not over capacity, every non-ANY shelf contains only books matching its required_genre, every shelf satisfies its ASC/DESC/NONE ordering rule, and every shelf with required_genre ANY is empty. Otherwise it prints IN_PROGRESS. Capacity is always an upper bound for every shelf, including ANY shelves, so a move into a full ANY shelf is illegal. Non-ANY shelves do not need to be completely full to win. ANY shelves are temporary buffers during play, not final solved shelves.


The audit command is read-only and exists so a saved game can be checked against the original seed data after several moves and undos. It recreates the requested level from --seed-db and --level in a temporary database, then replays move_history rows ordered by id. For every row it must compare the recreated board digest before the row with before_digest, apply that row's move exactly using book_id, from_shelf, to_shelf, from_slot, and to_slot, compare the recreated digest with after_digest, and if undone is 1 immediately restore that book to from_shelf/from_slot before replaying the next row. It must then compare the replayed final digest with the live runtime database digest. Audit prints one JSON object to stdout with keys current_digest, replayed_digest, history_count, active_count, undone_count, valid, and first_bad_history_id. Digests are 64-character lowercase hex strings, counts are JSON numbers, valid is a JSON boolean, and first_bad_history_id is the first bad move_history id or null. If every history row validates but the final live digest does not match the replayed digest, first_bad_history_id must be 0. Audit must not change books or move_history in the runtime database.

Redo reactivates the most recent move_history row with undone = 1 without inserting a new history row. Before changing anything, it must require the live canonical board digest to equal that row's before_digest, verify that the recorded book is still the top book at from_shelf/from_slot, verify that the recorded route and target placement are legal, and verify that replaying the move produces the stored to_slot and after_digest. A successful redo moves the book, sets undone back to 0, and prints OK redone <book_id>. Missing or stale redo state must fail with ERROR: and leave both books and history unchanged.

The apply-plan command reads a JSON object from --file with exactly expected_start_digest, expected_final_digest, and moves. Both digest fields are lowercase 64-character SHA-256 hex strings. moves is a non-empty array of objects with exactly from, to, and book_id. The command must first simulate every requested move against an in-memory copy of the current board, in array order. Each book_id must identify the current top book of from, and every move must satisfy the same route, capacity, genre, and ordering rules as move. The live board digest must match expected_start_digest before simulation and the fully simulated board must match expected_final_digest. Unknown JSON fields, malformed input, a wrong digest, a wrong top book, or any illegal intermediate move must fail before the runtime database changes.

When the full plan validates, apply all book updates and insert one ordinary active move_history row per step inside one SQLite transaction. The before_digest and after_digest of each row must form the exact simulated digest sequence. In the same transaction, insert one plan_runs row and one plan_steps row per move. plan_steps uses zero-based step_index, references the corresponding inserted move_history id, and repeats that history row's after_digest. plan_id is the lowercase SHA-256 digest of this UTF-8 text: expected_start_digest plus a newline, expected_final_digest plus a newline, then one line per move formatted from|to|book_id, including a trailing newline. On success print one JSON object with plan_id, start_digest, final_digest, and move_count. Any database failure must roll back the entire plan, including books, history, plan_runs, and plan_steps.

The apply-batch command applies a dependency-constrained move graph rather than a preordered list. Its --file input is a strict JSON object with exactly expected_start_digest, expected_final_digest, and operations. operations is a non-empty array; every operation object has exactly id, from, to, book_id, expected_after_digest, and depends_on. Operation ids must be unique non-empty lowercase identifiers containing only a-z, 0-9, hyphen, or underscore. depends_on is an array of distinct operation ids; self-dependencies, unknown dependencies, duplicate dependencies, and cycles are invalid. All three digest positions use lowercase 64-character SHA-256 hex strings. Unknown JSON fields or trailing JSON values are invalid.

Resolve the graph with deterministic Kahn ordering: among all operations whose dependencies have completed, execute the lexicographically smallest id. Input array order must not affect execution. Before touching SQLite, load the live board, require its digest to equal expected_start_digest, and simulate the complete resolved sequence in memory. Each operation must identify the current top book and pass the ordinary route, capacity, genre, and ordering rules; its resulting digest must equal expected_after_digest. The final simulated digest must equal expected_final_digest. Any graph, schema, digest, or move failure is read-only.

After full validation, apply every simulated move and its ordinary active move_history row in one SQLite transaction. Insert one batch_runs row and one batch_steps row per executed operation. step_index is zero-based execution order; history_id references the move_history row inserted for that step; after_digest is the validated per-operation digest. batch_id is the SHA-256 digest of this canonical UTF-8 text: expected_start_digest plus newline, expected_final_digest plus newline, then one line per resolved operation formatted id|from|to|book_id|expected_after_digest|dep1,dep2 where dependencies are sorted lexicographically and every line has a trailing newline. On success print one JSON object with batch_id, start_digest, final_digest, step_count, and execution_ids. Database errors must roll back books, history, batch_runs, and batch_steps together.

The history command is read-only. The hint command must inspect the current SQLite board, print the first legal move as MOVE <from> <to> <book_id>, or print NO_MOVE when no move is legal. Hint must not mutate books or move_history. For hint and solve, enumerate candidate legal moves by source shelf position, then source shelf_id, then target shelf position, then target shelf_id; seed_edges insertion order must not decide ties.

The solve command must inspect the current SQLite board without mutating it. If the board already satisfies status WIN, print ALREADY_SOLVED. Otherwise perform a breadth-first shortest-plan search up to --max-depth using the same legal-move order as hint for tie-breaking. Print one MOVE <from> <to> <book_id> line per step for the first shortest plan found. If no plan exists within the depth limit, print NO_SOLUTION. The default depth is 8 when --max-depth is omitted.


The verify-ledger command is a read-only integrity pass over both gameplay history and transactional provenance. Recreate the requested seed level, replay move_history in id order with the same before/after digest and undone semantics as audit, and compare the recreated final board with the live board. In parallel, compute history_root by starting with SHA-256(`booksort-ledger-v1\n`) and, for each history row, replacing the root with SHA-256(previous-root-hex + `\n` + `id|book_id|from_shelf|to_shelf|from_slot|to_slot|before_digest|after_digest|undone\n`).

Validate every plan_runs row against plan_steps and every batch_runs row against batch_steps. Step indices must be contiguous from zero, row counts must equal the declared count, each referenced history row must exist, each step after_digest must equal its history row after_digest, and the referenced history digests must form an unbroken chain from the run start_digest to final_digest. A history id may belong to at most one plan or batch provenance record, and step rows whose parent run is missing are invalid. Report one JSON object with current_digest, replayed_digest, history_root, history_count, plan_count, batch_count, valid, and first_error. first_error is null when valid; otherwise it is the earliest failure encountered in this precedence: `history:<id>`, then lexicographically ordered `plan:<plan_id>`, then `batch:<batch_id>`, then `board`. The command reports integrity failures through valid=false rather than mutating the database or partially repairing it.
