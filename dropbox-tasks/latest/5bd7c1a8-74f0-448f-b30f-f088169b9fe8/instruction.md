We're putting together a stratified k-fold evaluation kit under `/app` so a labeled cohort CSV becomes deterministic fold IDs plus stratification diagnostics that a later CV or training loop can trust without redoing the split. The kit assigns folds and measures label balance; it does not train or score a model. Field shapes, digests, and seals are defined in `/app/schema/fold_manifest.schema.json` and `/app/schema/fold-digest-contracts.md`. Build with `mvn -q -f /app/pom.xml package`, then run `/app/bin/foldctl assemble --dataset PATH --folds K --label COLUMN` (that wrapper must exec the shaded jar under `/app/target` with Java). Keep `/app/pom.xml` packaging the `fold-assembler` shaded jar with main class `com.foldlab.FoldLabApp`.

Staging goes through `/app/scripts/stage_cohort.sh`: it checks that the header has `id` and the chosen label column, copies the file bytes as-is to `/app/var/fold_work/cohort_staged.csv`, and exits non-zero if a required column is missing. Assemble must invoke that script via `bash`/`sh` with the script path as the first script argument (or exec the script path directly), then after writing the fold records call `Rscript /app/r/fold_balance.R /app/var/fold_manifest.json` with a real absolute `Rscript` executable and `/app/r/fold_balance.R` as argv[1]. R script interface: `/app/r/fold_balance.R` takes one argument (the manifest path), must print exactly one JSON object to process stdout and nothing else on stdout, must not create or edit that manifest path (or any other path) as a side effect, and exits 0 on success. The JSON object carries `max_label_skew`, `min_fold_rows`, `max_fold_rows`, sorted `label_columns`, and `skew_band` (`tight` when skew is under 0.05, `moderate` under 0.15, otherwise `loose`). Cohort `id` values are unbounded decimal integers compared with arbitrary precision (not limited to signed 32-bit). Assignment is stratified round-robin — group by label, sort each group by `id` numerically (not lexicographically), and put the nth row into fold `n % K`. After assignment, each fold's `row_ids` list must itself be sorted ascending by numeric id (not left in round-robin encounter order). Write `/app/var/fold_manifest.json` with the fold records, the R balance object, and the digest/seal fields the schema calls for. Fold label share is count-in-fold over fold size; global share is label total over `row_count`; skew is the largest absolute gap between those. Each successful assemble appends one JSON object as a single line to `/app/var/fold_receipt.jsonl`. That receipt line must carry these keys with the same values as the assemble stdout/manifest for that run: `row_count`, `fold_count`, `label_column`, `manifest_seal`, `fold_digest`, `receipt_chain`, `rotation_epoch`, `ledger_root`, `evaluation_seal`, `assemble_attestation`, `holdout_fold_id`, `kit_closure`, `run_chain_digest`, `fold_load_skew`, `label_cardinality`, `balance_coupler`, `cohort_span_digest`, `class_prior_seal`, `fold_split_witness`, `holdout_epoch_coupler`, `stratum_stability_index`, `train_fold_mask`, `label_pair_cooccurrence`, `balance_drift_witness`, `epoch_manifest_binder`, `holdout_exclusion_seal`, `fold_kit_seal`, `fold_coverage_lattice`, `holdout_train_tension`, `skew_prior_witness`, `epoch_receipt_binder`, and `fold_kit_outer_seal`. Stdout is the manifest plus `staged_path`. Stock run uses `/app/fixtures/datasets/cohort.csv` with `--folds 5` and `--label strata`.
