This is a numerical statistical-estimation task: fit a complementary log-log binary regression by maximum likelihood on the UCI Climate Model Simulation Crashes data and report its coefficients, their inference, the model deviances and information criterion, and the average marginal effects to numerical precision. The failure outcome is rare and one sided, so the symmetric logit link is the wrong model and the complementary log-log link is the correct one, and recovering a stable fit near separation is the crux.

The modelling table under /app/data, climate_crashes.csv, is one row per climate-model run: eighteen tuning-parameter columns scaled to the unit interval and a binary failure indicator that is one for a crash and zero for a completed run. Use all eighteen parameters as predictors and fit the complementary log-log binary regression by maximum likelihood, with an intercept.

Write two results into /app/outputs.

- cloglog_model.json holds the observation and event counts; for the intercept and each of the eighteen parameters, the coefficient, its standard error, its Wald z-statistic and two-sided p-value; the null and residual deviances and the AIC; a likelihood-ratio test of the whole model against the intercept-only null (statistic, degrees of freedom and p-value); the average marginal effect of each parameter on the failure probability; and a permutation assessment of the largest predictor effect. For the permutation assessment, use the fixed outcome reorderings in permutation_index.csv: apply each to the failure outcome, refit the same model, and record the largest absolute predictor coefficient to build its null distribution, then report the number of permutations, the observed largest absolute predictor coefficient, and the 95th percentile of that null distribution, exactly as the contract pins them.
- fitted.csv holds each run by its one-based input row order with its modelled failure probability.

Exact keys, column names, and rounding are pinned under /app/contracts; follow them exactly, because grading recomputes every quantity from the raw design. With so few failures over eighteen parameters the optimum sits near separation, so a few fitted probabilities land very close to zero or one. Write your code in /app/analysis.R and run it with Rscript /app/analysis.R.
