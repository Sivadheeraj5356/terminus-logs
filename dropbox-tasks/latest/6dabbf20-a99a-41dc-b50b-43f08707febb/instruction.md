Our training engine at /app has a checkpoint/rematerialization mode that is supposed to be numerically indistinguishable from running without it, but right now checkpointed runs drift away from the baseline a few steps in, and resuming from a mid-run checkpoint doesn't line up with an uninterrupted run either. The engine is the stubbed Rust crate under /app/src. The op formulas, the per-layer rematerialization schedule, the PRNG and dataset-shuffling scheme, the ragged-last-batch rule, the optimizer update, and the gradient-clipping policy for the unstable third layer are all pinned in /app/spec/engine_design.md — read that first.

Implement the tape-based autodiff engine and training loop so that a full run with checkpointing enabled reproduces the loss and gradient norm of the same run with checkpointing disabled at every step, and so that resuming from a checkpoint saved mid-run continues training identically to an uninterrupted run through the remaining steps. Don't change how the third layer behaves; clip its gradients per the spec rather than working around it. Write per-step loss, gradient norm, and checkpoint hashes into /app/out/runs.db following the schema in the spec, one row per step per run, for the non-checkpointed run, the checkpointed run, and the resumed run. Follow the RNG and batching rules exactly: small deviations in operation order or random-draw consumption desynchronize the run from the reference several steps later rather than immediately, so check your work past the first epoch boundary.
