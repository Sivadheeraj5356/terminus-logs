# Engineering journal — June 2025

Author: M. Anaya, secretary

Unwelcome discovery during the pre-freeze inventory. The service working
tree on the analysis host does not match the last recorded pom revision.
Three dependency lines have drifted:

The driver line reads 42.2.5 — the 2019 baseline, rescinded since advisory
MRA-2024-011 — where the last recorded revision left 42.7.4. It appears a
contractor restored an old baseline onto the working tree during the spring
host move and the restoration was never caught.

The numerical library line names a `commons-math4-core` artifact at
`4.0-beta1`. No such version was ever fetched into the station repository
and no 4.x artifact holds an approval; the line looks like an optimistic
edit made after February's migration enthusiasm, ahead of any decision.

The serializer line reads 2.17.9, which does not exist in the station
repository either — the approved version is 2.17.2, and the trailing digit
looks like a slip of the hand made during the same editing session.

None of these edits was recorded as a pom revision; they are working-tree
drift, outside the revision record, and this entry does not add to the
count of recorded revisions. The recorded record still ends at the May
revert. I am leaving the working tree exactly as found — drift and all —
because the freeze audit should see the true state of the host, and the
remediation will be judged against the freeze record in any case.
