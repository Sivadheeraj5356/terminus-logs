We need a build tool that turns the vendor image drops in /app/assets/src into the exact derivatives our CDN expects. Every rule for this — target sizes per asset class, when to crop versus fit, how to normalize camera orientation, the color profile policy, the output naming, and the manifest layout — is written up in /app/spec/asset_processing_spec.md. Please read the whole thing; the rules differ by asset class and some only appear once, in prose rather than a table.

Each source file's asset class comes from /app/assets/src/manifest_inputs.csv. Build a C++ tool using the CMake setup already in /app so that /app/build/derive, given the sources directory, the CSV, and the spec path, produces every required derivative under /app/out/derivatives and writes /app/out/manifest.json describing what it produced, in the order the spec requires, with a content hash per output. Use ImageMagick for the actual image work.

Running the tool twice back to back must produce byte-identical output, manifest included. A couple of the source images are already exactly what we need — think carefully before you re-encode anything, since even a lossless-looking pass can change a file's bytes. Don't modify anything under /app/assets. When you're done, the images on disk and the manifest should agree with each other and with the spec.
