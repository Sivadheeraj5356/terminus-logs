VLAN segmentation failures (CWE-653) enable lateral movement across network security zones. The enforcement engine at `/app/bin/vlan-segmentation-enforce` processes 8 flows across 4 trunk ports from `/app/evidence/` and writes results to `/app/output/enforcement_result.json`. The output JSON contains `analysis_metadata`, `summary`, `violations`, `trunk_configuration_findings`, `native_vlan_analysis`, and `violation_breakdown`.

The engine must detect four violation categories on cross-VLAN flows (same-VLAN flows produce no violations). A `double_tagging` violation fires only when the frame's outer_tag equals the trunk port's configured native VLAN (VLAN 1) — frames whose outer_tag matches their source VLAN are not double-tagging. This applies to both 0x8100 and 0x88A8 ethertypes. Double-tagging severity is `critical` when the flow targets critical service ports (1433/3306/5432, 22/3389), `high` otherwise. A `native_vlan_exploit` fires on the same flows where double_tagging is detected, always severity `critical`. A `zone_violation` fires when a flow's source-to-destination zone crossing appears in the zone policy's blocked_destinations; severity is `high` for management service ports (445/3389/22), `medium` otherwise. An `acl_bypass` fires when cross-VLAN traffic reaches destinations blocked by explicit subnet-targeted ACL deny rules, always severity `high`. ACL catch-all deny entries (e.g., seq 999 "deny any any") do not trigger acl_bypass findings. Double-tagged flows are not excluded from ACL bypass checks — they are evaluated against ACL rules like any other cross-VLAN flow.

The `trunk_configuration_findings` array must contain exactly 8 entries: one native VLAN mismatch finding per trunk port (comparing each port's configured native VLAN against the policy requirement of VLAN 999, referencing the switch name and port identifier) and one DTP finding per trunk port. The `native_vlan_analysis` must have `mismatch_detected` true, `all_consistent` false (trunk ports have native VLANs 1, 1, 100, 200), and `risk_level` critical. The `enforcement_status` is `FAILED` when critical-severity violations exist. Note that code comments and docstrings may themselves contain errors.
