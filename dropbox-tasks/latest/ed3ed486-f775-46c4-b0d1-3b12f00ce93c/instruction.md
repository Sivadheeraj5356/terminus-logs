# Accumulation Trace Drift

The training runtime under /app/environment emits JSONL run records and per-pass JSON summaries under /app/output. Serial runs look consistent. Under concurrent admission with snapshot/continue — including partial-window halts mid accum window — norm summaries often stay within plan tolerance while pass files disagree with a serial baseline for the same plan, seed, and accum window. Fix the Rust sources under /app/environment so the pipeline regenerates correct evidence. Output-only work is not allowed. Do not edit /tests/ or fabricate output files. Static or manual output creation is insufficient; the verifier deletes /app/output before each scenario and the normal train/continue pipeline must regenerate artifacts. Build, CLI flags, plan choices, and fingerprint formulas are in /app/environment/docs/contract.md and /app/environment/docs/toolchain.md; invoke the release binary through the train/continue pipeline described there.

For a fixed plan, seed, accum window, and mode, sorted pass step fingerprints must agree between a serial uninterrupted run and a concurrent run that snapshots mid-training and continues. The same serial baseline must also match for per-step accumulator checksum chains and for the sorted tag membership recorded at each completed step in the trace. Successful runs emit artifact families with distinct schemas: /app/output/run_trace.jsonl records seq, slot, phase, tag, payload_fp, and step_index on each line; /app/output/pass_transcripts/pass_<n>.json carries step_digest, balance_tally, pending_slots, mode, and acc_checksum for each completed step; /app/output/vault/manifest.json holds last_tag, last_step, pending_count, and wave_offset when a snapshot is written, with /app/output/vault/acc.bin and /app/output/vault/tags.bin sidecars for accumulator and tag bytes and /app/output/wal.log seal records for tag recovery. Payload, step, and accumulator digests all use sha256; published fields store the first 16 lowercase hex characters. At each snapshot boundary, pending_count must equal the tag sidecar length divided by eight (pending_count * 8 bytes in tags.bin) and must match pending_slots length in the pass transcript when that pass exists. Continue must rebuild partial-window accumulator state and pending tags before finishing an interrupted wave; when wave_offset is non-zero the scheduler resumes after skipping that many slots in the wave. The continue `--from` path may reference any valid vault snapshot directory, including a relocated copy under /app/output such as /app/output/vault_relocated. If tags.bin is absent, continue may recover tag lists from wal.log seal records. Step fingerprints hash sorted tag CSV; acc_checksum hashes the live accumulator vector at step completion. Multi-stage train/continue chains must preserve serial digest prefixes at every intermediate halt boundary before the final uninterrupted completion.
