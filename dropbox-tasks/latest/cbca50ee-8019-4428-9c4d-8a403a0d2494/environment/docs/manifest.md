# Manifest and digest rules

`/app/ops/manifests/bundle_manifest.json` uses `schema_version = 2`. Its `partition_entries` array is ordered by cursor `seq` and has the same fields as the ledger rows except for ledger-only `service_generation`, `batch_id`, and `terminal`. `path` is relative to `/app/ops` and points at a rotated partition file.

Digest formulas are exact:

- `digest_hex` is lowercase SHA-256 over the raw bytes of the partition file.
- `omission_digest_hex` is lowercase SHA-256 over the UTF-8 string `partition_id|omission_reason|cursor_start|cursor_end|prev_cursor`.
- `signer.lineage_hash_hex` is lowercase SHA-256 over exported partitions in order, one line each as `partition_id|prev_cursor|cursor_end\n`.

The generated `bundle_manifest.signed.json` adds `manifest_digest_hex` and `signature_hex`; these are regenerated by `rotlogctl` and are not source authorities.
