The command-line tool `formula-order` in `/app` decides which of two formula versions is the newer one, so the catalog can keep a formula's published releases in order when it plans an upgrade or pins a dependency. Given two version strings on the command line, it prints -1 when the first is older than the second, 1 when the first is newer, and 0 when the two rank equally. Today it only handles plain dotted-number releases, so it misranks most of the versions a real catalog publishes; it needs to order the full range of versions the way Homebrew itself orders formula versions.

That ordering reaches well past comparing dotted numbers. Releases carry pre-release words such as alpha, beta, pre and rc, patch- and post-release markers, single-letter revisions, and numeric revisions embedded inside those markers, and two versions can still rank equal despite differing in their separators, in leading zeros, or in a trailing zero component. The file `/app/examples.json` records a sample of how such decorated versions are expected to rank. The comparator lives under `/app/internal/version` behind the `Compare` function; make its ordering match Homebrew across this whole range while leaving the existing plain dotted-number behaviour unchanged.

Build the command with `go build ./cmd/formula-order` from `/app`. It takes its two versions as command-line arguments and writes a single line to standard output.
