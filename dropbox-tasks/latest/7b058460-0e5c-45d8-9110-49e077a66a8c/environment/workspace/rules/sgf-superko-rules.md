# Harbor House 5x5 Cup rules

Games use a 5x5 board, SGF coordinates `aa` through `ee`, alternating Black and White moves, and pass moves written as empty SGF coordinates. A stone placement is legal only on an empty intersection. Captures remove adjacent opposing groups with no liberties, self-capture is not legal, and positional superko means a stone placement must not recreate any earlier board position from the same game. Passes are legal and do not count as superko repetitions.

A normal game ends after two consecutive passes. The score is occupancy scoring: Black's score is the number of black stones on the final board, White's score is the number of white stones, and the result is the higher color plus the difference. The tournament awards 1 win point for a win and 0 for a loss. SOS is the sum of each opponent's win points. SODOS is the sum of win points for opponents defeated by the player. Final standings sort by win points, then SOS, then SODOS, then player name.

The referee card columns `game_id`, `round`, `board`, `black`, `white`, `expected_result`, `reason`, and `overturned_ply` describe the official identity and outcome. In every reconciled SGF root, `ID` is the game ID, `RO` is the round, `PB` and `PW` are the Black and White players, and `RE` is the expected result. A positional-superko overturn determines a forfeit result. In that case, the official SGF record contains only the legal played moves before the overturned placement and carries `RE[<winner>+F]`, `ADJ[superko-forfeit]`, and `FP[<overturned-ply>]` on the root node.


The reconciled archive includes an updated `register/rounds.tsv`; each row identifies its official SGF through the `record` path. Source repair is part of the maintenance job: the command supports `repair`, `audit`, and `export`. `sgfpack repair --root /app/workspace` rebuilds the rounds register, current SGF records, and `register/repair_state.json` from the evidence. `sgfpack audit --root /app/workspace` checks that those durable files still agree. Generate a clean pack with `sgfpack export --root /app/workspace --out /app/output/sgf-pack`; `sgfpack export --help` describes its flags. The exporter removes and recreates the output directory, so the same reconciled archive must produce byte-for-byte identical output on every run.

The repair state is a JSON array sorted by `game_id`. Each object has `game_id`, `journal_seq`, `journal_event`, `camera_sha256`, `record_sha256`, `result`, `reason`, and `legal_ply_count`. The `journal_seq` and `journal_event` come from the numerically highest active journal row for the game, the camera digest is the SHA-256 digest of the camera move file, and the record digest is the SHA-256 digest of the repaired current SGF.

The `standings.tsv` header is `rank`, `player`, `wins`, `losses`, `sos`, `sodos`, and `stone_margin`, in that order. Each field is tab-separated. `rank`, `wins`, `losses`, `sos`, `sodos`, and `stone_margin` are decimal integers; `player` is text. `stone_margin` is the sum of each finished board margin from that player's perspective, using the final legal board for forfeit games.

The `adjudications.json` export is a JSON array with one object per game. Each object uses these exact keys and types: `game_id` (string), `round` (integer), `board` (integer), `black` (string), `white` (string), `result` (string), `reason` (string), `black_points` (integer), `white_points` (integer), `black_score` (integer), `white_score` (integer), `legal_ply_count` (integer), and `record_sha256` (lowercase hexadecimal SHA-256 digest of the reconciled SGF file).

The `manifest.json` export is a JSON object with `ruleset` (the string `TTB-PSK-5`), `board_size` (integer), `record_count` (integer), `source_rounds_sha256` (lowercase hexadecimal SHA-256 digest of `register/rounds.tsv`), `repair_state_sha256` (lowercase hexadecimal SHA-256 digest of `register/repair_state.json`), and `records` (the same array of per-game objects written to `adjudications.json`).
