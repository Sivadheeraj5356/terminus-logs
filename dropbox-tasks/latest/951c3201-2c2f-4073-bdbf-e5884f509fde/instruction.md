The Redis-backed dispatch provisioning service in /app won't come up. The service code is fine, but it's carrying stale configuration from an old docker-compose deployment: it can't reach Redis, and even once it does its file paths are wrong. Redis itself is set up in /app/config/redis.conf and the service reads its own settings from /app/config (a service.json base with a service.overrides overlay). Get the service talking to the Redis instance described by redis.conf and bring it online, then run `node /app/scripts/reconcile-client.js` so it completes a run and writes /app/output/reconciliation-report.json. Note that the Redis data directory referenced by redis.conf still needs to exist before Redis will start.

Once the service is up, the reconcile run brings the drifted zone keyspace back in line with the canonical TLC lookup in /app/data/taxi_zone_lookup.csv, which takes precedence over the values currently in Redis. Operator overrides ship in the bundle the service unpacks, keyed by LocationID: a locked override is authoritative and wins over the canonical value, an unlocked override is only advisory and must be ignored, and any zone whose LocationID is not in the lookup is left untouched. Each zone carries a version that should increase by one only when one of its fields actually changes.

The reconcile run must be idempotent, so a second run leaves the keyspace and the report unchanged, and the report itself must be byte-for-byte deterministic.
