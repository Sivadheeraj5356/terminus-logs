The LoRA merge evaluation lab under /app decides whether multi-adapter PEFT candidates are safe to launch on a pinned base checkpoint. Score each launch candidate with /app/lora-gate <request-file> and publish the model-readiness board at /app/output/lora_merge_conflict_gate.json plus per-adapter findings at /app/output/adapter_findings.jsonl. Requests use the existing line-oriented adapter/manifest interface documented by the source parser, including base checkpoint, revision, held-out evaluation parts, merge-risk limit, alias lines, and adapter leaf rows.

The readiness board is a JSON object where request_id and model_view are strings, ready is boolean, score is an integer, and targets is an array of strings. Findings are JSONL rows where request_id, model_view, and adapter are strings, ready is boolean, and score is an integer. Target module lists are sorted and deduplicated; finding lines follow adapter input order. Both artifacts must agree on request identity, composed model view, launch readiness, and merge-risk score.

Adapters that address the same low-rank weight region after module aliasing and orientation normalization accumulate into one region. Merge risk for a region is the squared accumulated adapter weight on that region. The published score is the worst-case region risk across the candidate. ready is true only while that score stays at or below the request merge-risk limit; otherwise the adapter combination is withheld from launch.

Equivalent LoRA manifests that resolve to the same weight regions must produce the same targets, score, readiness, and model_view. model_view identifies the composed model under evaluation and must change across different base checkpoints, revisions, held-out evaluation parts, resolved weight regions, score, or readiness. A replayed or warm evaluation of the current candidate must match a clean evaluation of that same candidate. Keep the public command interface and derive both artifacts from the live merge-evaluation path rather than hand-writing them. Published output from current runs does not satisfy independent merge-evaluation replay.
