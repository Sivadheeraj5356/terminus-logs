Cold rebuilds print a clean driver status while loader output still drops required objects. Warm rebuilds look healthier, but manifest, journal, and loader surfaces disagree on ordering and availability. Incremental bundle deltas can be missing from regenerated `/app/output/` JSON on runs that looked successful. Carry sidecars from an earlier profile or merge tier can pin the wrong wave label across later driver invocations in the same session. Stamp digests and lane ranking also drift across shared helpers under `/app/environment/lib/`.

Repair the bash pipeline under `/app/environment` so cold and warm profiles agree on object presence and ordering across `/app/output/staging_manifest.json`, `/app/output/phase_journal.json`, and `/app/output/loader_trace.json`. Regenerate those files through the driver under `/app/environment/driver/` for warm, cold, incremental merge, and second-tier merge wave shapes. Static or hand-written JSON under `/app/output/` is not enough. Do not mutate notes under `/app/environment/bundles/k6preserve/`.

## Requirements

Profile labels, required object sets, and weight table paths live in `/app/environment/data/profiles.json`. The `profiles` property must name each profile label together with its required object set and weight table path. Each profile uses its own weight table under `/app/environment/bundles/profiles/`; warm and cold disagree on several ranks, so ordering must follow the active profile table, not a shared default. Manifest `profile` alignment, loader trace `profile` alignment, journal `segments`, manifest `objects` weight ordering, trace `read_order` and `rows` sequence alignment, plus carry binding, hook gating, shared stamp helpers, journal-gated availability, merge-tier wave staging, and probe sidecar isolation are defined in `/app/environment/docs/k4_contract.md`.
