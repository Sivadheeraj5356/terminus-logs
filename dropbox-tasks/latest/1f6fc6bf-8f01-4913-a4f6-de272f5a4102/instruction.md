# Pooled relay linger governor

Operations is shipping the Rust edge relay coordinator under `/app/environment` for offline shard polling. Bundled smoke workloads finish, but larger profiles either abort with descriptor pressure or leave idle pooled sockets unreclaimed after mock shards close quiet connections.

Complete the coordinator by fixing Rust source under `/app/environment` so pooled transport reuse, linger governance, and export reconciliation match the contract. Library behavior in the workspace crates must match the contract, not only the CLI layer. Rebuild using the operator runbook cargo invocation; the verifier rebuilds and reruns `/app/bin/relayctl run`. Manual or hand-written exports are insufficient; the normal pipeline must regenerate `/output/relay_run_report.json`, `/output/pool_journal.csv`, and `/output/relay_trace.ndjson`.

Run `/app/bin/relayctl run` with policy, root workload, state, seed, report, journal, trace, phase, optional workload-rounds limit, and shard-profile as documented in `/app/docs/operator_runbook.md`. Exit `0` on success; `5` on static descriptor ceiling exceeded; `6` on export mismatch or when the verify phase runs against an unpopulated or empty state database; `7` when the generation-adjusted effective descriptor limit is breached; `9` when the idle phase runs before governance is ready on a cold state database. The `generation_seals` SQLite table MUST contain a boolean (or integer) column named `sealed` alongside the `pool_generation` column. The effective descriptor limit is `descriptor_ceiling - (pool_generation * 2)` using the current ledger generation at each populate transport open. `mark_populated` must be called after all transports for the current run are opened. Every exported `pool_generation` field in the run report, journal rows, and trace records must equal the post-increment ledger generation from the populate pass. The journal `linger_reclaim` event reports idle sockets retired during idle reconciliation.

During idle linger reconciliation the governor preserves at least one idle socket per active unsealed ledger generation even when that socket is already EOF. The pinned socket MUST remain in the pool for the duration of the current idle phase invocation; it may only be reaped on a subsequent call, even after the generation has been sealed within the same call. You cannot seal-then-immediately-reap within a single pass. Only after a generation is sealed in the SQLite ledger may its last pinned idle socket be reaped on a later idle invocation. The idle phase seals the populate generation when linger reconciliation finishes.

Linger governance and socket sweeping must run concurrently across the pooled idle inventory. NDJSON trace rows and CSV journal rows still require deterministic ordering: reclaim trace events sorted by ascending `socket_id`, journal rows sorted by ascending `round_index` then ascending `socket_id`. Concurrent sweeps must buffer, sort, and synchronize results before persistence and export. Verifier concurrency checks exercise a wide pooled inventory with mock-shard close delays and require sorted reclaim export order plus aligned reclaim totals across trace, journal, and report without wall-clock timing assertions.

Exported artifacts must stay aligned on `schema_version`, `workload_id`, `round_count`, `pool_generation`, `checkouts_total`, `reclaims_total`, `journal_digest`, `pool_peak`, `state_bytes`, `socket_id`, `shard`, `event`, `round_index`, and trace `phase` as defined in `/app/docs/run_report_schema.md`, `/app/docs/journal_schema.md`, and `/app/docs/trace_schema.md`. Mock shards are started locally by the verifier harness, which tears them down with `signal`. Verifier tests may query SQLite through `sqlite3` and load harness helpers with `importlib`. Do not edit bundled fixtures listed in the runbook.
