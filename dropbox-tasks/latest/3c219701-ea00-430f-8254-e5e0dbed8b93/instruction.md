Revenue protection at a regional distribution network has opened a meter-fraud case, and our firm has the forensic audit. Field crews keep pulling tapped service heads off circuits whose exports look clean, the same meter credential keeps turning up at delivery points minutes apart, and a run of settlement disputes has been quietly writing off charges that should have stood. The seized evidence sits in a corpus shaped like /app/data: the network registry, the utilities' raw binary meter exports under exports/, the regulator's circular book under circulars/, and the disputes file. The board wants a case report it can reproduce on any corpus, and a review service the tribunal can read the closed case through. The format sheet /app/spec/FORMATS.md lists every layout and schema (the corpus paths, the registry field table, the packed record layout with an annotated hex dump, the circular grammar, the schema of every report file, the two database table schemas, and the HTTP response shapes), and /app/spec/RULES.md carries the complete rule set for all five subcommands. The directory /app/data/example holds a small worked corpus to exercise the engine on before the dense one; grading is byte-exact on unseen corpora.

Mechanize the audit as a single Rust program under /app/tariff whose binary is named tariff, built with make -C /app/tariff build and producing /app/tariff/target/release/tariff. The one binary carries five subcommands that build on each other: tariff intake --data DIR --out DIR parses the meter exports and logs the evidence; tariff draws --data DIR --out DIR reconstructs the draws and runs the fraud detectors; tariff settle --data DIR --out DIR settles the expected-revenue baseline and closes the case; tariff ingest --data DIR --db PATH runs the full audit and writes the case file into a SQLite database; tariff serve --db PATH --port N serves the case file over HTTP. Each command that takes --out or --db creates its output as needed, exits 0 on success, and exits 2 when either of its required flags is missing. Every report file the engine writes is compact JSON with no spaces between tokens, one object per line, LF-terminated, with the keys in the order the format sheet gives. Implement every rule in /app/spec/RULES.md exactly; grading compares each output byte for byte against the reference audit on corpora the task never shows you.
