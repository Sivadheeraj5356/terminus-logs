giri is our engine for a capture-and-territory board game played on an arbitrary graph board, and the rules core still needs to be written. The board's intersections and their adjacencies are in /app/board.spec, and the recorded games are the move logs under /app/games. The rules — groups and liberties, how captures resolve, when a move is suicide, the repetition rule, passing and how a game ends, and area scoring — are written up in /app/docs/RULES.md; the move-log grammar is in /app/docs/NOTATION.md; the results schema, the group-graph format, and the command-line interface are in /app/docs/STORE.md.

The Rust crate under /app already has the command-line entry point and the notation parser; the board model, the capture and legality logic, the repetition check, scoring, the results store, and the graph output are stubbed out. There is no network here, so keep the crate dependency-free and reach SQLite and Graphviz through the sqlite3 and dot binaries that are already installed. giri replay should replay every recorded game under /app/games, determine the index of the first illegal move if there is one, reconstruct the final position, compute each player's area score and capture counts, and write the results for every game into the SQLite database named by --db. giri graph --game <id> should emit that game's final group-and-region graph as Graphviz and render it to SVG with dot. giri report should print a game's stored result. Replaying the same games twice must produce identical results. Build the release binary at /app/target/release/giri.
