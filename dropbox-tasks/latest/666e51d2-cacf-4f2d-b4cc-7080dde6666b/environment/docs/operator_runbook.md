# Storage quota operator runbook

## Standard recovery workflow

This runbook is the on-call path for the local storage quota control plane after an
unclean host reboot. Rebuild with `/app/environment/scripts/build_all.sh`, run
`/app/bin/ctl_s8 recover-all`, then validate with `/app/bin/client_t4 list`. Graded
artifacts under `/app/output` must be generated by the admin recovery pipeline.
Wrapper-only edits that leave broken packages in place will fail when the verifier
rebuilds and reruns recover-all.

## Pre-flight fixture sanity

Before recover-all, operators should inventory:

- Ledger rows in `data/q9/rows_q2.json` (including `retired` flags)
- Sidecar stamps and staging under `data/m9`
- Deferred journal tails under `data/j4`
- Per-label streams under `data/k7/<label>/stream.jsonl`
- Matrix lane tables under `data/matrix/`

Lane binding (authoritative after convergence): labels `c01` and `c02` resolve
`attach_id` from `data/matrix/m01_lane.json` keys; labels `c03` and `c04` resolve from
`data/matrix/m02_lane.json`. After fleet convergence, matrix attach overrides stale
attach strings embedded in stream rows for active labels. Stream attach strings remain
useful for forensics but must not win over matrix keys on the converged tuple.

## Maintenance checks after recover-all

After a successful fleet recover-all:

1. Under `data/m9`, only per-active-label `.tmp` staging files may remain. The orphan
   staging file `orphan.tmp` must be removed. Sidecar `.stamp` files must be preserved
   and must match head-phase era per label. Do not delete `.stamp` sidecars while folding
   residue.
2. Successful fleet recover-all collapses `data/j4` so that no journal tail files remain.
   Leaving tails in place lets later boot epochs replay ghost limits for retired catalog
   labels when `S8_BOOT_EPOCH` is two or higher.
3. Confirm `client_t4 list` probes for active labels match converged ledger rows on
   `hard_limit`, attach identifiers, and era markers.
4. Export `S8_BOOT_EPOCH=2` or higher for later list probes. Ledger rows in
   `data/q9/rows_q2.json` carry `retired` flags. Retired labels must not report positive
   `hard_limit` on boot-epoch probes with `S8_BOOT_EPOCH=2` or higher.

These filesystem checks are the authoritative staging and journal-tail contract.
recovery_semantics.md narrates why tails matter; this section states what must be true
on disk after recover-all.

## Quarantined single-label recovery

`recover-one` updates ledger rows for the requested label only, emits no graded outputs
(`recovery_run.json` / `state_fingerprint.txt` stay absent), and does not refresh sidecar
stamps. Isolation probes deliberately inject staleness for `c01` using `c01_stale_era`
and `c01_stale_attach` from `[probe_fixtures]` in `config/bindings.toml`. When
`recover-one` targets another label, those injected `c01` values must remain untouched
and `c01` stamps must not change.

## Catalog refresh expectations

The q9 catalog is refreshed during recover-all for active labels. Stale era values in
`rows_q2.json` before recovery should reconcile to stream commit maxima afterward
(commit maxima taken after journal_format.md replay filtering). Retired rows keep
retirement semantics described above rather than resurrecting positive hard limits on
later boot epochs.
