The terminology API in `/app` must not start unless its Gradle dependency lock and Hugging Face asset lock agree on the exact local dataset revision used for synonym expansion. `/app/gradlew updateHfAssetLock check` must run offline, emit `/app/config/hf-assets.lock.json` from the local Hugging Face mirror, and enforce route and file policy from the release council transcript. Lock regeneration currently yields malformed JSON; validation accepts stale revisions and forbidden public-route files; Gradle `check` proceeds while asset validation fails; Spring Boot starts with tampered locks; the public synonym route returns evaluation-only or preview-only aliases.

The asset lock must record repository, revision, lock schema version, metadata and transcript digests, the Gradle dependency-lock digest, and each public route with permitted files, per-file checksum, and byte size. Operative policy lives only in `<!-- FINAL_RATIFIED:... -->` markers with inline `route`, `revision`, `files`, and `forbidden` attributes. Earlier `PROPOSAL` lines are non-operative. For a route, permitted and forbidden file sets accumulate across every FINAL_RATIFIED marker targeting that route; if markers disagree on `revision`, the last non-empty `revision` in transcript order is operative while accumulated file sets are retained. Digest and lifecycle rules are normative in `/app/docs/asset-lock-format.md`. Lock workflows honor `HF_MIRROR_ROOT` and `HF_TRANSCRIPT` from the process environment if present.

Lock regeneration and validation are separate lifecycle operations. Regeneration must publish the lock atomically and bind every offline provenance input; validation must be read-only and must never invoke regeneration or alter persisted lock content or its sources. Gradle `check` and application startup must reject stale or tampered locks instead of repairing them. The `/v1/terms/{term}/synonyms` route may only use dataset files permitted for that route by the transcript; missing public-route synonyms must return the existing structured error envelope with code `term_not_found`. All workflows must run offline without network downloads.
