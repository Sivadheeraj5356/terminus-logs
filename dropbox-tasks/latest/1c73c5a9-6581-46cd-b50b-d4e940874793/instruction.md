We need a deterministic link-plan utility for a build audit. Complete the intentionally incomplete Go program in `/app/src/main.go` so `/app/build.sh` creates `/app/arcplan`, then run `/app/arcplan /app/linkcase /app/link-report.json`. The starter currently handles only a small part of loose-object processing. The complete four-file contract is in `/app/link-model.md`: it includes transitive symbol aliases, strong and weak references, ordered `NEED` directives, normal/group/whole archive scans, COMDAT ownership, and provider precedence. In particular, `OBJ` must name a loose object; using an archive member there is malformed input and must exit `2`. The verifier may create additional valid inputs following the same contract, so do not specialize the program to `/app/linkcase`.

The output is one JSON object with exactly these fields: integer `version` equal to `2`; string `status` (`ok` or `error`); arrays `selected_units`, `extracted_members`, `discarded_units`, `symbols`, `unresolved`, and `errors` with the exact element fields and ordering defined in `/app/link-model.md`; and string `plan_sha256`, computed from the exact canonical transcript defined there. Empty collections must be arrays, not `null`, canonical symbol names must be used throughout the report, and the digest must use the `sha256:` prefix plus lowercase hexadecimal.

A valid successful link writes the complete report and exits `0`. Valid input with unresolved strong needs or duplicate strong definitions writes `status: "error"` and exits `1`. Any malformed table, alias graph, command, or CLI must remove a stale output when an output path is available, write a line beginning `arcplan: ` to stderr, and exit `2`. Keep the implementation offline and byte-deterministic. The verifier directly recompiles `/app/src/main.go` with the installed Go toolchain before every test run and executes that fresh binary, so changing `/app/build.sh`, leaving a stale `/app/arcplan`, or substituting a script shim will not satisfy the task.
