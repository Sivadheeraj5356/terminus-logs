Passenger rebooking build graph stitchers must compile cancellation-to-replacement depends_on edges and seat-inventory closures into staged layer manifests, then publish digest-sealed build ledgers that operations can trust without rebuilding the dependency graph from live inputs. Shipped compile and publish stages do not match the dependency graph, manifest digest, and export contracts below. Inputs live under /app/data/ (passengers.json, flight-cancellations.json, seat-inventory.json, alliance-agreements.json, airline-policies.json). Compile writes /app/state/rebooking-snapshot.json and /app/state/rebooking-ledger.json. Publish writes /app/output/rebooking-plan.json and /app/output/passenger-summary.json from those staged artifacts only and must never reload /app/data/. Invoke /app/bin/passenger-rebooking-engine after producing it with /app/scripts/build.sh. Subcommands are build, stage, export, and version; no arguments means build; build means stage then export; version prints passenger-rebooking-engine/1.0.0; export exits 2 when snapshot or ledger is missing. TB3_DATA_DIR, TB3_STATE_DIR, and TB3_OUTPUT_DIR override those roots only when set to absolute paths; relative TB3_DATA_DIR is ignored.

Collapse same-flight_id cancellations by highest revision, then lexicographically smallest event_id. Derive cancelled_flights, collapsed_cancellation_count, and disruption_date from that collapsed set. Score passengers as loyalty weight plus fare_class weight; when priority_pick_mode is priority_score, process by descending score then ascending passenger_id; when it is manifest_passenger_order, keep passengers.json array order. For each cancelled leg, choose the lexicographically first eligible replacement with inventory under alliance eligibility, no fare downgrade, upgrade limits, and connection protection: reject a candidate whose replacement arrival plus connection_protection_minutes is strictly after the next leg departure_utc, using the original next-leg schedule even if that next leg is also cancelled. When multiple eligible candidates share the same flight_id, break ties by ascending fare_class before checking inventory. Status is rebooked only when every cancelled leg is replaced, standby when any cancelled leg is not, and unaffected when no leg was cancelled. Each rebooked leg must carry leg_seq, original_flight, replacement_flight, carrier, fare_class, departure_utc, and arrival_utc.

Ledger input_digest is the manifest digest over the full loaded bundle; stage_sequence starts at 1, stays put on unchanged digest, and increments when the digest changes. Snapshot, ledger, plan, and summary version fields are 1. snapshot_fingerprint omits the fingerprint key from the hash input entirely. Plan entries follow processing order with rebook_rank; plan includes ledger_stage_sequence and plan_fingerprint over an entries wrapper; summary must not include ledger_stage_sequence. Repeated build on unchanged inputs must be byte-identical. Field tables and schema examples are under /app/docs/.
