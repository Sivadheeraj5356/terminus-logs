The weather evidence report is consumed by downstream quality gates. Station metadata comes from the bundled NOAA-style station response fixtures in `/app/metadata/noaa-station-fixtures`, while readings, aliases, and sensor windows come from the bundled CSV files. Canonicalize raw station IDs through `/app/metadata/station-aliases.csv` before exclusions, duplicate checks, metadata lookup, aggregates, and output files. Raw IDs without an alias are already canonical.

Report stations in station_id order. The station cache is keyed by station ID for every station with kept readings and stores `metadata_status`, `name`, and `time_zone`. Use `active` only when the fixture has matching `properties.stationIdentifier`, a station name, and a usable IANA time zone. Treat absent fixtures, malformed fixtures, incomplete fixtures, identifier mismatches, and invalid time zones as `missing`.

The readings CSV may contain repeated station/timestamp ingests. Count every CSV row in `readings_count`, but rows with a blank `temp_c`, a `maintenance_hold` quality flag, or an observed instant inside an offline window from `/app/metadata/sensor-health.csv` are excluded before duplicate detection and station aggregates. Sensor windows also canonicalize their station IDs, use UTC-normalized half-open ranges from `status_start` through before `status_end`, and only rows with `status` set to `offline` create blackout exclusions. Count all replaced station/timestamp ingests in the top-level `duplicate_reading_count`, count all excluded readings in the top-level `excluded_reading_count`, count the offline-window subset in the top-level `sensor_blackout_count`, and include each station's combined excluded count as `excluded_reading_count` in that station entry. Station aggregates use only the row with the highest numeric `ingest_sequence` for each station and observed instant after exclusions; normalize `observed_at` to a UTC instant before comparing duplicates so different offset strings for the same moment are treated as the same reading.

Missing metadata, non-ok quality flags from kept readings, replaced duplicate ingests, excluded readings, or offline sensor windows require review. Quality flag arrays include every distinct flag from the deduplicated readings, including `ok`, and average temperatures are rounded half-up to one decimal place. The review queue uses station IDs as keys; each value is an object with a `reasons` array sorted alphabetically from `duplicate_ingest`, `excluded_reading`, `missing_metadata`, `non_ok_quality_flag`, and `sensor_blackout`.

The day rollup file groups deduplicated readings by station and local date. Active station metadata supplies the time zone; stations with missing metadata use UTC. Each station key maps to a list of day objects, and each object includes `local_date`, `reading_count`, `min_temp_c`, `max_temp_c`, `average_temp_c`, and sorted `quality_flags` for that station on that local date. Round the minimum, maximum, and average temperatures half-up to one decimal place.

The excluded-reading audit is a list of the raw readings removed before duplicate detection. Each item stores the original `raw_station_id`, the canonical `station_id`, UTC-normalized `observed_at_utc`, numeric `ingest_sequence`, and the first matching reason from `maintenance_hold`, `blank_temp`, and `sensor_blackout`. Write `observed_at_utc` as an ISO 8601 UTC offset string such as `2026-06-01T01:00:00+00:00`, not with a `Z` suffix. Sort the list by `station_id`, `observed_at_utc`, and `ingest_sequence`.

The trend alert file is a list of rapid temperature changes between consecutive kept readings for the same station after duplicate removal. Compare readings in UTC instant order. Include an alert only when the absolute temperature change is at least 2.0 C and the absolute rate is at least 4.0 C per hour. Each alert stores `station_id`, `from_observed_at_utc`, `to_observed_at_utc`, `from_temp_c`, `to_temp_c`, `temp_delta_c`, `elapsed_minutes`, `rate_c_per_hour`, and `direction`, where direction is `rise` or `fall`. Round temperatures, deltas, and rates half-up to one decimal place. Sort alerts by `station_id`, `from_observed_at_utc`, and `to_observed_at_utc`.

The station health summary file is a list with one row for every station that has kept readings or at least one canonicalized offline sensor window. Each row stores `station_id`, `offline_window_count`, `offline_minutes`, `blackout_reading_count`, `excluded_reading_count`, `duplicate_reading_count`, and `requires_review`. Count only sensor-health rows whose status is `offline`; canonicalize their station IDs before grouping them, and compute `offline_minutes` as the sum of each half-open offline window's duration in whole minutes. `blackout_reading_count` is the number of raw readings excluded by offline windows, `excluded_reading_count` is all exclusions for the station, `duplicate_reading_count` is the number of replaced duplicate ingests for the station after exclusions, and `requires_review` must match the station's review state from the main report. Sort rows by `station_id`.
