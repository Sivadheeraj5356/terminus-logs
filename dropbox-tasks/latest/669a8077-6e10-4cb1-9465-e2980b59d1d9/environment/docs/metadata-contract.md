# Metadata contract

Each metadata directory contains batch.json, batch_policy.json, qc_records.json, equipment_status.json, environmental_logs.json, and documentation_manifest.json. These file names are legacy batch-record feed names used by the quality release system. batch.json and batch_policy.json must share the same batch_id, which identifies the pharmaceutical lot being screened for release authorization.

metadata_digest is batch-fnv64- followed by sixteen lowercase hex digits. Digest parts are built from normalized rows, sorted lexicographically, then hashed with the lot-integrity FNV-1a 64-bit profile. Offset basis is 14695981039346656037 and the FNV prime is 1099511628211. For each sorted part in order, XOR and multiply for every UTF-8 byte of that part, then apply one inter-part separator step: XOR the running state with ASCII LF (decimal 10) and multiply by the FNV prime again before the next part. Omitting the LF separator step is incorrect for metadata_digest. staging_seal uses the same FNV-1a offset and prime over the exact on-disk staging file bytes with no inter-part LF steps. Batch digest rows use only b, batch_id, product_code, manufacturing_start, and manufacturing_end, in that order: b|batch_id|product_code|manufacturing_start|manufacturing_end. Policy digest rows use only p, batch_id, and em_monitoring_days, in that order: p|batch_id|em_monitoring_days. QC rows use q|test_id|status|signed_off. Equipment rows use e|equipment_id|status|calibration_expires|used_in_batch with used_in_batch rendered as lowercase true or false. Environmental rows use v|reading_id|observed_at|excursion|resolved with excursion and resolved as lowercase true or false. Documentation rows use d|doc_type|status|version. Date comparisons for equipment grace and environmental windows use the calendar ordinal rule shared by the release policies.

generated_at in the staging snapshot is always the generated_at value from batch_policy.json so reruns on unchanged metadata stay byte-identical.
