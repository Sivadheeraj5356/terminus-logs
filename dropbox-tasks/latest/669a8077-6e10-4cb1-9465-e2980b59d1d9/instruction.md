Produce the offline GMP lot-release integrity attestation artifacts under /app for quality-unit and compliance reviewers. This is a regulated release-governance security review. The security analysis reads the authoritative lot evidence dossier at /app/environment/metadata/base, materializes the normalized integrity staging capsule at /app/state/batch-release-snapshot.json, advances the release-authorization continuity ledger at /app/state/release-auth-ledger.json, and writes the paired trust attestation at /app/output/batch-release-audit.json.

Security control contracts live in /app/docs/metadata-contract.md, /app/docs/qc-policy.md, /app/docs/equipment-policy.md, /app/docs/environmental-policy.md, /app/docs/documentation-policy.md, /app/docs/staging-snapshot.md, /app/docs/authorization-ledger.md, /app/docs/report-schema.md, and /app/docs/integrity-attestation-invocation.md. Every lot must be classified against quality-control approval and late signoff rules, manufacturing equipment release and calibration grace, environmental excursion windows, and approved release documentation types. Control evaluation order, blocker identifiers, metadata_digest construction, generated_at handling, staging_seal, evaluation_seq, and hold versus released attestation status must match those security contracts exactly. Issuance modes and absolute-path arguments are defined only in /app/docs/integrity-attestation-invocation.md. Re-running attest-release on unchanged dossier evidence must keep snapshot and report gate math stable while evaluation_seq advances in the ledger and report. Setting BATCH_METADATA_DIR to a non-empty absolute directory must make attestation read that dossier instead of the path given by --metadata. Malformed dossier rows, missing required arguments, relative override paths, and unknown issuance modes are invalid security evaluations with process status 2.
