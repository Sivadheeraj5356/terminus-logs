# Media API production decision export

This export combines change-advisory notes, capacity reviews, privacy discussions, and incident follow-ups. Only production records in ratified state with their required approvals can establish policy. A partial decision changes only fields it names; historical, revoked, staging, and rollback material is retained for context.

## Archive discussion 001: privacy review

During review cycle 1, the team compared request metadata, operator audit needs, appeal handling, and the current release checklist. Participants distinguished a temporary operational mitigation from a lasting deployment setting. Capacity observations were retained with sample dates and client cohorts so later reviewers could reproduce the reasoning without treating a measurement as a policy decision.

The minutes note alternatives of 4 MiB, 8 MiB, 16 MiB, and 100 MiB where upload sizing was discussed, alongside several browser-origin sets and threshold tables. These narrative references are deliberately non-authoritative because they lack a complete decision header. Privacy and reliability representatives agreed that each policy dimension can evolve independently. A later change to an upload ceiling or a telemetry field list should not silently reopen browser access, diagnostics, or confidence calibration.

Review cycle 1 closed with follow-up ownership for request metadata. The next cycle must consult scope, state, approvals, and supersession before applying any record. The working group compared the proposal against incident records, operator notes, and the previous deployment window. The discussion documents assumptions and alternatives, but it is not itself an authorization to change production defaults.
