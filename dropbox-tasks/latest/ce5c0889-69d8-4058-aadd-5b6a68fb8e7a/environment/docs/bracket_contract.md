# Bracket playtest atlas contracts

Public schemas for playtest simulation atlases under `/app/output/`. Each snapshot is a JSON file regenerated by deskctl playtest ticks; field rules below define valid shapes and values for win-condition sealing.

## Snapshot inventory

Deskctl must regenerate these seven paths:

- `/app/output/rival_merge.json`
- `/app/output/referee_poll.json`
- `/app/output/verdict_snapshots.json`
- `/app/output/combo_audit.json`
- `/app/output/bracket_seal.json`
- `/app/output/rules_audit.json`
- `/app/output/fw_audit.json`

## Shared field tokens

`winner`, `ruling_side`, and ledger `winner_side` values are `side_a`, `side_b`, or `void`. `resolution_source` values are `cabinet_agree`, `referee`, `rule_void`, `overlay_lane`, or `forfeit`.

## rival_merge.json (`tb3-pixel-duel-01`)

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-01` |
| `q7_a_rows` | int | Row count from `/app/data/q7_a.csv` excluding header; skip blank data lines |
| `q7_b_rows` | int | Row count from `/app/data/q7_b.csv` excluding header; skip blank data lines |
| `merged_count` | int | Distinct `round_id` count across both ledgers |
| `dispute_ids` | int[] | Sorted ascending `round_id` values where `winner_side` differs between the q7_a and q7_b lanes |
| `merged_rounds` | object[] | Each merged round sorted by `round_id` ascending with `q7_a_winner` and `q7_b_winner` |

## referee_poll.json (`tb3-pixel-duel-02`)

The referee_poll snapshot records live in-sim referee oracle results. After the loopback referee oracle starts, poll disputed rounds using each `round_id` from `rival_merge.json` `dispute_ids`.

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-02` |
| `dispute_count` | int | Number of disputed rounds returned; must match `dispute_ids` length from the ledgers snapshot |
| `disputes` | object[] | Sorted by `round_id`; each has `round_id`, `ruling_side`, `cabinet_hint`, `note` |
| `fw_q7_a` | string | Firmware version for the red cabinet from referee `cabinet_meta` |
| `fw_q7_b` | string | Firmware version for the blue cabinet from referee `cabinet_meta` |

Each dispute entry `ruling_side` must match the live referee oracle for that `round_id`.

## verdict_snapshots.json (`tb3-pixel-duel-03`)

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-03` |
| `verdicts` | object[] | Sorted by `round_id`; each has `round_id`, `winner`, `resolution_source`, `moves_valid` |
| `batch_digest` | string | Lowercase hex SHA-256 of the sorted verdicts JSON string (see below) |

**Sorted verdicts JSON (`batch_digest` input).** Hash only the finalized `verdicts` array — not the full snapshot and not individual rows separately:

1. Keep `verdicts` sorted by `round_id` ascending.
2. For each verdict object, reorder keys lexicographically ascending (`moves_valid`, `resolution_source`, `round_id`, `winner`).
3. JSON-encode that array as one compact string with no extra whitespace and unescaped `/` characters (PHP: `json_encode($rows, JSON_UNESCAPED_SLASHES)` after per-row key sort).
4. Take SHA-256 of the UTF-8 bytes of that string; set `batch_digest` to the lowercase hex digest.

Resolution rules:

1. When both ledgers agree on `winner_side`, set `winner` to that side and `resolution_source` to `cabinet_agree`.
2. When ledgers disagree, use the referee `ruling_side` for that `round_id` and set `resolution_source` to `referee`.
3. Before finalizing, validate each ledger's `p1_action,p2_action` pair against `legal_actions` for that `round_id` and ensure neither action appears in `blocked_actions`. If any ledger fails, set `winner` to `void`, `resolution_source` to `rule_void`, and `moves_valid` to false; otherwise `moves_valid` is true.
4. Rule void overrides referee and cabinet agreement.

## combo_audit.json (`tb3-pixel-duel-04`)

Combo scoring evaluates q7_a move pairs only on rounds where stage-3 verdicts report `moves_valid` true. Match each pair against `combo_rules.prefix` values in `/app/run/move_rules.sqlite` using comma-separated tokens (same order as CSV `p1_action,p2_action`). Skip voided rounds entirely.

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-04` |
| `combo_hits` | object[] | Sorted by `round_id`; each has `round_id`, `chain_id`, `bonus_pts`, `matched_prefix` |
| `combo_total` | int | Sum of `bonus_pts` across hits |
| `rounds_scored` | int | Distinct rounds with at least one hit |

CSV importers must ignore blank data lines when counting rows.

## bracket_seal.json (`tb3-pixel-duel-05`)

Overlay rows load from `/app/data/q7_overlay.csv`. Rows with `flags=forfeit` land in `overlay_void_ids` and produce overlay verdicts with `winner` void and `resolution_source` forfeit regardless of `winner_side`. Non-forfeit overlay rows keep `winner_side` with `resolution_source` overlay_lane.

Gate config lives at `/app/config/overlay_gate.json`. The seal lane must read `verdict_snapshots.json` (not the singular snapshot filename) for `upstream_digest`.

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-05` |
| `overlay_rows` | int | Data rows in overlay CSV excluding header and blanks |
| `overlay_void_ids` | int[] | Sorted forfeit round ids |
| `overlay_verdicts` | object[] | Sorted by `round_id`; each has `round_id`, `winner`, `resolution_source` |
| `combo_total` | int | Copied from combo_audit.json |
| `upstream_digest` | string | `batch_digest` from verdict_snapshots.json |
| `seal_digest` | string | Lowercase hex SHA-256 of sorted seal bundle JSON (see below) |

**Sorted seal bundle JSON (`seal_digest` input).** Build one object with keys sorted lexicographically:

1. `combo_total` — integer from combo audit.
2. `overlay_void_ids` — sorted ascending array of forfeit round ids.
3. `upstream_digest` — string batch digest from stage 3.

JSON-encode that object as one compact string with no extra whitespace (`sort_keys` / lexicographic key order). SHA-256 the UTF-8 bytes; lowercase hex digest.

## rules_audit.json (`tb3-pixel-duel-06`)

Rules audit inspects the materialized move-rule store at `/app/run/move_rules.sqlite` after `bash /app/scripts/desk_init.sh`. Orphan round policy and digest recipe live in `/app/docs/move_rule_policy.md`.

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-06` |
| `action_count` | int | Row count in `legal_actions` |
| `combo_count` | int | Row count in `combo_rules` |
| `blocked_count` | int | Row count in `blocked_actions` |
| `orphan_round_ids` | int[] | Sorted `legal_actions.round_id` values absent from both rival CSV fixtures |
| `store_digest` | string | Lowercase hex SHA-256 of sorted store summary JSON (see move_rule_policy.md) |

## fw_audit.json (`tb3-pixel-duel-07`)

Firmware audit reads `/app/output/referee_poll.json` and `/app/config/firmware_policy.json`. Patch drift math and digest recipe live in `/app/docs/firmware_policy.md`.

| Field | Type | Rule |
|-------|------|------|
| `schema_tag` | string | Must be `tb3-pixel-duel-07` |
| `fw_q7_a` | string | Copied from referee poll |
| `fw_q7_b` | string | Copied from referee poll |
| `patch_drift` | int | Patch-level semver drift when major.minor match |
| `policy_limit` | int | Copied from config `max_patch_drift` |
| `policy_excess` | int | Zero when drift is within limit; otherwise drift minus limit |
| `fw_audit_digest` | string | Lowercase hex SHA-256 of sorted firmware audit JSON (see firmware_policy.md) |
