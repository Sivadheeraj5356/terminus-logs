# Logseal release-attestation contract

This document defines the complete input and output contract for the offline Rust security attestation and blast-radius gate in `/app/task_file/logseal`.

Run it as `cargo run --release --bin logseal -- <input_dir> <output_dir>`. The CLI must read `policy.json`, `trusted_logs.jsonl`, `signers.jsonl`, `artifacts.jsonl`, `attestations.jsonl`, `checkpoints.jsonl`, `inclusions.jsonl`, and `revocations.jsonl` from the input directory. The runtime is offline and already contains the locked dependencies. The CLI must write exactly one output file: `<output_dir>/report.json`. Exact-match grading is used.

JSONL files contain one JSON object per non-empty line. Times are RFC3339 strings ending in `Z` and may be compared lexicographically. Artifact ids, signer ids, log ids, checkpoint ids, channel names, cohorts, predicates, and reason strings are case-sensitive. Versions are dot-separated non-negative integers compared numerically by segment, with missing segments treated as zero.

The input schemas are fixed, and `artifact_id` values are unique across `artifacts.jsonl` rows. `policy.json` has string fields `evaluation_time` and `ordering`, array field `channel_priority`, object field `required_predicates_by_channel` mapping channel strings to objects that map predicate strings to integer thresholds, object field `default_required_predicates`, object field `log_quorum_by_channel` mapping channel strings to integer thresholds, integer field `default_log_quorum`, object field `resilience_min_cost_by_channel` mapping channel strings to non-negative integer minimum costs, integer field `default_resilience_min_cost`, object fields `fleet_resilience_targets_by_channel`, `fleet_resilience_direct_targets_by_channel`, and `fleet_resilience_impact_targets_by_channel` mapping channel strings to non-negative integer targets, non-negative integer field `fleet_resilience_min_cost`, integer field `fleet_recovery_domain_budget` from zero through two, object fields `signer_domain_costs` and `log_domain_costs` mapping domain strings to positive integer costs, and object field `allowed_cohorts_by_channel` mapping channel strings to arrays of cohort strings. The three fleet target objects contain exactly the same channel keys. Every cost is at most 1,000,000. `trusted_logs.jsonl` rows have string fields `log_id`, `operator_domain`, `log_secret`, `not_before`, and `not_after`; every `operator_domain` names a key in `policy.log_domain_costs`. `signers.jsonl` rows have string fields `signer_id`, `trust_domain`, `role`, `key_secret`, `not_before`, and `not_after`, plus array fields `artifact_scopes`, `cohorts`, and `predicates`; every `trust_domain` names a key in `policy.signer_domain_costs`. `artifacts.jsonl` rows have string fields `artifact_id`, `version`, `digest`, `channel`, `cohort`, `rollout_start`, and `rollout_end`, non-negative integer fields `fleet_impact` and `fleet_dependency_threshold`, plus array field `dependencies`. Each dependency object has string fields `artifact_id` and `min_version`, non-negative integer field `fleet_weight`, and array field `allowed_channels`. `attestations.jsonl` rows have string fields `attestation_id`, `artifact_id`, `artifact_version`, `predicate`, `digest`, `issued_at`, `signer_id`, `signature`, `log_id`, `leaf_hash`, and `checkpoint_id`. `checkpoints.jsonl` rows have string fields `checkpoint_id`, `log_id`, `root_hash`, `signed_at`, and `signature`, plus integer field `tree_size`. `inclusions.jsonl` rows have string field `attestation_id`, integer field `leaf_index`, and array field `audit_path`; each audit path item has string fields `side` and `hash`, where `side` is `left` or `right`. `revocations.jsonl` rows have string fields `kind`, `target_id`, `effective_at`, and `reason`; only `kind` values `signer`, `attestation`, `log`, and `checkpoint` affect validation.

An attestation signs a canonical payload. The payload fields are `artifact_id`, `artifact_version`, `predicate`, `digest`, `issued_at`, `signer_id`, `log_id`, and `checkpoint_id`, in that order. Canonical bytes are a compact JSON object containing exactly those fields in that order, using normal JSON string encoding, no sorted keys, and no extra whitespace. An attestation signature is valid when `signature` equals the lowercase hex SHA-256 of the signer `key_secret`, a newline byte, and those canonical payload bytes. If `signer_id` does not name a signer, emit `unknown_signer` and skip only signer-owned checks for that attestation: `bad_signature`, `wrong_role`, `scope_mismatch`, `cohort_scope`, `predicate_scope`, `signer_time_window`, and `revoked_signer`. The same attestation must still be checked for digest, version, log, checkpoint, inclusion, threshold, and final artifact-policy reasons. Secrets appear in fixture files only so this offline gate can verify archived data; do not emit them.

A checkpoint signs a canonical payload with fields `checkpoint_id`, `log_id`, `tree_size`, `root_hash`, and `signed_at`, in that order. It is valid when `signature` equals the lowercase hex SHA-256 of the trusted log's `log_secret`, a newline byte, and those canonical payload bytes. Log and checkpoint reasons are additive, but checks are gated only by the objects they require. If `log_id` does not name a trusted log, emit `unknown_log` and skip only `bad_checkpoint_signature` and `checkpoint_time_window`, because those checks require the trusted log's secret or time window. Check `revoked_log` against the attestation's referenced `log_id` whether or not that id names a trusted log and whether or not the checkpoint exists. If `checkpoint_id` does not name a checkpoint, emit `unknown_checkpoint` and skip `checkpoint_log_mismatch`, `bad_checkpoint_signature`, `checkpoint_time_window`, `checkpoint_after_evaluation`, `revoked_checkpoint`, `leaf_hash_mismatch`, and `bad_inclusion_proof`. Whenever the checkpoint exists, evaluate `checkpoint_log_mismatch`, `checkpoint_after_evaluation`, `revoked_checkpoint`, `leaf_hash_mismatch`, and `bad_inclusion_proof` even if the trusted log is unknown or another check has already failed. When both the trusted log and checkpoint exist, also evaluate `bad_checkpoint_signature` and `checkpoint_time_window`. A log can count for an attestation only if the log exists, the checkpoint exists and names that log, the checkpoint signature is valid, the checkpoint `signed_at` is within the inclusive log `not_before` and `not_after` window, the checkpoint `signed_at` is at or before `policy.evaluation_time`, neither the referenced log id nor checkpoint is revoked at or before `policy.evaluation_time`, and the inclusion proof recomputes the checkpoint `root_hash`.

For inclusion proofs, first decode the lowercase hexadecimal text in the attestation `leaf_hash` into raw bytes and use those bytes as the current value. Process each audit path item in order by decoding its `hash` hexadecimal text into raw sibling bytes before concatenation: if `side` is `left`, hash the raw sibling bytes followed by the raw current bytes; if `side` is `right`, hash the raw current bytes followed by the raw sibling bytes. Each SHA-256 digest becomes the raw current bytes for the next step, and the final digest's lowercase hexadecimal encoding must equal the checkpoint `root_hash`. Emit `leaf_hash_mismatch` when the provided `leaf_hash` is not exactly the lowercase hex SHA-256 of the attestation canonical payload bytes. Emit `bad_inclusion_proof` when the inclusion row is missing, `leaf_index` is negative or greater than or equal to the checkpoint `tree_size`, an audit path `side` is not `left` or `right`, the attestation leaf hash or any proof hash is not lowercase hex, or the recomputed root does not equal the checkpoint `root_hash`. These two reasons are independent whenever the checkpoint exists; a bad leaf hash can also cause `bad_inclusion_proof`.

A signer can count for an attestation only if all of these are true: the attestation signature is valid, the signer exists and has role `release`, the artifact id is listed in the signer's `artifact_scopes` or that list contains `"*"`, the artifact cohort is listed in signer `cohorts`, the attestation predicate is listed in signer `predicates`, `issued_at` is within the inclusive signer `not_before` and `not_after` window, the attestation artifact version and digest match the artifact row exactly, neither the signer nor attestation is revoked at or before `policy.evaluation_time`, and the log evidence can count. Unusable attestations still contribute reasons as described below; they just do not count toward thresholds.

Thresholds are channel-specific. For each artifact row, use `policy.required_predicates_by_channel[channel]` when present, otherwise `policy.default_required_predicates`. Every required predicate must have at least its required number of distinct usable signer ids. An attestation whose predicate is not required for that artifact's channel never counts toward signer thresholds and does not by itself add a reason unless another documented rule applies. The log quorum is `policy.log_quorum_by_channel[channel]` when present, otherwise `policy.default_log_quorum`; each artifact must have usable attestations from at least that many distinct log ids across all required predicates. Log ids for quorum and `accepted_logs` come from all usable attestations for required predicates, including usable duplicate-signer attestations that are not the retained signer entry. If one signer signs the same artifact and predicate more than once, count that signer once in `accepted_signers` and keep the usable attestation with the latest `issued_at`; ties use the lexicographically smaller `attestation_id`. Accepted signer ids are sorted lexicographically per predicate. Accepted log ids are sorted lexicographically.

Usable required-predicate attestations also form the artifact's resilience evidence graph. Each usable attestation is an edge between its signer's `trust_domain` and its trusted log's `operator_domain`, labelled by its predicate, signer id, and log id. For a hypothetical cut, remove every usable attestation whose signer trust domain or log operator domain is selected. Recompute distinct usable signer ids separately for each required predicate and distinct usable log ids across all required predicates. A cut breaks the artifact when at least one predicate falls below its threshold or the remaining logs fall below the log quorum. Attestations for unrequired predicates and attestations that are unusable for any documented reason never enter this graph. Multiple attestations with the same signer, predicate, and log do not create extra signer or log counts.

Find the deterministic minimum resilience cut over all subsets of relevant signer trust domains and log operator domains, including the empty subset. Its cost is the sum of each selected unique domain's configured cost; the signer and log namespaces are separate even if their text is equal. Input fixtures contain at most 16 combined relevant domains per artifact. Compare breaking cuts by total cost, then total number of selected domains, then the first broken condition (`threshold:<predicate>` in lexicographic predicate order before `log_quorum`), then the lexicographic signer-domain array, then the lexicographic log-domain array. A cut's `failure` is that first broken condition even when it breaks several. If no cut can break an artifact because every required threshold and its log quorum are zero, its cut fields are null as described below. Use `policy.resilience_min_cost_by_channel[channel]` when present, otherwise `policy.default_resilience_min_cost`. Emit `resilience_shortfall` only when the artifact has a finite minimum cut whose cost is strictly less than the required minimum; equality passes. This final-state reason is additive with baseline threshold, quorum, rollout, and cohort reasons. A baseline threshold or quorum failure therefore has the empty cut with cost zero and can also emit `resilience_shortfall` when the required minimum is positive.

Also compute one dependency-amplified fleet resilience cut across all channels named in the three fleet target objects. A candidate artifact belongs to a named channel and, before any hypothetical removal, meets every required predicate threshold and its log quorum using its usable evidence graph. Its other attestation reasons, rollout state, cohort state, dependency state, and per-artifact resilience result do not affect fleet candidacy. For a hypothetical fleet cut, remove matching signer and log domains from every candidate graph. A candidate is directly broken when any required predicate threshold or its log quorum then fails.

Starting with the directly broken candidates at cascade depth zero, propagate failures in synchronous rounds. At the start of each round, for every still-unbroken candidate whose positive `fleet_dependency_threshold` is greater than zero, sum `fleet_weight` from every object in its input `dependencies` array whose `artifact_id` names a candidate already broken in an earlier round. Mark the candidate broken in the current round when that sum is at least its threshold. All candidates selected in one round become visible only to the next round. A zero threshold disables dependency propagation for that artifact. Every dependency row contributes separately, including repeated rows naming the same artifact. `min_version` and `allowed_channels` remain release-policy fields and do not change blast-radius propagation. A dependency that names a missing artifact or a non-candidate contributes zero weight. Continue until a full round marks no candidate. Cycles do not break themselves, but a sufficiently weighted seed can propagate through a cycle. `directly_broken_artifacts` contains only evidence-broken candidates; `broken_artifacts` contains both direct and propagated failures. `cascade_depth_by_artifact` maps every broken artifact id to its zero-based break round, so direct failures have depth zero.

For every targeted channel, a cut qualifies only when its directly broken count is at least `fleet_resilience_direct_targets_by_channel[channel]`, its complete broken count is at least `fleet_resilience_targets_by_channel[channel]`, and the sum of `fleet_impact` over its complete broken candidates is at least `fleet_resilience_impact_targets_by_channel[channel]`. All three conditions are simultaneous. A zero target is already satisfied. Artifacts in channels absent from the target objects are neither candidates nor included in either broken list.

A selected fleet cut is recovery-safe only when every effective cut formed by restoring any subset of at most `policy.fleet_recovery_domain_budget` selected domains still qualifies under all three target families after recomputing direct failures and the entire synchronous cascade from scratch. Recovery counts domains, not their configured costs, and signer and log namespaces remain distinct. Restoring no domains is included implicitly by testing the selected cut itself. When the budget is zero, this adds no condition. The report describes the original selected cut before any hypothetical recovery.

For each qualifying selected cut, compute its recovery breakpoint by considering every non-empty subset of its selected domains. A subset defeats the cut when restoring it makes the recomputed effective cut fail any target. The breakpoint is the defeating subset with the smallest domain count, then the smallest sum of the restored domains' configured costs, then the complete lexicographic restored signer-domain array, then the complete lexicographic restored log-domain array. It is null only when no restoring subset defeats the cut. Recovery safety is equivalently a null breakpoint or a breakpoint count strictly greater than the recovery budget.

For each recovery-safe cut, also compute a recovery-margin witness over restoration subsets whose domain count is at most the recovery budget, including the empty subset. For each such recomputed qualifying outcome, form three integer slacks for every targeted channel: directly broken count minus its direct target, complete broken count minus its total target, and complete broken impact minus its impact target. The outcome margin is the minimum of those slacks, or zero when there are no targeted channels. The cut's recovery margin is the smallest outcome margin over the permitted restoration subsets. Choose its witness by margin value, then restored-domain cost, then the complete lexicographic restored signer-domain array, then the complete lexicographic restored log-domain array, all ascending. Thus the empty restoration wins an otherwise exact tie because its restored cost is zero.

Find the recovery-safe qualifying fleet cut over all subsets of the combined relevant candidate domains, including the empty subset. The signer and log namespaces remain separate, and fixtures contain at most 18 combined relevant fleet domains. Compare eligible cuts by total cut cost; then prefer the larger recovery-margin value; then prefer the larger recovery-breakpoint count, treating null as larger than every integer; then prefer the larger recovery-breakpoint cost, again treating null as larger than every integer; then prefer the smaller total selected-domain count; then compare the complete lexicographic selected signer-domain array and selected log-domain array. Both broken-artifact arrays are sorted lexicographically and include qualifying failures beyond the requested targets. The cascade-depth object has lexicographically ordered artifact keys. `broken_impact_by_channel` contains every targeted channel key and the summed impact of its complete broken set. `shortfall` is true exactly when a finite selected cut has cost strictly less than `policy.fleet_resilience_min_cost`; equality passes. If no recovery-safe qualifying cut exists, use null cost, false shortfall, empty arrays, an empty cascade-depth object, zero impact for every targeted channel, and null recovery-breakpoint and recovery-margin fields. When all targets are zero, the empty cut qualifies with cost zero, empty broken-artifact arrays, an empty cascade-depth object, zero impacts, a null recovery breakpoint, and a recovery-margin witness with value and restored cost zero and empty domain arrays.

Artifact policy rules are final-state rules and are additive with attestation rules. An artifact row is rejected if `policy.evaluation_time` is before `rollout_start` or after `rollout_end`, or if the artifact cohort is not listed in `policy.allowed_cohorts_by_channel[channel]`. Missing channel entries mean no cohorts are allowed.

Dependency evaluation is two-phase and non-iterative. First evaluate every artifact using attestation, signer, log, threshold, rollout, and cohort rules. Then check dependencies exactly once against those first-phase artifact states; dependency failures do not cascade into other artifacts' dependency checks. Each dependency names an artifact id, a minimum version, and allowed channels. For each dependency, emit only the first applicable blocker in this order: dependency artifact is missing, has at least one first-phase rejection reason, has a version below the minimum, or has a channel that is not allowed. Dependency blockers are emitted in input dependency order using `missing:<id>`, `rejected:<id>`, `version:<id>`, or `channel:<id>`.

For each artifact, emit every applicable reason in this exact order: `bad_signature`, `unknown_signer`, `wrong_role`, `scope_mismatch`, `cohort_scope`, `predicate_scope`, `signer_time_window`, `digest_mismatch`, `version_mismatch`, `revoked_signer`, `revoked_attestation`, `unknown_log`, `unknown_checkpoint`, `checkpoint_log_mismatch`, `bad_checkpoint_signature`, `checkpoint_time_window`, `checkpoint_after_evaluation`, `revoked_log`, `revoked_checkpoint`, `leaf_hash_mismatch`, `bad_inclusion_proof`, then any `threshold:<predicate>` reasons in lexicographic predicate order, then `log_quorum`, `resilience_shortfall`, `rollout_window`, `cohort_not_allowed`, and `dependency_blocked`. Reasons are additive and each reason string appears at most once per artifact.

`report.json` must be a JSON object with `generated_at`, `artifacts`, `fleet_resilience_cut`, and `summary`. `generated_at` is exactly `policy.evaluation_time`. `artifacts` is an array of objects with `artifact_id`, `version`, `channel`, `cohort`, `status`, `reasons`, `accepted_signers`, `accepted_logs`, `resilience_cut`, and `dependency_blockers`. `status` is `accepted` only when there are no reasons; otherwise it is `rejected`. `accepted_signers` is an object whose keys are all required predicates for that artifact row and whose values are arrays of accepted signer ids, including empty arrays. `accepted_logs` is the sorted array of distinct accepted log ids used for that artifact's log quorum, including an empty array when none count. `resilience_cut` is an object with `cost`, `failure`, `signer_domains`, and `log_domains`. For a finite cut, `cost` is an integer, `failure` is the selected `threshold:<predicate>` or `log_quorum` string, and both domain fields are sorted string arrays including empty arrays. When no cut can break an artifact, `cost` and `failure` are JSON null and both domain arrays are empty. `dependency_blockers` is present for every artifact, including an empty array when no dependency blocked it. `fleet_resilience_cut` is an object with integer-or-null `cost`, boolean `shortfall`, sorted string arrays `directly_broken_artifacts`, `broken_artifacts`, `signer_domains`, and `log_domains`, object `cascade_depth_by_artifact` mapping every broken artifact id to its integer depth, object `broken_impact_by_channel` mapping every targeted channel to its integer impact sum, object-or-null `recovery_breakpoint`, and object-or-null `recovery_margin`. A non-null breakpoint object has integer `count` and `cost` plus sorted string arrays `signer_domains` and `log_domains`. A non-null margin object has integer `value` and `restored_cost` plus the same two sorted domain arrays. Both nested objects describe restored rather than removed domains. The finite, impossible, and all-zero-target forms are defined above. `summary` has integer fields `accepted`, `rejected`, and `total`.

When `policy.ordering` is `artifact_id`, sort artifacts by `artifact_id`, then version, then channel, then cohort. When it is `channel_priority`, sort by channel order from `policy.channel_priority`, then artifact id, then version, then cohort; channels not in the priority list sort after listed channels in lexicographic order. Empty arrays and objects are valid and must still be present.
