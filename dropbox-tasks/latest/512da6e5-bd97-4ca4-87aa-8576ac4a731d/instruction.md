A CDN edge runs a fetch-admission guard: before it pulls a resource from an upstream, it checks the request against the route's allowlist and either admits the fetch or blocks it. Leave the check too loose and an attacker slips an injected `data:` script or a look-alike host such as `evil.example.com.attacker.com` past the allowlist, and the smuggled content runs; make it too strict and the guard drops assets the site legitimately serves. The guard in the Go sources at `/app` makes exactly this allow-or-block decision. It is handed the allowlist attached to a route (the raw value of a Content-Security-Policy directive such as `script-src`), the candidate resource URL, and the page's own origin, and answers whether that fetch is admitted. What is there now leans on loose substring and prefix checks that both wave through fetches it should refuse and turn away legitimate ones; the job is to enforce the allowlist precisely so the bypasses close without breaking real traffic.

The guard enforces the allowlist with the Content-Security-Policy Level 3 rules for matching a URL against a source list, which govern every case here: `'self'` against the origin scheme, host, and port, where the only scheme relaxations allowed are `http`-to-`https` and `ws`-to-`wss` (matched against the URL scheme's own default port), so an `https` origin does not admit a `wss` URL and a `wss`/`https` URL is never admitted by a `ws`/`http`-only match; a `*.example.com` host wildcard that admits subdomains but not the bare domain or a different domain; a scheme source such as `https:` matching by scheme while opaque schemes like `data:`, `blob:`, and `filesystem:` match only when their scheme is listed explicitly; ports compared using the scheme default when none is given. A bare `*` source matches any URL whose scheme is a network scheme (`http`, `https`, `ws`, `wss`) with any host and port, but does not by itself match the opaque `data:`, `blob:`, or `filesystem:` schemes. `'none'` blocks every fetch only when it is the sole entry in the source list; when it appears alongside other sources it carries no meaning and those other sources decide. A source path ending in `/` matches as a directory prefix while one without a trailing slash must match exactly, both after percent-decoding, and a host with no path matches any path; `'unsafe-inline'`, `'unsafe-eval'`, nonces, and hashes do not match a URL request. Scheme and host comparisons are case-insensitive.

The program reads one JSON object per line from standard input, each with the fields `source_list`, `url`, and `origin`, and writes one line per input to standard output containing exactly `ADMIT` or `BLOCK`, in the same order. It is built from the Go sources in `/app` into the `/app/fetch_gate` binary and run as `/app/fetch_gate`. Keep the input/output contract and the per-line ordering intact.
