Our risk science team has exported a trained sparse logistic model for horizon-aware fraud risk scoring. Implement the offline model inference and calibration audit routine in `/app/task_file/calibrator.py`. The evaluator accepts exactly one argument, the task root path, consumes the trained model artifacts and binary request batch under `/app/task_file`, and emits the required model-scoring reports under `/app/task_file/output`.

The complete inference semantics, trained-artifact formats, feature normalization rules, sparse observation handling, score calibration rules, monotonic post-calibration pooling rules, and audit report schemas are defined in `/app/task_file/SPEC.md`. In particular, preserve the bundled request batch and trained model artifacts, support duplicate and unknown feature observations exactly as specified, apply first-matching horizon windows, segment drift, pairwise feature interactions, calibration bands, post-calibration monotonic rules, probability clamping, risk labels, feature attribution traces, segment-level calibration summaries, record-level diagnostics, per-interaction contribution tracing, per-record monotonic pooling audits, global horizon reruns, single-feature ablation reruns, second-order pairwise ablation reruns, rank-corridor dominance chains, and robust policy-frontier optimization.

Scenario names are exact strings. Single-feature ablation scenarios must be named `ablated_<feature_id>` with the trailing `d`; `ablate_<feature_id>` is incorrect. Pairwise ablation scenarios are named `pair_ablated_<feature_a>_<feature_b>` with `feature_a < feature_b`. Every scenario is a full-batch rerun through feature inference, interactions, calibration, monotonic pooling, label assignment, and prediction sorting.

The evaluator must write `/app/task_file/output/predictions.csv`, `/app/task_file/output/feature_trace.csv`, `/app/task_file/output/segment_summary.csv`, `/app/task_file/output/record_diagnostics.csv`, `/app/task_file/output/interaction_trace.csv`, `/app/task_file/output/monotonic_audit.csv`, `/app/task_file/output/horizon_stability.csv`, `/app/task_file/output/feature_ablation.csv`, `/app/task_file/output/policy_frontier.csv`, `/app/task_file/output/rank_corridor.csv`, `/app/task_file/output/resilient_frontier.csv`, and `/app/task_file/output/pairwise_ablation.csv`. These twelve reports are used for model monitoring and calibration review, so they must use the headers, row ordering, decimal formatting, empty-batch behavior, and final trailing newline required by `/app/task_file/SPEC.md`; malformed request input must exit nonzero without leaving stale scoring reports behind.
