In this milestone an external auditor receives a presented copy of the transparency log (a list of entry dicts that may have been tampered with in transit or storage) together with a registry of trusted signing-key fingerprints, and must pinpoint exactly what is wrong with each entry. Implement this in a flat module at exactly /app/transparency/audit.py (importable as import audit with /app/transparency on sys.path).

Each presented entry has the milestone-3 committed fields plus the signer's key: index, prev_hash, manifest_hash, signature (base64 Ed25519 over the ASCII bytes of the lowercase hex manifest_hash), entry_hash, and public_key (base64 of the raw 32-byte Ed25519 public key). A key's fingerprint is key_id(raw_pub) = sha256(raw_pub)[:16], the first 16 lowercase hex chars, and the registry of trusted keys is a list of such fingerprints. The function recompute_entry_hash(index, prev_hash, manifest_hash, signature) is the lowercase hex SHA-256 of the compact canonical JSON of those four fields (json.dumps(..., sort_keys=True, separators=(",", ":"))), exactly as in milestone 3.

The function localize_log(entries, trusted_key_ids) returns one result per presented entry, in order, shaped as {"index": <the entry's claimed index>, "reasons": [<sorted reasons>], "trusted": <bool>}, where trusted is true if and only if reasons is empty. The reasons are drawn from a fixed vocabulary exported as the sorted tuple audit.REASONS. The reason index_inconsistent fires when the entry's claimed index is not equal to its 0-based position in the presented list. The reason broken_chain fires when prev_hash is not equal to the expected predecessor: 64 zeros for position 0, otherwise the previous presented entry's claimed entry_hash. The reason entry_hash_mismatch fires when recompute_entry_hash(index, prev_hash, manifest_hash, signature) is not equal to the entry's claimed entry_hash. The reason untrusted_key fires when the public_key is missing or malformed, or its key_id is not in trusted_key_ids. The reason bad_signature fires when the key is trusted but its Ed25519 signature does not verify over the ASCII bytes of manifest_hash. The reason replay fires when this (manifest_hash, signature) pair already appeared in an earlier presented entry.

These reasons are independent, accumulating predicates, never mutually exclusive branches. Evaluate every one on its own and collect all that fire, rather than stopping at the first match or modelling them as an if/elif chain, because a single tamper routinely trips several at once. The bad_signature reason is only added when the key is trusted, since otherwise untrusted_key already explains it.

The function audit_log(presented) takes {"entries": [...], "trusted_key_ids": [...]} and returns {"rows": [...], "n_trusted": <int>, "n_bad": <int>, "per_reason": {<reason>: <int>}}, where rows is the localize_log output, n_trusted counts trusted rows, n_bad is len(rows) minus n_trusted, and per_reason has exactly one integer per reason in audit.REASONS counting how many rows carry it (a row contributes to every reason it carries). Keep these exact importable names: localize_log(entries, trusted_key_ids), audit_log(presented), recompute_entry_hash(index, prev_hash, manifest_hash, signature), key_id(raw_pub), and REASONS.
