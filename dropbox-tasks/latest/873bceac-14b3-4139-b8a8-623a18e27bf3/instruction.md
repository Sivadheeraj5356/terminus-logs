The RelicMaze escape-room sim has a Java game-master library under /app/relicmaze, and right now `com.relicmaze.Resolver` is just a stub. I need it to actually answer seekers: given a capsule and a player's transcript, `resolve()` has to replay the transcript and return the exact narration and the ordered list of next actions that a Keeper would speak. The canonical rules for all of that live in /app/relicmaze/manual/keeper-manual.md, which is the source of truth for how every line of the account is composed.

The room, relic, and passage data is not in any file you can read directly; it lives in the running PostgreSQL database (see /app/relicmaze/db.properties for the connection). Query it live over JDBC. The capsules are the OCI-style image-config JSON files under /app/relicmaze/capsules, and the manual explains which of their labels and history entries the Keeper actually acts on.

You can sanity-check yourself with `cd /app/relicmaze/verifier && npm test`, which builds your resolver, runs it against the sample scenarios in /app/relicmaze/fixtures, and diffs the output against the golden files. The scored suite uses more scenarios than the samples, and everything is compared byte-for-byte, so match the manual exactly.
