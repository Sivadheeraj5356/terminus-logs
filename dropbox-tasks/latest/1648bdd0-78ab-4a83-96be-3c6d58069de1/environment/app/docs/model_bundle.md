# Model release bundle

The policy is `/app/config/repro_config.json`. Training inputs are Parquet files with exactly `id`, `feature_0` through `feature_3`, and binary integer `label`; `id` is metadata and unique, all model values are finite, and both classes have at least the configured fold count.

For each candidate, run `cv_repeats` shuffled `StratifiedKFold` partitions. Repeat `r` uses split seed `random_state + r * repeat_seed_stride`; fold `f` fits its forest with random state `split_seed + f + 1`. Each repeat produces one raw OOF probability per row. Within that repeat, cross-fit sigmoid calibration by fitting `LogisticRegression(C=calibration_c, solver="lbfgs", max_iter=1000)` on the other folds' raw OOF probabilities and labels, then calibrating the held-out fold. Average raw probabilities row-wise across repeats to obtain released raw OOF probabilities, and average calibrated probabilities row-wise for evaluation. Fit the released calibrator on the averaged raw OOF probabilities and all labels.

Brier values are mean squared error on the averaged OOF arrays. Select one threshold from sorted unique averaged calibrated OOF probabilities plus `0.0` and `1.0`; maximize F1 and choose the higher threshold on a tie. OOF accuracy uses that global threshold. `fold_f1` is repeat-major then fold-minor and applies the global prediction vector to each repeat's held-out subset. `repeat_f1` thresholds each repeat's calibrated OOF vector with the same global threshold. Select the champion by highest OOF F1, lowest calibrated Brier, highest worst-repeat F1, highest worst-fold F1, lowest `n_estimators * max_depth`, then lexical name.

A successful training run leaves exactly `model.joblib`, `calibrator.joblib`, `metrics.json`, `drift_profile.json`, and `artifact_manifest.json` in the artifacts directory. JSON is UTF-8 canonical JSON: recursively sorted keys, compact separators, finite numbers, and one trailing newline.

`metrics.json` has exactly `model_version`, `champion`, `positive_class`, `calibration_method`, `calibration_c`, `calibration_intercept`, `calibration_coefficient`, `decision_threshold`, `raw_brier`, `calibrated_brier`, `oof_accuracy`, `oof_f1`, `worst_repeat_f1`, `repeat_f1`, `worst_fold_f1`, `fold_f1`, `training_rows`, `cv_folds`, `cv_repeats`, `random_state`, `repeat_seed_stride`, and `candidate_scores`. Candidate scores follow policy order and each has exactly `name`, `complexity`, `decision_threshold`, `raw_brier`, `calibrated_brier`, `oof_accuracy`, `oof_f1`, `worst_repeat_f1`, `repeat_f1`, `worst_fold_f1`, and `fold_f1`.

`drift_profile.json` has `profile_version` equal to `6` and exactly `profile_version`, `feature_order`, `quantiles`, `features`, `prediction_profile`, `disagreement_profile`, `correlation_profile`, `leaf_profile`, and `path_sketch_profile`. Feature, prediction, and disagreement profile values have exactly `mean`, `std`, `cut_points`, and `bin_proportions`. Quantiles use NumPy's linear method, duplicate cuts are removed, and values equal to a cut use the lower bin (`searchsorted(..., side="left")`). Feature profiles use training columns. `prediction_profile` uses the full-data refit forest followed by the released calibrator on training rows.

For `disagreement_profile`, obtain every fitted tree's positive-class probability for each row, using zero if a tree has no positive class. A row's tree disagreement is the square root of the mean squared deviation of those tree probabilities from their row mean. Profile those disagreement values with the same quantiles and `profile_ddof`.

`correlation_profile` has exactly `metric` and `pairs`; `metric` is `spearman_rank`. `pairs` is an array in nested feature-order combination order (`feature_0|feature_1`, `feature_0|feature_2`, and so on), with one object per unordered pair and exactly `key`, `left`, `right`, and `coefficient`. Compute Spearman correlation as Pearson correlation of average ranks. If either ranked vector is constant, the coefficient is exactly `0.0`.

`leaf_profile` has exactly `metric` and `trees`; `metric` is `jensen_shannon_natural_log`. `trees` follows estimator order and has one object per forest tree. Each tree object has exactly `leaf_ids` and `bin_proportions`: sorted unique integer leaf ids returned by `model.apply(training_features)` for that tree and their row proportions in the same order.

`path_sketch_profile` has exactly `metric`, `hash`, `salt`, `bucket_count`, and `bin_proportions`. Its metric is `joint_leaf_path_jensen_shannon_natural_log` and its hash identifier is `sha256_first_u64_be_mod`. For each row, take the estimator-order leaf vector, build UTF-8 bytes from `<salt>|<leaf0>,<leaf1>,...`, hash with SHA-256, interpret the first eight digest bytes as an unsigned big-endian integer, and reduce modulo `bucket_count`. `bin_proportions` contains every bucket in numeric order, including zero buckets.

`artifact_manifest.json` has exactly `schema_version`, `model_version`, `champion`, `feature_order`, `training_rows`, `training_parquet_sha256`, `config_sha256`, `artifact_sha256`, and `release_sha256`, with `schema_version` equal to `7`. `artifact_sha256` maps exactly the four non-manifest artifacts to lowercase `sha256:` digests over exact bytes. Training and policy digests use the same form. `release_sha256` hashes canonical JSON bytes, without a newline, of exactly `model_version`, `champion`, `feature_order`, `training_rows`, `training_parquet_sha256`, `config_sha256`, and `artifact_sha256`.

## Release validation

Before `run-drift` performs any product API request, it re-runs every repeat and fold for every policy candidate and re-derives the champion and complete `metrics.json`. It also refits the expected champion, compares the stored forest's parameters, probabilities, and leaf assignments on the supplied training rows, verifies the released calibrator's parameters/classes/coefficient/intercept, and reproduces every feature, prediction, disagreement, correlation, per-tree leaf, and joint path-sketch profile. A hash-consistent artifact that violates one of these semantic bindings is attributed to that artifact's concrete filesystem path.
