# Entitlement lineage corruption policy (read-only specification)

Implement these rules in Go under `/app/cmd` and `/app/internal` only; do not edit this file or other files under `/app/provenance_charters/`.

Fixtures live under `/app/delegation_federation_slices` as `delegation_slice_XX.json` (01–28) plus `/app/delegation_federation_slices/delegation_slice_XX/inheritance_journal.elwj` (ELWJ little-endian per `ELWJ1_INHERITANCE_JOURNAL_CODEC.md`). JSON files hold slice defaults only (no `events` array). `/app/delegation_federation_slices/federation_slice_roll.json` lists `delegation_slices` in processing order.

## Slice defaults

- `require_attestation_on_operational` (bool): **defaults to `true`** when the field is omitted from scenario JSON
- `block_vendor_to_sovereign` (bool): **defaults to `true`** when the field is omitted from scenario JSON
- `governance_overrides` (optional object): may override either boolean above after defaults are applied

Apply `governance_overrides` on top of these defaults before replay begins. A scenario JSON file that lists only `"delegation_slice_id"` uses both defaults as `true`.

## Event ordering and deduplication

Sort events ascending by `(seq, coordinator_id, event_id)` using the **`coordinator_id` field exactly as decoded from the inheritance_journal JSON** — do **not** substitute `grantee_coordinator`, `eval_target_id`, or any other field for sorting. Bundled ELWJ payloads carry `coordinator_id` on trust and auth events; that raw value is the sort tie-breaker. **Sorting by `seq` alone is incorrect** when multiple events share the same `seq` (for example a `GRANT_INHERITANCE` whose `coordinator_id` sorts after its endpoints must still run only after both coordinators are registered).

**`event_id` dedup identity** — Before duplicate detection, compute `id_key` = ASCII-trim of `event_id`. If `id_key` is empty (omitted, `""`, or whitespace-only), the row never participates in dedup: do not skip it and do not insert into the seen set. If `id_key` is non-empty and was already seen, skip the row and increment `duplicate_events_skipped` (first non-empty trimmed identity wins). Sorting still uses the raw `event_id` string as decoded.

## Coordinator state

Per `coordinator_id`: `privilege_tier` (`operational`, `vendor`, or `sovereign`), `business_unit` (non-empty string after canonicalization), `entitlement_bindings` (set of strings from `BIND_ENTITLEMENT`).

**Business-unit canonicalization** — Before storing or comparing `business_unit`, apply in order: trim ASCII whitespace, convert to lowercase, then replace every ASCII underscore (`_`) with a hyphen (`-`). An omitted or whitespace-only value becomes `business-core` **after** those steps. Example: `" Business_Core "` and `"business-core"` compare equal. `DOMAIN_BLEED` compares only these canonical forms.

Track purged coordinator IDs in a **tombstone** set for the slice. Purged IDs are absent from live coordinator state until the slice ends.

## REGISTER_COORDINATOR

Fields: `coordinator_id`, `privilege_tier`, optional `business_unit`.

If `coordinator_id` is in the tombstone set → `RESURRECTED_ENTITLEMENT` (`entity_id` = `coordinator_id`, `detail` = **empty**; no mutation).

If `coordinator_id` already exists in live state → `DUPLICATE_COORDINATOR` (no mutation).

Else create coordinator with empty `entitlement_bindings`. When `business_unit` is omitted, empty, or whitespace-only before canonicalization, store `business-core`; otherwise store the canonical form (trim + lowercase + `_`→`-`).

## RETIRE_COORDINATOR_SCOPE

Fields: `coordinator_id`.

If `coordinator_id` is not in live state → `UNKNOWN_COORDINATOR` (`entity_id` = `coordinator_id`, `detail` = event kind).

Else remove the coordinator, add its ID to the tombstone set, and delete every `GRANT_INHERITANCE` edge where `grantor_coordinator` or `grantee_coordinator` equals that ID.

## GRANT_INHERITANCE

Fields: `grantor_coordinator`, `grantee_coordinator` (both non-empty).

If either endpoint is unknown → `UNKNOWN_COORDINATOR` when `grantor_coordinator` is missing (`entity_id` = `grantor_coordinator`, `detail` = event kind); else `UNKNOWN_TARGET` (`entity_id` = `grantee_coordinator`, `detail` = event kind).

If directed edge `grantor_coordinator→grantee_coordinator` already exists → `DUPLICATE_INHERITANCE` (`entity_id` = `grantee_coordinator`, `detail` = `grantor_coordinator`). Else record the edge.

## REVOKE_INHERITANCE

Fields: `grantor_coordinator`, `grantee_coordinator`.

If `grantor_coordinator` is not registered → `UNKNOWN_COORDINATOR` (`entity_id` = `grantor_coordinator`, `detail` = event kind).

If `grantee_coordinator` is not registered → `UNKNOWN_TARGET` (`entity_id` = `grantee_coordinator`, `detail` = event kind).

When both endpoints are registered and the directed edge `grantor_coordinator→grantee_coordinator` is absent → **no finding** (do not mutate state).

When both endpoints are registered and the edge exists → remove the edge.

## BIND_ENTITLEMENT

Fields: `coordinator_id`, `entitlement_key` (non-empty).

Missing coordinator → `UNKNOWN_COORDINATOR` (`entity_id` = `coordinator_id`, `detail` = event kind). Else add entitlement_key (idempotent).

## ACCESS_EVAL

Fields: `requestor_id`, `eval_target_id`, `action`, `has_governance_attestation` (bool), `propagated_entitlements` (array), optional `provenance_requestor` (default `""`).

Evaluate in order; **stop** further checks for this event after emitting `UNKNOWN_TARGET`, `UNKNOWN_COORDINATOR`, `UNTRUSTED_INHERITANCE`, `DOMAIN_BLEED`, `RESTRICTED_TIER`, or `UNATTESTED_ACCESS`.

1. Missing `eval_target_id` registration → `UNKNOWN_TARGET` (`entity_id` = `eval_target_id`, `detail` = event kind).
2. Missing `requestor_id` registration → `UNKNOWN_COORDINATOR` (`entity_id` = `requestor_id`, `detail` = event kind).
3. No directed `GRANT_INHERITANCE` edge **`requestor_id` → `eval_target_id`** (caller is `grantor_coordinator`, callee is `grantee_coordinator`) → `UNTRUSTED_INHERITANCE` (`entity_id` = `eval_target_id`, `detail` = `requestor_id`). Do not test the reverse edge.
4. Caller `business_unit` ≠ callee `business_unit` → `DOMAIN_BLEED` (`entity_id` = `eval_target_id`, `detail` = `requestor_id`).
5. Caller privilege_tier `vendor` and callee privilege_tier `sovereign` → evaluate `RESTRICTED_TIER` (`entity_id` = `requestor_id`, `detail` = `eval_target_id`) as follows after `governance_overrides`:
   - If `block_vendor_to_sovereign` is **true** → always emit `RESTRICTED_TIER` and stop (callee bindings are irrelevant).
   - If `block_vendor_to_sovereign` is **false** → emit `RESTRICTED_TIER` and stop **only when** the sovereign callee’s `entitlement_bindings` do **not** contain `governance:audit`. If the callee **does** hold `governance:audit`, skip this check (no `RESTRICTED_TIER`) and continue to later ACCESS_EVAL checks.
   - **Worked examples (vendor → sovereign ACCESS_EVAL after overrides):**
     - `block_vendor_to_sovereign=true` (default or explicit) → always `RESTRICTED_TIER`, even if callee has `governance:audit` and/or `governance:admin`.
     - `block_vendor_to_sovereign=false` and callee **lacks** `governance:audit` → still `RESTRICTED_TIER` (override alone is not a free pass).
     - `block_vendor_to_sovereign=false` and callee **has** `governance:audit` → **no** `RESTRICTED_TIER`; continue. `UNATTESTED_ACCESS` still applies only when the callee’s privilege_tier is `operational` (sovereign callees never emit `UNATTESTED_ACCESS` from check 6).
   Agents that treat `block_vendor_to_sovereign=false` as an unconditional bypass are incorrect.
6. Callee privilege_tier `operational`, `require_attestation_on_operational`, and not `has_governance_attestation` → `UNATTESTED_ACCESS` (`entity_id` = `eval_target_id`, `detail` = **empty**).
7. **ENTITLEMENT_ESCALATION** — Ignore empty-string entries in `propagated_entitlements`. Let `miss` be the lexicographically **first** remaining `entitlement_key` that is absent from the **caller’s** `entitlement_bindings` (sort the non-empty keys before scanning). If `miss` is empty, skip check 7. Otherwise maintain a per-scenario set of keys `requestor_id::entitlement_key`: emit `ENTITLEMENT_ESCALATION` (`entity_id` = `requestor_id`, `detail` = `miss`) **only when** `requestor_id::miss` is not already in the set, then add it. Later `ACCESS_EVAL` rows with the same missing pair produce **no second** `ENTITLEMENT_ESCALATION`. Checks 7–8 run only if checks 1–6 did not fire.
8. **LATERAL_GHOSTING** — Evaluate whenever checks 1–6 did not fire, **including when check 7 emitted `ENTITLEMENT_ESCALATION` or skipped due to dedup**. When `provenance_requestor` is non-empty, `provenance_requestor != requestor_id`, and the same `miss` rule from check 7 (lexicographically first missing propagated claim on the **caller**) yields a non-empty `miss`, emit `LATERAL_GHOSTING` with **`entity_id` = `provenance_requestor`** (never `requestor_id`), `detail` = `miss`. Do **not** emit `LATERAL_GHOSTING` merely because `requestor_id != eval_target_id`. When both checks fire on one `ACCESS_EVAL`, emit `ENTITLEMENT_ESCALATION` before `LATERAL_GHOSTING` (emission order before `finding_id` sort).

## Post-replay audits (after all events)

Let `max_seq` be the maximum `seq` among **all decoded inheritance_journal events** in the slice (including rows later skipped as duplicate `event_id`). Use `event_seq` = `max_seq + 1` for every audit-only finding (`INHERITANCE_ASYMMETRY`, `OPEN_GHOST_PATH`, `SOVEREIGN_UNBOUND`). When the slice has no events, `max_seq` is `0` and audit findings use `event_seq` = `1`.

**INHERITANCE_ASYMMETRY** — For each `GRANT_INHERITANCE` edge where `grantor_coordinator` has privilege_tier **`vendor`** and `grantee_coordinator` has privilege_tier **`operational`** (vendor→operational only; not vendor→sovereign), if there is no reverse `GRANT_INHERITANCE` edge from that `grantee_coordinator` back to the same `grantor_coordinator`, emit one finding (`entity_id` = `grantee_coordinator`, `detail` = `grantor_coordinator`). At most one per directed vendor→operational pair.

**OPEN_GHOST_PATH** — Let `P` be a `sovereign` privilege_tier coordinator (the inbound edge’s `grantee_coordinator`). For each inbound `GRANT_INHERITANCE` edge from a `vendor` privilege_tier coordinator to `P`, if `governance:audit` is not in **P’s** `entitlement_bindings` (check the sovereign callee’s bindings, not the vendor caller’s), emit one finding (`entity_id` = `P`, `detail` = lexicographically first such vendor `coordinator_id`). At most one finding per sovereign coordinator.

**SOVEREIGN_UNBOUND** — For each `sovereign` privilege_tier coordinator `P`, if `governance:admin` is not in **P’s** `entitlement_bindings`, emit (`entity_id` = `P`, `detail` = **empty**). Run this pass **after** the `OPEN_GHOST_PATH` pass above so both findings on the same sovereign coordinator share one `finding_id` but appear in emission order: `OPEN_GHOST_PATH` first, then `SOVEREIGN_UNBOUND`.

## Coordinator delegation_poison_risk field

Allowed values only: `contained`, `elevated`, `critical`. Derive **only** from each coordinator’s `privilege_tier` when building output — never from findings, `entitlement_bindings`, or `business_unit`:

- `contained` — `privilege_tier` is `operational`
- `elevated` — `privilege_tier` is `vendor`
- `critical` — `privilege_tier` is `sovereign`

`SOVEREIGN_UNBOUND` and other findings do **not** change `delegation_poison_risk`.

## Finding kinds

Emit **only** the kinds listed in the table below. Do not invent other `kind` strings (for example, use `UNATTESTED_ACCESS` for operational callees without token validation — not `MISSING_CHECKPOINT` or similar).

`finding_id` = `{delegation_slice_id}::{entity_id}::{event_seq:04d}` where `event_seq` is the event’s `seq` for replay-time findings, or the audit `event_seq` (`max_seq + 1`) for post-replay findings.

| Kind | `entity_id` | When | `detail` |
|------|-------------|------|----------|
| `UNATTESTED_ACCESS` | `eval_target_id` | operational callee without token | empty |
| `DOMAIN_BLEED` | `eval_target_id` | cross-domain ACCESS_EVAL with edge | requestor_id |
| `RESURRECTED_ENTITLEMENT` | `coordinator_id` | REGISTER after RETIRE_COORDINATOR_SCOPE | empty |
| `ENTITLEMENT_ESCALATION` | `requestor_id` | propagated cap absent on caller | entitlement_key |
| `UNTRUSTED_INHERITANCE` | `eval_target_id` | no inheritance edge | requestor_id |
| `UNKNOWN_TARGET` | `eval_target_id` / `grantee_coordinator` | unknown callee | event kind |
| `UNKNOWN_COORDINATOR` | caller / bind target | unknown caller / BIND target | event kind |
| `DUPLICATE_COORDINATOR` | `coordinator_id` | second REGISTER_COORDINATOR | empty |
| `DUPLICATE_INHERITANCE` | `grantee_coordinator` | duplicate GRANT_INHERITANCE | grantor_coordinator |
| `LATERAL_GHOSTING` | **`provenance_requestor`** | non-empty `provenance_requestor` ≠ `requestor_id`, missing propagated claim on **caller** | entitlement_key |
| `RESTRICTED_TIER` | `requestor_id` | vendor→sovereign blocked by policy **or** by missing callee `governance:audit` when policy override disables the hard block | eval_target_id |
| `INHERITANCE_ASYMMETRY` | `grantee_coordinator` (operational) | missing reciprocal operational→vendor edge | vendor `grantor_coordinator` |
| `OPEN_GHOST_PATH` | sovereign `P` | sovereign lacks `governance:audit` with vendor inbound | vendor `coordinator_id` |
| `SOVEREIGN_UNBOUND` | sovereign `P` | sovereign lacks `governance:admin` | empty |

Sort `findings` by `finding_id` ascending **only**. Do **not** apply a secondary sort on `kind`, `detail`, or other fields. When two findings share the same `finding_id` (possible when post-replay audits emit both `OPEN_GHOST_PATH` and `SOVEREIGN_UNBOUND` for the same sovereign proxy at the same audit `event_seq`), keep the **emission order** from the audit passes above — `OPEN_GHOST_PATH` before `SOVEREIGN_UNBOUND`. `status` = `VALID` iff no findings.

Across all bundled delegation_slices together, the report must use every kind at least once.

## Build and allowed paths

Use `make build` and `make run` only. The Go binary must live at `/app/build/delegationintegrity` (`go build -o build/delegationintegrity`). Do not leave `/app/delegationintegrity` or other stray top-level binaries.

`cmd/delegationintegrity/main.go` must keep the exact identifiers `fixtureRoot`, `catalogPath`, and `outPath` with the absolute string literals required by `DELEGATION_INTEGRITY_SNAPSHOT_SCHEMA.md` (including `outPath := "/app/build/delegation_integrity_snapshot.json"` verbatim). Do not use shell substitution, backticks, or semicolon-wrapped shell commands on absolute `/app` paths.

## Report

Write `/app/build/delegation_integrity_snapshot.json` per `/app/provenance_charters/DELEGATION_INTEGRITY_SNAPSHOT_SCHEMA.md`. UTF-8 compact JSON, LF only, exactly one trailing newline; use `[]` never null. Identical `/app/delegation_federation_slices` bytes must produce byte-identical reports across consecutive `make run` invocations.
