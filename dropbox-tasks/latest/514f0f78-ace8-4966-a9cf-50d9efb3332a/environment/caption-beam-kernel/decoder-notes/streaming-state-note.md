# Streaming state note

A request names one of three stream operations: decode (`OP_DECODE` = 1) appends its frames to the named stream and may return a provisional verdict; finish (`OP_FINISH` = 2) appends its frames, returns the finalized verdict for the accumulated stream evidence, and then clears only that stream; reset (`OP_RESET` = 3) clears only the named stream and returns an empty successful verdict. Streaming state is keyed solely by stream id, so unrelated stream ids never share logits, vocabulary, bias progress, or finalization state. Empty chunks are legal and preserve the named stream. Any legal chunk partition of an utterance has the same finished collapsed tokens, ordered scores, spans, and confidence as one batch finish request. Expected rejection must not modify any stream state and must not affect the next request. Identical fresh-state requests produce identical response bytes.
