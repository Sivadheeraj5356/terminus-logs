# Stencil lowering cache drift

Our grid-operator compiler in `/app/environment` keeps a replay journal beside the build cache and a migration WAL under `/app/output/.cache/`. Incremental compiles have been drifting: spill totals change on repeated stage-two cache hits, migration leaves stale stage rows behind, WAL segments disagree with the journal epoch, replay generations diverge from the replay log, metrics rollups diverge from the live trace, and poisoned digest rows sometimes override a fresh recompute. Repair `/app/environment` so `node /app/environment/cli/driver.mjs compile --spec /app/environment/specs/operator.json --out /app/output` regenerates `/app/output/kernel.mjs`, `/app/output/pass.trace.json`, and `/app/output/metrics.json`. Static or manual writes to `/app/output` are not sufficient; hand-editing those outputs or bypassing the driver is not acceptable.

`node /app/environment/cli/driver.mjs cache-reset` marks a migration before the next compile. `node /app/environment/cli/driver.mjs status --trace /app/output/pass.trace.json` prints register estimates from an existing trace.

The operator spec at `/app/environment/specs/operator.json` defines a `packs` array; each pack entry must bind a grid fixture, tile shape, and spill budget. The `grid_fixture` field names a grid JSON file under `/app/environment/fixtures/grids/`. Packs are processed sequentially during each compile. `/app/docs/output-contract.md` documents trace and metrics schemas, peel spill formulas, digest projection rules, digest cache integrity, compile_epoch and replay-log semantics, migration WAL reconciliation, cache dependency rules, and replay behavior. Metrics include spill_total, max_scratch_bytes, lane_width_summary, compile_epoch, replay_generation, replay_entry_count, and a 64-character hex digest_chain.
