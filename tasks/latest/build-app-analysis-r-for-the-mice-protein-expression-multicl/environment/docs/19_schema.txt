metrics.json keys: accuracy, macro_f1, log_loss, selected_lambda, validation_log_loss, n_fit, n_validation, n_test, n_classes.
predictions.csv columns: row_id, actual, predicted, proba_c_cs_m, proba_c_cs_s, proba_c_sc_m, proba_c_sc_s, proba_t_cs_m, proba_t_cs_s, proba_t_sc_m, proba_t_sc_s, split_role.
class_report.csv columns: class, precision, recall, f1, support.
confusion_matrix.csv columns: actual, predicted, n.
missing_report.csv columns: feature, missing_fit, missing_validation, missing_test, imputation_value. For categorical features, imputation_value is the literal string missing.
validation_report.csv columns: lambda, validation_log_loss.
validation_report.csv records the supplied-validation losses from the full configured feature set and the closed-form ridge one-vs-rest softmax model.
stability_refit_predictions.csv columns: repeat_id, row_id, actual, predicted, proba_c_cs_m, proba_c_cs_s, proba_c_sc_m, proba_c_sc_s, proba_t_cs_m, proba_t_cs_s, proba_t_sc_m, proba_t_sc_s, split_role. The split_role value for every row in this file is stability_validation. For repeat_id 1, 2, 3, and 4, stability validation rows are original fit rows where row_id modulo 4 equals repeat_id minus 1; every other original fit row trains that repeat.
stability_refit_report.csv columns: repeat_id, n_fit, n_validation, selected_lambda, validation_log_loss, validation_macro_f1, mean_confidence.
robust_lambda_consensus_report.csv columns: lambda, supplied_validation_log_loss, stability_selection_count, total_selection_count, selection_rate, selected. It has one row per configured lambda and is sorted by total_selection_count descending, supplied_validation_log_loss ascending, then lambda ascending. The supplied-validation winner and four stability winners provide five votes; selection_rate is total_selection_count divided by 5, and only the first row has selected equal to 1. Its lambda drives the final model outputs.
The consensus winner is still fitted with the closed-form ridge normal-equation model on the original fit rows before producing final test artifacts.
feature_drop_refit_report.csv columns: feature, n_terms, validation_log_loss, validation_macro_f1, delta_log_loss, delta_macro_f1, rank. It has one row for every configured numeric feature. For each row, remove only that numeric design term, refit the consensus lambda on original fit rows, and score the unchanged supplied validation rows. The baseline is the full-feature consensus-lambda model scored on supplied validation rows. delta_log_loss is dropped-feature validation_log_loss minus the baseline validation_log_loss. delta_macro_f1 is dropped-feature validation_macro_f1 minus the baseline validation_macro_f1. Round the four metric columns to six decimals. Sort rows by delta_log_loss descending, delta_macro_f1 ascending, then feature ascending, and assign rank after sorting.
n_terms is the number of retained design-matrix terms after the feature drop, including the intercept, all remaining numeric terms, and every categorical indicator term learned from the fit rows.
protein_pair_drop_refit_report.csv columns: pair_id, feature_a, feature_b, n_terms, validation_log_loss, validation_macro_f1, delta_log_loss, delta_macro_f1, rank. Audit these pairs in order: pair_01 drops dyrk1a_n and itsn1_n; pair_02 drops bdnf_n and nr1_n; pair_03 drops nr2a_n and pakt_n; pair_04 drops pbraf_n and pcamkii_n; pair_05 drops pcreb_n and pelk_n; pair_06 drops perk_n and pjnk_n; pair_07 drops pkca_n and pmek_n; pair_08 drops pnr1_n and pnr2a_n. For each pair, remove both numeric design terms, refit the consensus lambda on original fit rows, and score the unchanged supplied validation rows. Use the same baseline, metric rounding, n_terms definition, and ranking rule as feature_drop_refit_report.csv, with pair_id as the final ascending tie-breaker.
boundary_refit_report.csv columns: audit_rank, row_id, actual, baseline_predicted, refit_predicted, removed_row_id, removed_label, nearest_distance, baseline_margin, refit_margin, probability_l1_shift, decision_changed. Select the ten test rows with the smallest difference between their largest and second-largest consensus probabilities, breaking ties by row_id ascending. For each row, find the nearest fit row in the fit-learned design space whose actual class is different from the baseline predicted class, breaking distance ties by row_id ascending. Remove that one fit row, relearn preprocessing on the reduced fit set, refit the consensus lambda without reselecting it, and rescore the audited test row. nearest_distance is the Euclidean distance in design columns excluding the intercept. probability_l1_shift is the sum of absolute per-class probability changes, and decision_changed is 1 only when the refit predicted label differs from the baseline predicted label.
paired_boundary_reselection_report.csv columns: audit_rank, row_id, actual, baseline_predicted, local_refit_predicted, conflict_removed_row_id, conflict_removed_label, support_removed_row_id, support_removed_label, conflict_distance, support_distance, baseline_margin, local_selected_lambda, local_validation_log_loss, local_margin, probability_l1_shift, decision_changed. Use the same ten audited test rows and ranking as boundary_refit_report.csv. In the original fit-learned design space excluding the intercept, find the nearest fit row whose actual class differs from the baseline predicted class and the nearest fit row whose actual class equals the baseline predicted class, breaking distance ties by row_id ascending in both searches. Remove both selected fit rows, relearn preprocessing on the reduced fit rows, transform the unchanged supplied validation rows with that reduced-fit preprocessing, fit every configured lambda on the reduced fit rows, and select the lambda with the lowest supplied-validation log loss, breaking ties by lambda ascending. Score the audited test row with that local selected lambda. conflict_distance and support_distance are the original fit-learned Euclidean distances. probability_l1_shift is the sum of absolute per-class probability changes from the consensus baseline probabilities, and decision_changed is 1 only when local_refit_predicted differs from baseline_predicted.
model_manifest.json keys: task_name, model_family, target_column, class_order, feature_columns, numeric_features, categorical_features, selected_lambda, split_source, preprocessing_source. model_family is exactly ridge_one_vs_rest_softmax, split_source is split_role, and preprocessing_source is fit_rows_only.
Probability columns are named proba_ plus the sanitized class label. Sanitizing class or level text means lowercase, replace every non-alphanumeric run with one underscore, trim leading and trailing underscores, use value if empty, and prefix x_ if the result starts with a digit. The required multiclass labels therefore serialize as proba_c_cs_m, proba_c_cs_s, proba_c_sc_m, proba_c_sc_s, proba_t_cs_m, proba_t_cs_s, proba_t_sc_m, and proba_t_sc_s. Metrics and manifest use selected_lambda and validation_log_loss exactly; aliases such as best_lambda or val_log_loss are not part of the contract.
missing_report.csv is wide format with one row per feature, not separate rows per split or missing token. Blanks, literal question marks, NA values, and nan style markers count as missing. Numeric imputation values are the fit-row means, and categorical imputation values are the literal string missing. confusion_matrix.csv is long format ordered by class_order with actual as the outer loop and predicted as the inner loop. Multiclass log loss clips probabilities before taking logs, and JSON numeric values should preserve enough precision for 1e-5 comparison.
