LayerFS capture format, revision 2

The input argument is a manifest no larger than 65536 bytes. It begins with the exact ASCII line LAYERS2 followed by LF. Each remaining nonempty line is exactly 64 lowercase SHA-256 hexadecimal digits, one space, a layer basename, and LF. A basename is one or more ASCII letters, digits, dot, underscore, or hyphen, but is not dot or dot-dot. Names are unique. There are 1 through 16 layers in base-to-top order. Every named file is in the manifest directory, is at most 8388608 bytes, and its raw bytes have the listed SHA-256 digest.

Each layer is an uncompressed POSIX ustar stream whose length is a multiple of 512. Every header has magic ustar followed by NUL and version 00. A string field is either full-width or NUL-terminated with only NUL padding. Numeric fields use zero through seven in ASCII with optional leading spaces and only spaces or NUL after the digits. An empty numeric field is zero. GNU base-256 numbers are invalid. Mode is at most 07777 and uid and gid are at most 4294967295. Checksum is the unsigned sum of all 512 header bytes with the checksum field treated as eight spaces. File-data padding bytes are zero.

Two consecutive zero blocks terminate a layer and every remaining byte is zero. A layer contains at most 4096 real members. Supported real type flags are NUL or 0 for regular files, 1 for hard links, 2 for symbolic links, and 5 for directories. Directories and links have size zero. Other types are invalid.

Type x is a local PAX header. Its payload is consecutive decimal-length records of the exact form LENGTH SPACE KEY EQUALS VALUE LF. LENGTH counts the entire record, has no leading zero, and must end on a record boundary. Consecutive local headers merge and the last occurrence of a key wins. Recognized keys are path, linkpath, size, uid, and gid. Unknown keys are ignored. Decimal values contain digits only. Local state applies to the next real member and then clears.

Type L supplies a GNU long path and type K supplies a GNU long link. Each payload ends in exactly one NUL and has no earlier NUL. Consecutive records replace the same pending value. For a real member, effective path precedence is local PAX path, then GNU long path, then ustar prefix joined to name. Effective link precedence is local PAX linkpath, then GNU long link, then the ustar link field. A PAX size controls both the real payload extent and its padding even when the ustar size differs. Pending extension state at end of archive is invalid.

Every effective path and link is at most 4096 bytes and contains only printable ASCII bytes 20 through 7e. A path is nonempty. A link may be empty except for a hard link. Any malformed manifest, digest, tar header, checksum, extent, padding, extension, numeric value, unsupported type, or missing layer makes the complete invocation fail.
