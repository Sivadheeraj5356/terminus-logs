## Goal

Harden the Flask media metadata service in `/app` without changing the repository root layout. The finished project is an offline build-and-report pipeline: it must not download anything, it must not trust a system `yq`, and `make report PORT=<port>` must generate `build/hardened-report.json` from the current fixtures, manifest, and live local API responses rather than from hard-coded values.

## Flask and OpenAPI hardening

Run Flask only on localhost with debug disabled. Allow CORS only for `https://media.example.test`, return `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`, and never expose absolute fixture paths. `/health` stays public and returns `status: ok` and `debug: false`. `/media` must require `X-API-Key: media-local-build-token`; missing or wrong keys return HTTP 401. Authorized `/media` returns only policy-accepted media as `{count, items}`, where every item has exactly `name`, `format`, `width`, `height`, and `mode`, sorted by filename. Update `openapi.yaml` to describe the hardened API, use a server URL starting with `http://127.0.0.1`, bump the old `0.1.0` version, and define/apply an API-key security scheme named exactly `ApiKeyAuth`.

## Offline yq bootstrap and Perl report path

Expose `make bootstrap-yq`, `make report PORT=<port>`, and `make clean`. The Makefile must visibly use the literal project-local path `.tools/yq`, and must not discover `yq` from `PATH`. `bootstrap-yq` must be implemented through `scripts/analyze.pl`, use Perl `Digest::SHA`, verify the bundled artifact declared in `config/media.yaml` at `build.yq.source` as `vendor/yq_linux_amd64`, and install it as `.tools/yq`; it must fail nonzero with a checksum/SHA error if the artifact is tampered. The pinned yq is `v4.53.3` with SHA-256 `84be51c2bf82b1eae16c54fab3f5d9aa887f5fb30d90990217e9031bf42f9f56`.

`make report` must be self-contained: bootstrap yq, start Flask on the requested port, query `/health` and `/media`, stop Flask, write the report, and exit nonzero after writing the report whenever any manifest or policy validation fails. `make clean` must remove generated `build` and `.tools` outputs so each verifier scenario starts from a clean state. Keep `scripts/analyze.pl` as Perl; it must use `.tools/yq` for YAML inspection, resolve `jq` from `PATH` at runtime with field-specific filters such as `.status`, `.debug`, `.count`, `.items`, or `.items[].format`, and query the local API with `HTTP::Tiny` or `curl`. Do not hardcode `/usr/bin/jq`, do not replace the analyzer with Python, and do not use only a bare `jq '.'` pass-through.

## Manifest policy engine

`config/media.yaml` must contain `media.policy` and `media.manifest`. Each manifest entry contains `name`, `sha256`, `format`, `width`, `height`, `mode`, and `signature`. The signature is lowercase SHA-256 of exactly this UTF-8 string with the trailing newline: `media-manifest-v1\n{name}\n{sha256}\n{format}\n{width}\n{height}\n{mode}\n`. The policy uses `max_pixels: 24`, `serve_only_manifest_valid: true`, and reason weights for `missing_manifest`, `sha256`, `signature`, `format`, `width`, `height`, `mode`, `pixels`, and `name_collision`.

For every current fixture with an allowed image extension, collect rejection reasons in this order: `missing_manifest`, `sha256`, `signature`, `format`, `width`, `height`, `mode`, `pixels`, `name_collision`. `pixels` means `width * height > media.policy.max_pixels`. `name_collision` means two or more current fixture filenames have the same collision id, computed from the filename stem by lowercasing it, replacing each run of non-alphanumeric characters with `-`, and trimming leading/trailing `-`. A file is policy-accepted only when its reason list is empty; `/media` must serve only accepted files sorted by filename. List fields in the report must be deterministic: `expected_names`, `missing_files`, `unexpected_files`, and `accepted_names` are alphabetically sorted; `mismatches` and `quarantined` are sorted by filename; mismatch fields and quarantine reasons use the field/reason orders above.

## Report contract

`build/hardened-report.json` contains exactly seven top-level objects: `security`, `yq`, `tools`, `config`, `api`, `manifest`, and `policy`. The nested keys are exact and no extras are allowed: `security={passed}`; `yq={version,sha256,path,version_output}` with `path` resolving to `.tools/yq`; `tools={yq_used,jq_used}` with both boolean true when the commands were actually invoked; `config={debug,host,cors_wildcard,leaks_absolute_paths}`; `api={health_status,debug,auth_required,unauthorized_status,media_count,absolute_path_leaks,formats,catalog_sha256}`; `manifest={declared_count,expected_names,missing_files,unexpected_files,mismatches,content_sha256,passed}`; `policy={passed,accepted_names,quarantined,risk_score,catalog_merkle_root}`. `manifest.content_sha256` is not a single hash: it is a JSON object mapping every current allowed-extension fixture filename to that file's actual 64-hex SHA-256 digest, including accepted, quarantined, and unexpected files, encoded deterministically by filename. `security.passed` is true only when the hardening checks pass, `manifest.passed` is true, `policy.passed` is true, the API count matches the accepted policy set, and no path/debug/CORS/auth checks fail.

`api.formats` preserves one format entry per accepted item in API response order, including duplicates. For `api.catalog_sha256`, first build a compact JSON array from accepted `/media.items` in response order, but canonicalize each object key order exactly as `name`, `format`, `width`, `height`, `mode`, then SHA-256 that JSON with no spaces. Each manifest mismatch is `{name, fields}`, where fields are sorted by `sha256`, `signature`, `format`, `width`, `height`, `mode`. Each quarantined entry is `{name, reasons}` with reasons in rejection order. `risk_score` is the sum of configured weights for every quarantine reason on every quarantined file. For accepted items, compute `catalog_merkle_root` from leaves `sha256("media-leaf-v2\n{name}\n{format}\n{width}\n{height}\n{mode}\n{content_sha256}\n")`; repeatedly hash adjacent pairs as `sha256("media-node-v2\n{left}\n{right}\n")`, duplicating the final odd leaf at each level. If there are no accepted items, use `sha256("media-empty-v2\n")`.
