The TypeScript project in `/app` implements a URI Template expander that has to satisfy the Level 4 template-expansion rules of RFC 6570. It consumes a single JSON object on standard input, shaped as `{"template": <string>, "variables": <object>}`, in which `variables` binds each name to a string, a list, or an associative object; it emits the fully expanded string on standard output, closed by one newline. A template that is not syntactically valid under RFC 6570 must not be expanded at all — the program prints the token `ERROR` and exits with a non-zero status. Compiling with `make` (a `tsc` build) yields the launcher `/app/uritmpl`, and that executable is what the standard uritemplate-test conformance vectors are run against.

The expander must cover every RFC 6570 operator: the operator-less default plus `+`, `#`, `.`, `/`, `;`, `?`, and `&`, along with the prefix modifier `:N` and the explode modifier `*`. The `:N` prefix retains a string value's first `N` Unicode characters — the count is over characters, not bytes — before that portion is encoded, and it applies only to string values. Explode expands a list into repeated segments and expands an associative object into `name=value` pairs, so that exploding an object inside a query expansion emits separate `name=value` query parameters while the same object left unexploded flattens into one comma-joined run of alternating keys and values. An associative object's members are always emitted in the order the keys appear in the input JSON object, in both the exploded and the flattened form. For the named operators (`;`, `?`, `&`), an exploded list repeats the variable's name once per element, meaning a value of `["red","green","blue"]` produces `;list=red;list=green;list=blue` rather than a list of bare values. Percent-encoding depends on the operator: only `+` and `#` preserve reserved characters and any already-existing percent-encoded triplet, while all remaining operators percent-encode every character outside the unreserved set. A variable that is undefined adds nothing, an empty list is handled exactly like an undefined variable, and a variable defined as the empty string still yields its name — plus the `=` marker in the query and continuation forms. Literal characters between substitutions are reproduced exactly as written.

Scoring is exact against the published uritemplate-test suite: each expansion must equal one of the suite's accepted strings (some entries permit more than one ordering), and every template the suite records as a failure must be answered with `ERROR`. Those failures include expressions left unterminated or nested incorrectly, operators that are unrecognised or out of position, variable names holding characters outside the RFC 6570 name set — so any name with a space, a hyphen, or a tilde is malformed, because a valid name draws only on alphanumerics, underscore, dot, and percent-encoded triplets — and any prefix modifier placed on a list or associative value.
