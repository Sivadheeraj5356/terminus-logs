An internal DNS deployment pipeline needs `/app/dnssec-audit` to decide whether a child-zone delegation can be admitted without contacting the network. Complete the Go implementation in `/app` so the command reads one JSON bundle from the file named by its optional argument, or from standard input when no argument is supplied, and writes exactly one JSON object containing `admit` and `reasons`. The detailed bundle schema and the canonical DNSSEC subset used by this pipeline are documented in `/app/POLICY.md`; that file is the behavioral authority for this task.

Admission requires a supported parent DS to authenticate an eligible child DNSKEY and every supplied RRset to have a currently valid signature from an authenticated zone key. Treat DNS names, DNSKEY key tags, DS digests, canonical RRset ordering, signer and wildcard scope, algorithm policy, and signature time windows exactly as the policy describes. A successful result is `{"admit":true,"reasons":[]}`. A rejected bundle must set `admit` to false and return the distinct applicable reason codes in lexicographic order; malformed input must be rejected rather than causing a panic. Keep the implementation self-contained in Go and preserve both file-argument and stdin operation.
