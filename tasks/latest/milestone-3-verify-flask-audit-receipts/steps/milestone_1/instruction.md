You are building a Python toolchain that signs software release manifests with Ed25519, submits the signatures to a transparency-log API, and verifies the append-only audit receipts it returns. The work is split into six milestones; all run in the same /app container, so files you create persist between them. Build everything under /app/transparency/, place generated artifacts under /app/out/, and place keys under /app/keys/.

This first milestone canonicalizes release manifests. Before a manifest can be signed reproducibly, it must be serialized to a canonical form so that semantically identical manifests always hash to the same value. Implement the canonicalization logic in a module at exactly /app/transparency/canonical.py, and a CLI at exactly /app/transparency/cli.py that imports it. Place all modules directly in /app/transparency/ as flat top-level modules (no package __init__.py); they are imported by name with /app/transparency on sys.path (for example, from canonical import ...), so do not use package-relative imports such as from .canonical import.

The CLI must support the invocation python3 /app/transparency/cli.py canonicalize <manifest.json> --out <dir>, which writes two files into <dir>. The first is manifest.canonical.json, the RFC 8785 (JCS) canonical UTF-8 serialization of the manifest. Implement the JSON Canonicalization Scheme yourself rather than relying on a stock pretty-printer. Object keys are sorted ascending by Unicode code point at every level; compact separators (a comma and a colon) are used with no insignificant whitespace; strings use minimal JSON escaping (only the double-quote, the backslash, and the control characters U+0000 through U+001F, using the short escapes \b \t \n \f \r where defined and \u00xx otherwise) while all other characters, including non-ASCII, are emitted literally as UTF-8 (no \uXXXX for ordinary characters); and numbers use the ECMAScript Number::toString algorithm (RFC 8785 section 3.2.2 / ECMA-262 section 6.1.6.1.20), the shortest decimal string that round-trips to the IEEE-754 double. This is not Python's repr or json output: an integer-valued float drops the fraction (100.0 becomes 100), negative zero becomes 0, and small magnitudes use a bare exponent with no leading zero (1e-7, not 1e-07). Letting E be the base-10 exponent in scientific notation (mantissa in the half-open interval from 1 to 10), the value is written positionally when E is between -6 and 20 inclusive and switches to exponential form only when E is at most -7 or at least 21. So 1e20 becomes 100000000000000000000 but 1e21 becomes 1e+21; likewise 1e-6 becomes 0.000001 but 1e-7 becomes 1e-7. There is no trailing newline. The second file is manifest.sha256, the lowercase hex SHA-256 digest of the canonical bytes followed by a newline.

The canonicalization must be deterministic: two manifests that differ only in key order or whitespace must produce byte-identical output and the same digest, matching the JCS reference byte-for-byte. Demonstrate the tool by canonicalizing /app/data/manifest.json into /app/out/.
