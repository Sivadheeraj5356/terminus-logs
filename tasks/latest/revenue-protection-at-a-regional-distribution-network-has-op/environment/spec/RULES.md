# Audit rules

The complete rule set for the five `tariff` subcommands. `/app/spec/FORMATS.md` gives the
layouts and schemas; this file gives what every field means and how it is computed. All five
subcommands build on each other and are graded byte-for-byte against the reference on unseen
corpora.

INTAKE. Walk the segment files under DIR/exports. Each record is fixed-layout but variable-length: its serial-length byte tells you how far the next record starts, so walk the records off that length byte rather than assuming a fixed stride. Verify every record against its stored checksum, recomputing the checksum over the record's own bytes with the checksum field zeroed, exactly as the format sheet encodes it, and with the two result bytes nibble-swapped. A record whose recomputed checksum does not match the stored one is tampered evidence: none of its fields are trusted, it yields no read, and it is reported as a tamper finding. A segment's body may end before the header's record count is exhausted, which is a truncated transmission: a record that would run past the end of the file is lost, and so is every record after it. The header count is authoritative for what was transmitted, so the number of records lost is that count less the records fully present in the file, and a segment that lost any is reported as one spoliation finding. Record ordinals reported in findings are 0-based positions among the records fully present in that file, tampered ones included.

An intact record resolves to an account and to a delivery point. Telemetry records resolve to an account by their account code; estimate and manual records carry an account code of 0 and resolve by their meter serial instead. Every record resolves to a delivery point by its point code. A record that resolves to no registered account, or to no registered point, produces no read at all, though it is still counted as a read for intake statistics. Records that resolve to both become the reads the rest of the audit works from. A resolved record whose claimed tariff class, the one in the flag byte, differs from the registry class of the account it resolved to is a class understatement and is reported as a misdeclare finding, though the read itself still stands; a record that resolves to no registered account is never a misdeclare whatever class it claims.

Intake statistics are kept per reporting utility, the one named by the record's reporting-utility code, which need not own the point: reads counts the records fully present with a valid checksum including the ones that resolve to nothing, flagged counts those of them carrying the field-inspection marker, tamper counts its tampered records, lost counts its records lost to truncation, and misdeclare counts its class understatements. A tamper or spoliation finding is attributed to the utility the segment reports for, which is the reporting utility of its first intact record. Findings are priced at the evidence's face value: a tamper carries penalty_cents, a spoliation carries lost times penalty_cents, and a misdeclare carries the registry standing charge for the point's category at the account's registry class less the same for the claimed class, floored at zero and zero when the claimed class is outside 1 through 4.

Intake writes three files. The file evidence.jsonl holds one line per resolved read, ordered by segment file name then record ordinal, where utility is the reporting utility and class the claimed class. The file findings.jsonl holds one line per finding, grouped by kind in the order tamper, spoliation, misdeclare, and within a kind ordered by segment file name then record ordinal. The file intake.json is a single line where segments counts the segment files, records the records fully present across all of them, reads and tampered and lost total the corresponding per-utility columns, and unresolved counts the valid reads that resolved to no registered account or point; findings is the number of lines in findings.jsonl and findings_by_kind breaks that census down by kind carrying every one of the three kinds as a key even at zero; utilities holds one entry per registry utility whether or not it reported anything, where leakage_cents sums the cents of that utility's misdeclare findings and exposure_cents is leakage_cents plus penalty_cents times the sum of tamper and lost, and the entries are ranked by exposure_cents descending with ties broken by utility id ascending. The fields evidence_digest and findings_digest are FNV-1a folds over the exact bytes of evidence.jsonl and findings.jsonl respectively, as defined at the end of this document.

DRAWS. Several reads can describe one event: the point's own operator reports it, a neighbouring utility reports it too, an inspector keys it in by hand. Group the resolved reads per delivery point and resolved account and walk each group in ts order, ties broken by source in the order telemetry then estimate then manual, then by reporting utility id ascending. A read joins the draw currently being assembled while it falls within 5 seconds of that draw's FIRST read, measured against the first read and not the most recent one so a slow trickle of reads does not chain into one endless draw; otherwise it opens a new draw. Each draw takes its fields from one surviving read, chosen by source with telemetry beating estimate beating manual, then by reporter so that a read from the utility that owns the point's feeder beats a read from anyone else, then by earlier ts, then by smaller reporting utility id. The draw's ts and kwh are the survivor's, reads counts every read folded into it including the survivor, and its id is the account, the point and the surviving ts joined by colons. The draw's operator is the utility owning the point's feeder, its home is the account's home utility which is the prefix of the account id before the first hyphen, and its class is the account's registry class, never a claimed one. The register order of the draws, which is the order they are written in and the order both detectors below walk them in, is ts then delivery point id then account id.

A draw that repeats an earlier draw of the same point and account pair strictly sooner than replay_window_sec after it is a replayed meter capture. The comparison is always against the most recent draw of that pair that was NOT itself flagged as a replay, so a burst of replays is all measured against the same honest draw rather than walking itself forward, and a gap of exactly replay_window_sec is legitimate. A flagged draw is excluded from settlement and reported as a replay finding whose draw is the flagged draw's id, prior the id of the draw it was measured against, and gap_sec the seconds between the two.

Walk each account's draws in register order, skipping the ones already flagged as replays. A draw at a different delivery point, strictly sooner than that point pair's min_sec in the registry transfer table after the account's last accepted draw, cannot physically be one customer's load: it is a cloned credential or a tapped service head. The later draw is flagged, the accepted draw stands, and the account's walk continues from the accepted draw so the next comparison is still against the honest draw and not the clone, while a gap exactly equal to min_sec is a legitimate journey. Flagged draws are excluded from settlement and reported as bypass findings whose draw is the flagged draw's id, conflict the id of the accepted draw it was measured against, gap_sec the seconds between the two, and bound_sec that point pair's min_sec. An account with even one bypass against it is compromised: from the instant of its first flagged bypass onward, every draw of that account that is not itself flagged as a replay or a bypass is a suspect and is excluded from settlement wholesale, while draws of that account before the first bypass stand. Every compromised account gets exactly one quarantine finding carrying from_ts the ts of its first bypass, draws the number of suspect draws it swept up, and their summed value, and it gets that finding even when no suspect draws follow. A draw already flagged as a replay is never also flagged as a bypass.

Draw findings stay priced at the evidence's face value, which does not move with any settlement: the energy at stake priced at the registry opening band rate, which is the rate of the registry bands entry at index 0, plus the registry standing charge for the draw's point category at the account's registry class. A replay and a bypass each carry their flagged draw's face value; a quarantine carries the summed face values of its suspect draws. Draws writes three files. The file draws.jsonl holds one line per draw in register order, each with the status the detectors left on it, one of ok, replay, bypass or suspect. The file findings.jsonl now holds the six kinds raised so far grouped by kind in the order tamper, spoliation, misdeclare, replay, bypass, quarantine, where within a kind tamper and spoliation and misdeclare order by segment file name then record ordinal as before, replay and bypass order by their flagged draw's register order, and quarantine orders by account id ascending. The file draws.json is a single line where draws counts the draws, excluded those whose status is not ok, by_status counts each of the four statuses, and compromised_accounts lists ascending the account of every quarantine finding; findings counts the lines of findings.jsonl and findings_by_kind breaks it down over the six kinds each present as a key even at zero; and draws_digest and findings_digest fold every byte of draws.jsonl and findings.jsonl. The intake command must keep working.

SETTLE. Now price the leakage and let the case's own findings condemn the circuits the fraud came off. Every account carries an allowance_kwh, but an account is only ever supplied through its chain, which is itself, its parent, its parent's parent, up to the supply point at the root whose parent is null, so its own grant is not what it can draw. An account's residual is its allowance less everything already admitted anywhere in its subtree, itself included, since a parent is drained by its children's draws as surely as by its own. The headroom of a draw is the minimum residual along its account's whole chain, floored at zero, the tightest link wherever it sits. A draw is admitted at the lesser of the energy it asked for and its headroom, and admitting it depletes every account in the chain by the admitted amount, the drawing account and every ancestor up to the supply point alike. So a sub-account's draw eats into its parent's room and its supply point's room, a sibling's draw shrinks what is left for it, and no account's bill can be worked out on its own.

Bands, standing charges, shed parameters and exemptions are policy, and the regulator's circular book decides which of them is in force while the registry's own tables apply only where nothing is in force. So wherever settlement prices something, the bands, the standing charge and the shed parameters governing a draw are the operative ones the circular book leaves in force at the ts of that draw, resolved exactly as the circular rules below set out, and the registry table is the fallback the resolution lands on when no directive is in force on that subject. The one figure that is always registry-only is a finding's face value.

The operative bands are cumulative kWh bands: a band applies from its from_kwh up to the next band's from_kwh, the last band runs to infinity, and the energy charge for a draw is the sum over bands of the draw's admitted kWh falling inside that band times the band's rate_cents. The running cumulative those bands are indexed against is the SUPPLY POINT's, not the drawing account's. Every account in a supply point's subtree draws against the one cumulative total admitted at that supply point, so a draw is priced in whatever band the supply point has already been pushed into by the sub-accounts settled before it, whether siblings, cousins or ancestors, and a small sub-account can find itself paying the top band because the rest of the chain has already eaten the cheap ones. A draw takes its supply point's cumulative from start to start plus admitted, and only an admitted draw advances it. On top of the energy charge sits the standing charge, the operative standing for the delivery point's category at the account's registry class and never a claimed one; the register row's standing_cents is exactly that charge as it stands before any peak or shed multiplier is applied, and the toll is the energy charge plus the standing charge. A draw is peak when its local time of day at the operating utility's offset, the utility owning the point's feeder, falls in the interval from 07:00 up to but not including 10:00 or from 17:00 up to but not including 20:00, where local time of day is (ts plus utc_offset_min times 60) mod 86400 using a floored mod so a negative offset wraps rather than going negative; a peak draw's toll becomes the floor of toll times 5 divided by 4.

Each supply point carries a rolling load and a regime flag, initially normal. Its rolling load is the total admitted energy of the last window_draws draws settled at that supply point, each counted double if it rated in shed, and an excluded draw occupies a slot in that window while contributing zero so exclusions dilute the load. The shed parameters governing a supply point are the operative ones at the settling draw's ts, the registry's until a circular says otherwise. When a draw at a supply point is about to settle, three things happen in order. First, if the supply point is in shed and its rolling load is strictly below the operative exit_kwh it returns to normal, and shedding ends only through this test since the load merely falling under enter_kwh never ends it. Second, the draw rates and is charged under the regime as it now stands, and a draw settling while the supply point is in shed has its toll multiplied to the floor of toll times 3 divided by 2 on top of any peak surcharge, unless an in-force exempt directive names its account in which case it takes no shed surcharge and does not count double toward the load. Third, if the draw is not excluded its admitted energy joins the rolling load, and if the supply point is normal and the load now reaches the operative enter_kwh or more it enters shed starting with the next draw, so the draw that crossed the threshold itself rated normal. The regime is evaluated only when a draw settles, and a quiet supply point keeps its last state until its next draw.

Draws settle one at a time and which one settles next is not fixed in advance: the next draw to settle is the one among those not yet settled whose headroom is smallest at that moment, ties broken by earlier ts then delivery point id ascending then account id ascending. Because every admitted draw depletes a whole chain and therefore shrinks the headroom of every draw hanging off that chain, the key must be re-derived after every single settlement; an account that starts roomy can be overtaken by one whose chain has just been drained, and a draw with a late timestamp can settle before a draw with an early one, so a solver that sorts the draws once is settling a different register. An excluded draw, one whose status is replay, bypass, suspect, voided or severed, still takes its slot in the settlement order and still rates: it is admitted on paper up to the headroom standing at its slot and priced under the bands and regime in force at that slot so it carries a real toll_cents, but it is charged 0, depletes no allowance, does not advance any supply point's cumulative, and contributes zero energy to the rolling load while still occupying a window slot. When more than one exclusion applies to a draw, the status reported is the first of replay, bypass, suspect, voided, severed that does. The register must equal what a full settlement run with every excluded draw contributing nothing from the very start would produce: exclusions give chain headroom back, move band crossings, move shed crossings and re-order the settlement itself, so settling everything forward and then zeroing out the rows that turn out to have been excluded does not reach the stable result, and neither does a single corrective re-pass over a timeline the first pass already fixed.

Which bands, standing charges, shed parameters and exemptions are in force at any instant comes from the regulator's circulars. The operative content of a circular is only what stands between its DIRECTIVES line and its END DIRECTIVES line; the narrative paragraphs routinely quote figures, account ids and other circulars and none of that has any force. The effective window is half-open from start up to but not including end, and without a TO end clause it is open-ended. A circular is superseded when any circular, itself superseded or not, names its ref in a SUPERSEDES line with the authority to do so: the regulator may supersede any circular, a utility may supersede only circulars it issued itself, and a SUPERSEDES entry made without that authority is disregarded entirely. Supersession once published stands, so a rescission is not undone when the rescinding circular is itself later superseded, a superseded circular's directives are void for all time, and unknown refs in a SUPERSEDES line are ignored. A directive is in force at time t when its circular is not superseded and t lies inside its effective window. When more than one directive is in force on the same subject at the same instant, the operative one is chosen in order by these tests: a supply-point-specific BANDS schedule beats an ALL schedule, then a regulator circular beats a utility circular, then later effective start beats earlier, then later issued beats earlier, and finally the greater ref in byte order wins; when nothing is in force the registry value applies. An account is exempt at t when any live exempt directive naming it is in force at t. Every directive is applied by the ts of the draw being settled, never by the circular's issued date and never by when the settlement happens to reach it.

Every dispute ruling cites a circular as its legal basis. An upheld ruling on a draw the case knows is well-founded only when its basis circular is live, not superseded, and in force at the draw's ts; a well-founded upheld ruling voids its draw no matter when it was ruled, so the draw keeps its rated toll but is excluded from settlement with status voided and everything the stable baseline requires follows. An upheld ruling whose basis fails that test is itself the fraud, an attempt to erase a legitimate charge: the charge stands and the filing is reported as a void_fraud finding attributed to the filing utility, with cause unknown when no such circular exists, else superseded, else expired, in that order of precedence. Rejected rulings, and rulings naming a draw id the case does not know, change nothing.

A feeder is condemned once the number of draws at its delivery points that are excluded on their own evidence, meaning replay, bypass, suspect or voided, reaches condemn_threshold, and the inspectors lock the circuit out. A severed draw is a consequence of a condemnation, never evidence for one, and never counts toward any threshold, while a retroactive void counts on its feeder's tally like any other own-evidence exclusion so a dispute upheld today can be what locks a circuit out. The lockout then propagates through the supply chain to a fixpoint: apply three rules over and over until the condemned set stops growing, where an account that has at least one draw and every one of whose draws sits at a delivery point on a condemned feeder is condemned, a condemned account condemns its entire descendant subtree wherever those sub-accounts are metered, and an account every one of whose sub-accounts is condemned is itself condemned however clean its own metering. Every draw of a condemned account is then severed wherever it was metered, excluded from settlement exactly like a voided draw, so an account with nothing whatever wrong with it metered on a circuit nobody condemned loses its supply because of what the accounts around it in the chain did. A single pass of the three rules does not reach the fixpoint and each fresh round of severances can drag another level of the chain down with it, and every condemned feeder is reported as one condemnation finding.

Settlement findings keep face value as before, unchanged by the settlement: the energy at stake at the registry opening band rate plus the registry standing charge for the draw's point category at the account's registry class. A condemnation carries the summed face value of the draws severed at that feeder. The one finding priced off the settlement is void_fraud, which carries the charged_cents of the draw it tried to erase.

Settle writes three files. The file register.jsonl is the settled register, one line per draw in register order which is ts then delivery point id then account id, where root is the account's supply point, peak and shed the flags the draw rated under, admitted the kWh the chain let through, toll_cents the rated toll and charged_cents what was actually billed which is 0 on every excluded draw. The file findings.jsonl holds all eight kinds grouped by kind in the order tamper, spoliation, misdeclare, replay, bypass, quarantine, void_fraud, condemnation, where within a kind tamper and spoliation and misdeclare order by segment file name and record ordinal, replay and bypass by their flagged draw's register order, quarantine by account id, void_fraud by dispute id, and condemnation by feeder id; a condemnation's excluded counts every draw at that feeder whose status is not ok and severed those whose status is severed. The file summary.json is the closed case on one line: in case, draws counts the register lines and excluded those not ok, reads and tampered and lost total the exposure columns, findings counts findings.jsonl and findings_by_kind breaks it down over all eight kinds each present as a key even at zero, compromised_accounts and condemned_feeders and severed_accounts list ascending the quarantined accounts and the condemned feeders and every account the cascade condemned, charged_cents totals the register, leakage_cents and exposure_cents total the exposure columns, and top_utility names the utility at the head of the exposure ranking or the empty string when there are none. The exposure field holds one entry per registry utility, where tamper, lost, misdeclare and flagged belong to the reporting utility, replay, bypass, suspect and severed to the account's home utility, void_fraud to the filing utility, and condemned feeders to the utility that owns the feeder; leakage_cents sums the cents of that utility's misdeclare, replay, bypass, quarantine, void_fraud and condemnation findings, exposure_cents is leakage_cents plus penalty_cents times the sum of tamper and lost, and entries are ranked by exposure_cents descending with ties by utility id ascending. The supply field holds one entry per supply point that settled at least one ok draw, ordered by supply point id ascending, where accounts counts the distinct accounts that drew under it, draws every register row under it including excluded rows, admitted_kwh and charged_cents sum its ok rows, shed_draws counts its rows that rated in shed, and final_headroom is the supply point's own allowance_kwh less admitted_kwh floored at zero. The three digests register_digest, audit_digest and findings_digest fold bytes as defined below; register_digest folds register.jsonl in file order and findings_digest folds findings.jsonl in file order, while audit_digest folds the same register lines each with its newline after re-sorting the rows by account id then ts then delivery point id all ascending, so on a corpus with real traffic the two register digests differ. The intake and draws commands must keep working.

INGEST. The command tariff ingest --data DIR --db PATH runs the full audit and writes the case file into the SQLite database at PATH, creating the register and findings tables to the format sheet's schema if they are missing. Store one register row per settled register line carrying exactly the values the register file reports for that draw, with the peak and shed flags stored as the integer 1 or 0. Store one findings row per finding, whose seq is the finding's 0-based position in the findings emission order, the same grouping by kind and the same order within a kind that findings.jsonl uses, whose kind is the finding's kind, and whose body is that finding's exact JSON line byte for byte as findings.jsonl carries it without the trailing newline. Re-running ingest against the same database must refresh the case file and not accumulate a second copy, so after any number of runs the tables hold exactly one row per register line and one per finding. The settlement the database carries is the same stable settlement the register file reports and nothing about it changes because it is being written to a database. The intake, draws and settle commands must keep working.

SERVE. The command tariff serve --db PATH --port N serves the case file written by ingest over HTTP on 127.0.0.1 at the given port. A GET on /register responds 200 with a JSON object holding exactly two keys, register and count, where register is the list of register objects with the same fields in the same order as a register.jsonl line, in register order which is ts then delivery point id then account id, and count is how many objects that list actually holds; the key is register and not rows or draws. A GET on /register/ID responds 200 with the single bare register object for that draw id, not wrapped, and 404 with a JSON object body for an id the case does not know. A GET on /findings responds 200 with a JSON object holding exactly two keys, findings and count, the finding objects in the emission order findings.jsonl uses and how many that list holds. Both collections filter. A GET on /register accepts an optional min_charge query parameter and then keeps only the rows whose charged_cents is at least that value, and an optional status parameter and then keeps only the rows carrying that status, and given both keeps only the rows that pass both as a conjunction. A GET on /findings accepts an optional kind parameter and then keeps only the findings of that kind. In every filtered response the shape never changes, the surviving rows stay in the same order, and count always matches the list actually returned. The service reads what ingest wrote so every payload carries the same stable settlement the register file reports, and all earlier commands must keep working.

DIGESTS. Every digest is an FNV-1a fold over 32 bits: start the hash at 0x811c9dc5 and for each byte XOR the byte into the hash then multiply by 0x01000193 modulo 2 to the 32nd power, rendering the result as 8 lowercase hex digits. Each digest folds every byte of the file it names, in file order, newlines included, and over an empty file the fold is the bare basis 811c9dc5.
