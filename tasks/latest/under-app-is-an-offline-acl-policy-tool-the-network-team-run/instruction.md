Under /app is an offline ACL policy tool the network team runs before pushing a firewall change. It's a Go module for an `acl` binary with two JSON-printing subcommands, and neither is finished. `acl evaluate --rules <path> --flows <path>` walks the observed flows and decides allow or deny for each, recording every log rule crossed before the terminal rule, plus a summary. `acl lint --rules <path> [--flows <path>]` audits the ruleset itself. Sample rulesets and flows live in `/app/testdata`.

Rules are consulted by priority, not file order, and both subcommands must agree on that order. evaluate reports each decision with a `matched` id (the sentinel `default-deny` when nothing matches) and a `logged` list. lint has to surface the load-time problems (`bad_cidr`, `bad_port`, `bad_action`, `bad_proto`, `bad_direction`, `bad_id`, `dup_id`, `bad_priority`, and the informational `normalized`) with a `by_reason` tally, plus the analysis findings `shadowed`, `redundant`, `unreachable`, and a summary that partitions the loaded rules.

The contract is the five docs in /app/docs: overview.md, ruleset-format.md, cidr-math.md, evaluation.md, report-schema.md. Do the address math with integers, keep `--rules` overridable, and match the schema exactly: decision strings, the sentinel, canonical CIDR text, exact key sets, integer counts, index-sorted arrays. Get it right against /app/docs.
