# QCL emit contract

## Output path

`/app/output/qcl_emit.json` is regenerated by `ruby /app/environment/qcl/drive_qcl.rb --matrix-all`.

## Calibration profile ids

The built-in calibration profiles are exactly `fp16_baseline`, `int8_strict`, and `mixed_edge`. These are mode ids, not case ids. The driver emits every stock case id under those three built-in profiles. Additional profile ids may appear in verifier-created QZ pool entries; when a QZ file supplies a `modes` array, that array is authoritative for that pool case.

## Row shape

Top-level object includes `meta` and `rows`. meta.rows_total equals rows.length. Each row includes case_id, mode_id, layer_id, scale_u32, stat_min, stat_max, replay_tag, and row_digest. Field types appear in `environment/defs/emit_shape.json`.

## Canonical bytes and row_digest

Canonical row bytes are pipe-joined string forms of case_id, mode_id, layer_id, scale_u32, stat_min formatted to six decimal places, stat_max formatted to six decimal places, and replay_tag. row_digest is the first sixteen lowercase hexadecimal characters of sha256 over those canonical bytes. Implementation lives in `/app/environment/util/row_codec.rb`.

## Clip-then-round order

Tensor values must be clipped to documented bounds before rounding and bucket assignment. Bounds come from `environment/h5/x7/policy_table.toml` with per-layer overrides in shard manifests under `environment/h5/w2/`. Layer override lo and hi replace global bounds for that layer only. The required order is: clamp each value to the active bounds, round the clamped value to three decimal places, then use that rounded value for bucket/scale derivation. Reversing the order is invalid; for example, value `0.42` with bounds `[-0.4, 0.4]` contributes `0.400`, not `0.000`.

## Mode-clipped activation statistics

Activation statistics must be accumulated separately for fp16_baseline, int8_strict, and mixed_edge. For each mode row, first clamp every input activation value to that mode's global bounds from `environment/h5/x7/policy_table.toml`; then compute `stat_min` and `stat_max` from the clamped values. These statistics are not raw tensor extrema and are not shared across modes. For `sage`, `int8_strict` clips to `[-0.5, 0.5]` while `fp16_baseline` clips to `[-1.0, 1.0]`, so the two modes must produce different `stat_min`/`stat_max` values from the same NDJSON input. Layer-level shard bounds do not change `stat_min` or `stat_max`; they apply later during per-layer scale derivation.

## Per-layer scale derivation

Each layer_id under a shard receives an independent scale_u32 after bind. Copying a parent shard scale to every layer is invalid for mixed_edge and int8_strict rows. For each emitted layer, construct the layer tensor as `[stat_min, stat_max, (stat_min + stat_max) / 2.0]`. Merge the mode global bounds with the layer override bounds from the shard manifest; the layer override replaces `lo` or `hi` only for that layer. Clamp each layer tensor value to the merged bounds, round the clamped value to three decimals, and compute `base = abs(sum(round(value * 1000) for value in clipped_values))`. Let `offset` be the sum of the bytes in `layer_id` using the UTF-8 bytes of the layer_id string. The final scale is `(base % 1500) + 128 + offset` for `fp16_baseline`, `(base % 2000) + 256 + offset` for `int8_strict`, and `(base % 3000) + 512 + (2 * offset)` for `mixed_edge`. For verifier-added profile ids that are not one of the three built-ins, use `(base % 2500) + 384 + (3 * offset)`.

## Slice header layout

Authoritative replay bytes under `environment/fixtures/slices/` encode channel axis 1 and batch axis 0 in the first eight bytes. Text fragments under `environment/fixtures/fragments/` are incomplete.

## Staging snapshot shape

`/app/environment/fixtures/stage_snaps/q2_stub.json` may include a `headline` object mapping case_id strings to integer row counts for interim UI summaries only. It is not the graded emit.

## Recovery command

After `environment/migrations/rst9.sh` runs, execute recovery before matrix-all using the command in the Operators doc.

Recovery is idempotent. `replay_tag` is a state-machine field from `F5::ScratchArena`: if the arena file is absent or contains `clean`, every emitted row uses `live`; if it contains `poisoned`, every emitted row uses `replay` until the recovery command clears it. Do not delete or bypass the ScratchArena mechanism.

## Held-out QZ pool

Files matching `environment/h5/pool/QZ-*.json` are discovered at runtime and obey the same row_digest rules as stock case ids in `environment/docs/case_ids.txt`. A QZ file may name an existing stock case or a verifier-added case. Optional fields are:

- `source`: path relative to `/app/environment` for the activation NDJSON. When present, it replaces the stock source selection.
- `shard`: path relative to `/app/environment` for the shard TOML. When present, it replaces the stock shard selection.
- `modes`: array of profile ids to emit for this QZ pool case. When present, emit exactly these modes for the pool entry.
- `mode_hint`: single profile id for older pool fixtures; if `modes` is absent and `mode_hint` is present, emit only that profile for the pool entry.

Pool files must be interpreted at runtime; verifier-created QZ files are not known when the image is built.

## Tie-break order

When multiple layer rows share a parent shard id, sort layer_id lexicographically before bind.
