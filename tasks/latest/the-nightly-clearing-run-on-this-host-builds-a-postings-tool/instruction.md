The nightly clearing run on this host builds a postings tool entirely from vendored sources and then uses it to turn a binary tape of settlement records into a postings report. Since a recent change to the tool the build still completes and the tool still runs, but downstream reconciliation keeps rejecting the report: the amounts come out right for the small shipped tape and wrong for larger ones.

Everything the build needs is under /app/vendor and /app/build, and no network is available. The vendored kit at /app/vendor/reckit holds the record-format library recfmt.fs and the FORMAT descriptor, which together set out how one record frame is laid out and how each field is meant to be read from the tape. /app/build/assemble.sh places that library ahead of the unit /app/build/decode.fs and writes the assembled program to /app/build/tape.fs, and /app/build/run.sh performs that assembly and then runs the program. The assembled program takes two arguments, the path of an input tape and the path of the report to write; with no arguments it reads /app/data/records.bin and writes /app/data/report.txt.

Each record frame is eight bytes as the FORMAT descriptor sets out. For every frame the report writes a tab-separated line of the ledger key and the posting amount, and then a final line whose key is TOTAL carrying the summed amount of all frames. Every ledger key and every amount, and the total, must match the value the vendored recfmt library reads from the frame.

Restore the build so that /app/build/run.sh produces, at /app/data/report.txt and for any tape later passed to /app/build/tape.fs, a report that agrees with the vendored kit for records of every size. Do not change the vendored kit or the record layout.
