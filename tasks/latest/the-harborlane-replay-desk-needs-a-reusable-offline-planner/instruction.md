The harborlane replay desk needs a reusable offline planner, not a one-off plan for the sample files. Finish the Haskell program at `/app/Main.hs`; it will be compiled with GHC and run as `/tmp/harborlane-planner --root ROOT --out-dir OUT_DIR`.

For each `ROOT`, read `ROOT/var/lib/harborlane/data/segments.tsv`, `ROOT/var/lib/harborlane/data/replay.tsv`, `ROOT/var/lib/harborlane/data/conflicts.tsv`, `ROOT/etc/harborlane/policy.tsv`, and `ROOT/var/cache/harborlane/state/leases.tsv`. Write `OUT_DIR/plan.tsv` and `OUT_DIR/Plan.hs`. The public data root is `/`, but the same binary must work for other roots with the same schema. Do not edit input files, fetch packages, use the network, or call external helper programs from the Haskell planner.

The verifier statically scans `/app/Main.hs` before compiling it. It rejects the tokens `System.Process`, `System.Cmd`, `createProcess`, `callCommand`, `readProcess`, and `system ` anywhere in the file, including comments and string literals. It also rejects public segment-id prefix literals such as `seg-no-`, `seg-ea-`, `seg-so-`, `seg-we-`, `seg-de-`, `seg-re-`, `seg-qu-`, `seg-lo-`, and `seg-ga-`; do not embed the sample segment ids, public-root row positions, or a public-root lookup table anywhere in the source.

`plan.tsv` must be tab-separated with header `segment_id enabled threshold_param priority routing_tier`, using those exact names and one row per segment in the same order as `segments.tsv`. Enabled rows use `enabled=1`, `threshold_param` formatted with two decimals in `[0.50,2.00]`, unique priorities `1..N`, and routing tier `EDGE`, `BULK`, or `DEFER`. Disabled rows use exactly `0`, `0.00`, `0`, and `OFF`. `Plan.hs` must declare `module Plan where` and expose `planRows :: [(String, Int, Double, Int, String)]`, `planDigest :: String`, `tierCounts :: [(String, Int)]`, `streamTierCounts :: [((String, String), Int)]`, `thresholdBuckets :: [(String, Int)]`, `affinityCounts :: [(String, Int)]`, and `priorityBands :: [(Int, Int, Int, Int, Int, Int, Int, Int)]`. `planRows` must mirror the TSV, `planDigest` is the SHA-256 hex digest of the complete TSV bytes, `tierCounts` must contain counts keyed by tier, and `streamTierCounts` must contain counts keyed as `((tier, stream), count)`, not `((stream, tier), count)`. `thresholdBuckets` uses `track` for thresholds `<= 1.54`, `guard` for thresholds `> 1.54` and `<= 1.64`, and `quarantine` for thresholds `> 1.64`. `affinityCounts` is the EDGE/BULK/DEFER count of enabled rows whose tier equals the segment affinity, and each `priorityBands` tuple is `(band, edge, bulk, defer, ingest, ledger, cache, repair)` for one 11-priority band. The `band` field is the sequential band number `1`, `2`, `3`, or `4` for priority ranges `1-11`, `12-22`, `23-33`, and `34-44`; it is not the starting priority value.

Exactly 44 segments must be enabled. CPU must be at most 660 and memory at most 1060. `policy.tsv` gives `basin`, `min_enabled`, `max_enabled`, and `target_enabled` rows for basin counts. Stream counts must be 10-12 each for `ingest`, `ledger`, `cache`, and `repair`. Tier counts must be EDGE 12-17, BULK 12-20, and DEFER 9-17. Threshold bucket counts must be track 16-24, guard 12-20, and quarantine 4-10.

No enabled segment may be in a held lease state or paired with another enabled segment in `conflicts.tsv`. Every routing-tier/stream-class cell must have at least 2 enabled rows. No overlap group may appear more than 3 times. At least 30 enabled rows must use their segment affinity as the routing tier. The first 18 priorities must cover at least 7 basins, all 4 stream classes, EDGE 4-8, BULK 4-8, DEFER 3-7, and no overlap group more than twice. Each priority band `1-11`, `12-22`, `23-33`, and `34-44` must have EDGE/BULK/DEFER counts between 2 and 5, each stream count between 2 and 4, at least 5 distinct basins, and no overlap group more than twice. Any enabled segment with `risk >= 0.86` must use `DEFER` and a threshold at least `1.66`.

Acceptance uses the deterministic scorer at `ROOT/opt/harborlane/scripts/model.py` when present and the same documented rules for generated roots. A valid submission must satisfy every hard rule and clear every score gate reported by the model: aggregate score, replay, work, drift, risk, balance, and stress. Generated roots are not just the public root under new names: they may prefix every segment id, update all segment references in replay/conflict/lease files, reorder `segments.tsv`, perturb replay heat/pressure, and perturb per-segment numeric fields such as value, replay, work, drift, risk, threshold, noise, cpu, and mem while keeping the same schema. Read and optimize from the files under the provided `ROOT` on every run; do not cache public-root metrics, assume public-root row order, or reuse a fixed active set. Empty outputs are invalid; exact ordering, formatting, summary counts, and digest values are checked, and generated variants must produce root-specific plan contents rather than a single identical public-root plan. The verifier compiles only `/app/Main.hs`; any prototype or helper source left elsewhere is ignored.
