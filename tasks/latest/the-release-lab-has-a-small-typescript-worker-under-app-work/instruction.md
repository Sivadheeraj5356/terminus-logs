The release lab has a small TypeScript worker under `/app/worker` that should turn a directory of OCI-style diffusion experiment cards into a deterministic Monte Carlo reduction report. Make the source under `/app/worker` regenerate the report through the normal command; a manual or static JSON write is not sufficient because the verifier reruns the command on the default fixtures and on additional valid input directories. Please make this command work:

`cd /app/worker && npm run report -- --spec-dir /app/worker/fixtures/specs --calibration /app/worker/fixtures/calibrations.json --output /app/output/diffusion-report.json`

The same command must also work with other absolute `--spec-dir`, `--calibration`, and `--output` paths that follow the same input schema, and the output parent directory should be created when it does not exist. Treat the input cards and calibration file as read-only: apart from writing the requested output file, the worker must not create, edit, or delete files under the spec directory, and it must never modify the calibration file. Do not hardcode the provided fixture names or expected values; the report has to be derived from the input files each time.

Each input card is a `.json`, `.yaml`, or `.yml` file. Other file extensions are ignored. A valid card has `apiVersion` equal to `diffusion.ops/v1`, `kind: DiffusionExperiment`, `metadata.name`, optional `metadata.revision`, `container.image`, optional `container.digest`, and a `spec` object with `seed`, `walkers`, `steps`, `drift`, `volatility`, `calibrationRef`, optional `dependsOn`, and a non-empty `dimensions` array. Every dimension has `name`, `weight`, `lower`, and `upper`. `metadata.revision` defaults to `0`; when present it must be a non-negative integer. `spec.dependsOn`, when present, must be an array of unique non-empty strings naming other card `metadata.name` values. A present `metadata.revision` with the wrong type is a `schema_error`, but a correctly typed negative integer such as `revision: -1` is a `range_error`. The seed must be an integer from 1 through 2147483646; walkers and steps must be positive integers; volatility must be non-negative; every dimension must have a non-empty name, finite numeric values for weight, lower, and upper, and `lower < upper`.

The calibration file is JSON with a `profiles` object. The named profile ultimately supplies numeric `driftScale`, `volatilityScale`, `driftBias`, `confidenceK`, `ciLimit`, `escapeThreshold`, and `dependencyAttenuation` values. `dependencyAttenuation` must be between `0` and `1`, inclusive. A profile may include `inherits`, a non-empty string naming a parent profile in the same file. Resolve inheritance recursively before using the profile: start with the parent, override any scalar fields present on the child, including `dependencyAttenuation`, merge `dimensionAdjustments` by adjustment key and field, and merge `retention` fields by field. Missing parents, inheritance cycles, malformed raw profiles, or malformed resolved profiles make cards using that calibration fail with `calibration_missing`. A profile may also include `dimensionAdjustments`, an object keyed by dimension name or by `*`. Each adjustment object may contain only numeric `weightScale`, `weightBias`, `lowerShift`, and `upperShift` fields. For a dimension, apply the resolved `*` adjustment first when present, then apply the resolved exact-name adjustment when present. Each adjustment transforms the current values as `weight = weight * weightScale + weightBias`, `lower = lower + lowerShift`, and `upper = upper + upperShift`; missing adjustment fields use defaults `weightScale = 1`, `weightBias = 0`, `lowerShift = 0`, and `upperShift = 0`. The adjusted weight and bounds are used for simulation, escape checks, and the reported dimension weight. A resolved profile may include `retention` with `maxExperiments` as a positive integer and `riskWindow` as a non-negative number.

For accepted cards, normalize the image as follows: when `container.digest` is present, remove a tag suffix from `container.image` only if that suffix appears after the last slash, then append `@` and the digest; otherwise keep `container.image` unchanged. Sort dimensions by `name` after applying adjustments and before simulation and reporting. The worker uses the Park-Miller random generator: initialize one RNG state once per accepted card with the card seed before the walker loop, do not reset it for each walker, then for every random draw set `state = (state * 48271) % 2147483647` and use `state / 2147483647` as the uniform value. For each walker, start all dimension positions at zero. For each step and each sorted dimension, consume one random draw and add `drift * driftScale + driftBias` times the adjusted dimension weight, plus `volatility * volatilityScale * (uniform * 2 - 1) * abs(adjusted weight)`. A walker is escaped for a dimension if that dimension position ever goes below the adjusted lower bound or above the adjusted upper bound; keep simulating after escape so later random draws are still consumed. The walker score is the sum of final positions across dimensions.

Numeric outputs are rounded to six decimal places. For every simulated candidate, compute the population mean and population variance of walker scores, `ci95` as `[mean - confidenceK * sqrt(variance / walkers), mean + confidenceK * sqrt(variance / walkers)]`, `escape_rate` as escaped walkers divided by walkers, and one dimension entry per sorted dimension with that dimension's adjusted weight, final-position mean, population variance, and escape rate. The candidate `status` is `escaped` if its escape rate is greater than the calibration profile's `escapeThreshold`; otherwise it is `noisy` if the CI width is greater than `ciLimit`; otherwise it is `converged`. Its `risk_score` is rounded to six decimals from `status_rank * 100 + escape_rate * 50 + max(0, ci_width - ciLimit) * 10 + abs(mean)`, using unrounded `mean`, `escape_rate`, and CI width; `status_rank` is `0` for `converged`, `1` for `noisy`, and `2` for `escaped`.

After simulation but before cohort reduction, resolve the candidate dependency graph. Dependencies refer to simulated candidates by `metadata.name` before cohort reduction and retention. A dependency name must resolve to exactly one simulated candidate; missing names, ambiguous duplicate names, or dependencies on candidates that have already been rejected by dependency processing reject the dependent candidate with reason `dependency_missing`. If the remaining dependency graph contains a cycle, reject every candidate in the cycle with reason `dependency_cycle`; then repeat dependency-missing propagation until only acyclic candidates with accepted dependencies remain. For surviving candidates, compute dependencies first in deterministic order (`id`, then `file`) and set `dependency_risk = round6(risk_score + dependencyAttenuation * max(dependency_risk of dependencies))`; the max is `0` for candidates with no dependencies. The output `dependencies` array is the sorted list of dependency names. Cohort reduction and retention use `dependency_risk` as their primary risk value, not `risk_score`, but `risk_score` remains the simulation-only risk field.

After simulation, reduce duplicate release cohorts. A cohort is all otherwise valid candidates with the same normalized `image_ref` and `calibration`. Keep exactly one experiment per cohort: the candidate with the highest `dependency_risk`; if tied, the highest `revision`; if still tied, the lexicographically smallest `id`; if still tied, the lexicographically smallest relative `file`. Every non-kept cohort candidate becomes a rejection with reason `superseded`. Then apply the resolved calibration `retention` policy, when present, to the cohort winners for that calibration: sort those winners by highest `dependency_risk`, highest `revision`, lexicographically smallest `id`, then lexicographically smallest relative `file`; compute the top dependency risk in that calibration; keep a winner if its sorted rank is within `maxExperiments` or if `top_dependency_risk - dependency_risk <= riskWindow`; otherwise reject it with reason `retention_excluded`. Final summaries, accepted counts, and calibration aggregates use only experiments kept after cohort reduction and retention, while rejected counts and the digest include parse/validation rejections plus `dependency_missing`, `dependency_cycle`, `superseded`, and `retention_excluded` candidates.

Write `/app/output/diffusion-report.json` (or the requested output path) as JSON with exactly these top-level keys: `generated_at`, `source`, `experiments`, `rejections`, and `summary`. Use the constant timestamp `1970-01-01T00:00:00.000Z`. `source` contains `spec_dir`, `calibration`, `accepted`, and `rejected`. Each final experiment contains `file`, `id`, `revision`, `image_ref`, `calibration`, `walkers`, `steps`, `mean`, `variance`, `ci95`, `escape_rate`, `status`, `risk_score`, `dependency_risk`, `dependencies`, and `dimensions`. Each dimension contains `name`, `weight`, `mean`, `variance`, and `escape_rate`. Each rejection contains `file`, `reason`, and `message`; `file` is the card path relative to the spec directory using `/` separators. Rejection reasons are exactly `parse_error`, `schema_error`, `range_error`, `calibration_missing`, `dependency_missing`, `dependency_cycle`, `superseded`, or `retention_excluded`, with this precedence: parse failures first, then missing or wrong-shaped card fields, then invalid numeric ranges, then missing or malformed calibration profiles, then dependency-missing candidates, then dependency-cycle candidates, then superseded duplicate-cohort candidates, then retention-excluded cohort winners. Continue after rejections. If no cards are accepted after cohort reduction, still write the same report shape and exit with code 2; otherwise exit with code 0.

Order must be deterministic: scan card files recursively and sort by relative path, sort final experiments by `image_ref` then `id`, sort rejections by `file`, sort dimension arrays by `name`, and sort the summary calibration rows by calibration name. `summary.status_counts` always has `converged`, `noisy`, and `escaped` integer keys. `summary.calibrations` has rows `{name, experiments, mean_escape_rate, mean_dependency_risk}` grouped over final accepted experiments. `summary.digest` is the lowercase SHA-256 (`sha256`) base-16 hex digest of canonical compact JSON for an object with keys `experiments`, `rejections`, `status_counts`, and `calibrations`, where all object keys are recursively sorted lexicographically and the digest field itself is not included. Use JavaScript-standard JSON number formatting for this canonical JSON: no trailing zero padding and integers without a decimal point. The digest payload uses complete final experiment rows including `dependencies` and `dependency_risk`, calibration rows, status counts, and rejection rows containing only `file` and `reason` so free-form rejection messages do not affect the digest.
