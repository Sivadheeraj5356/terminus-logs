# Peak capture, lattice residual, and phase seal bind

After trace load, /app/state/torque-residual-snapshot.json uses schema lattice-residual-v1. Top-level keys are schema, residuals, and snapshot_digest only. Each residuals row carries batch_id and residual_score.

Residual formula: for every HOLD profile in a batch, add abs(temp_c - window_midpoint) * effective_hold_s * formulation quench_scale from /app/lattice-invariant-catalog/formulation-catalog.json. Then add the batch sum of adjacency_contrib from /app/state/hold-adjacency-ledger.json (see /app/docs/hold-adjacency-ledger.md). After summing those terms for the batch, round the total to exactly three decimal places using half-even (banker's) rounding on the float sum (example: 12.3456 → 12.346, 12.3455 → 12.346 when banker's rules select the even last digit as implemented by the language round-to-3). Encode that rounded value under the same Perl JSON::PP whole-number integer rules defined in /app/docs/kiln-trace-contract.md (149.000 becomes JSON integer 149; non-integers keep three-decimal float form). snapshot_digest covers stable JSON of residuals and schema only, using the same key-ordered sorted keys and Perl JSON::PP encoding. Wire example: /app/spec/torque-residual-snapshot.schema.json

Emit asymmetric trust for staged residuals: emit must read residual_score values from the on-disk /app/state/torque-residual-snapshot.json residuals rows when building lattice_walks, and must not re-derive residual_score from kiln traces. snapshot_digest is the bind-time fingerprint of residuals+schema; emit does not refuse publish solely because residual row values no longer hash to that snapshot_digest string. phase_seal still hashes the snapshot_digest string present on disk.

Bind also writes /app/state/hold-spine-ledger.json per /app/docs/hold-spine-ledger.md, /app/state/hold-adjacency-ledger.json per /app/docs/hold-adjacency-ledger.md, /app/state/cross-batch-concordance.json per /app/docs/cross-batch-concordance.md, and /app/state/concordance-cycle-basis.json per /app/docs/concordance-cycle-basis.md. Emit must verify all four staged ledgers before sealing.

/app/state/polymorph-walk-seal.json uses schema phase-stabilization-seal-v2. Top-level keys are schema, epoch, capture_digest, snapshot_digest, spine_digest, adjacency_digest, concordance_digest, cycle_digest, audit_commitment, ledger_triad_digest, topology_bundle_digest, closure_bundle_digest, and phase_seal only. Emit reads the current integer epoch from /app/var/walk_epoch before building the seal. Before sealing, emit must compute audit_commitment as SHA-256 over the UTF-8 string fuse|epoch_before|epoch_after where epoch_before is the pre-bump walk_epoch value and epoch_after is epoch_before plus one. ledger_triad_digest remains SHA-256 over bind_digest, spine_digest, and adjacency_digest joined by pipe characters. topology_bundle_digest is SHA-256 over concordance_digest and cycle_digest joined by a pipe. closure_bundle_digest is SHA-256 over ledger_triad_digest and topology_bundle_digest joined by a pipe. phase_seal is SHA-256 over capture_digest, snapshot_digest, the pre-bump epoch, bind_digest, spine_digest, adjacency_digest, concordance_digest, cycle_digest, audit_commitment, ledger_triad_digest, topology_bundle_digest, and closure_bundle_digest, joined by pipes in that order. The audit jsonl row appended after publish must use the same epoch_before and epoch_after pair and action fuse. Wire example: /app/spec/polymorph-walk-seal.schema.json Write polymorph-walk-seal.json, build the lattice chronicle publish, then increment walk_epoch.

bind_digest in the manifest is SHA-256 over kiln_traces_path, a pipe separator, and conching_window_path as recorded during bind.

Each successful polymorph-chronicle fuse increments /app/var/walk_epoch and appends one JSON line to /app/var/chronicle-audit.log.jsonl with action fuse, epoch_before, epoch_after, and chronicle_digest.

Contract helpers under /app/helpers/digest/ and /app/helpers/assess/ document fragment digest and hold assessment rules only. Authoritative seal preimage and spine rules live in this file and /app/docs/hold-spine-ledger.md. walk_content_digest stays stable for fixed lattice_walks content across epoch bumps while chronicle_digest changes because it includes epoch and phase_seal.
