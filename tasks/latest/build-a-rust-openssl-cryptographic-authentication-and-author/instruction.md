Build a Rust/OpenSSL cryptographic authentication and authorization binary that defends a sealed pathology vault against forged ECDSA claims, unauthorized AES-GCM plaintext disclosure, tampered attestation artifacts, and patient-identifier exfiltration. This is a security enforcement utility (signature verification, decrypt ACL, fail-closed key checks, integrity signing, confidentiality), not a reporting or analytics job.

Compile `/app/bin/seal_authz` from `/app/vault_scaffold` using OpenSSL + SQLite crates and the offline vendor tree at `/opt/cargo-vendor`. With no arguments, re-read live `/app/data` each run and enforce:

- Read every `*.json` sealed claim under `/app/data/sealed/` (`report_id`, `category`, `label_ciphertext`, `label_nonce`, `label_tag`, `signature`, `patient_ref`).
- Authenticate each claim with ECDSA P-256 / SHA-256 using `/app/data/keys/archive_verify.pub`. The signed message is exactly UTF-8 `{report_id}|{category}|{label_ciphertext}|{label_nonce}|{label_tag}` using the stored base64 strings. Deny authentication failures.
- Authorize via `/app/data/policy.json`: deny any claim whose `category` is outside `authorized_classes`, even when the signature verifies.
- Decrypt under ACL with AES-256-GCM (OpenSSL) and the 32-byte `/app/data/keys/label_dek.bin` (base64 nonce/tag/ciphertext). Release plaintext labels only for categories in `decrypt_plaintext_for`; other authenticated categories keep report IDs only. If `label_dek.bin` is not exactly 32 bytes, exit non-zero without writing or rewriting anything under `/app/output` (fail closed).
- Emit the integrity attestation `/app/output/seal_attestation.json` as canonical JSON (UTF-8, keys sorted at every object level, compact `,`/`:` separators, no trailing newline): `version`=`1`, `authorized` sorted by `category` (each with `category`, sorted `report_ids`, and `labels` only when decrypt-authorized), sorted `denied`, and `audit` integers `scanned`/`authenticated`/`denied`. Identical inputs must reproduce identical bytes; deleting outputs and re-running must recreate the same content.
- Integrity-sign the exact attestation bytes with ECDSA P-256 / SHA-256 using `/app/data/keys/registry_signing`, writing base64 DER to `/app/output/seal_attestation.sig`.
- Persist `/app/output/seal_authz.db` with `authentications(report_id TEXT PRIMARY KEY, category TEXT NOT NULL, label TEXT, verified INTEGER NOT NULL)` (`verified=1`; `label` plaintext only when decrypt-authorized else NULL) and `meta(key TEXT PRIMARY KEY, value TEXT NOT NULL)` including `attestation_sha256` (lowercase hex SHA-256 of attestation bytes), `authenticated_count`, and `denied_count`.
- Confidentiality: never write `patient_ref` or any `PT-` patient token into the attestation, signature, or database.

On the provided sealed seed, authentication accepts 10 claims across `copy_number_alteration`, `epigenetic_change`, `point_mutation`, and `translocation`, denies `MSR-0011` and `MSR-0012`, and decrypts labels only for `point_mutation` and `copy_number_alteration`.
