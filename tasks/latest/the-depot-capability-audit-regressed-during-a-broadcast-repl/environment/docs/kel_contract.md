# Kel admission export contract

`/app/output/admission_trace.json` is regenerated by running `bash /app/environment/ci/rebuild.sh` and then `/app/environment/bin/depot audit --pack <pack>`. Pack JSON files live under `/app/environment/data/packs/`, ticket catalog rows live in `/app/environment/data/tickets/catalog.json`, and runtime floor, revocation, and session state live under `/app/environment/data/runtime/`.

## Pack and runtime inputs

A pack contains `pack_id`, `profile`, `session_id`, optional `reset_session`, and a `tickets` array. A ticket row contains `row_id`, `principal`, `ticket_id`, `parent_id`, `ticket_epoch`, `scope_mask`, `action_mask`, `ticket_hex`, and `seen_seq`. `seen_seq` is the broadcast sequence visible to that row.

The catalog contains `tickets` with `ticket_id`, `parent_id`, `subject_id`, and `scope_mask`. Presented principals may be aliases; admission always resolves the canonical subject from the catalog row named by `ticket_id`.

`epoch_floor.json` contains `floor_epoch`. `revoke_ledger.json` contains a `broadcasts` array. Each broadcast has `seq`, `kind` (`ticket` or `subject`), `value`, and `active`. For a row, only broadcasts with `seq <= seen_seq` are visible. For the same `(kind, value)`, the visible broadcast with the highest `seq` decides whether that value is currently revoked.

`session_state.json` is maintained by the audit command. A pack with `reset_session: true` clears the named session before appending new rows. Otherwise, rows from the same session remain part of the exported trace across later invocations and after output-file deletion. Sessions with different `session_id` values do not share rows.

## Export shape

The top-level JSON object contains `schema`, `pack_id`, `profile`, `session_id`, `floor_epoch`, `run_count`, `row_count`, `rows`, `fold_audit_hex`, and a first-row mirror for compatibility: `principal`, `subject_id`, `ticket_id`, `parent_id`, `ticket_epoch`, `scope_mask`, `action_mask`, `effective_scope`, `decision`, `reason`, `mac_ok`, `revoke_hit`, `scope_ok`, `epoch_ok`, `issuer_audit_hex`, and `gate_audit_hex`.

Each row contains the mirrored fields plus `index`, `row_id`, `seen_seq`, `session_seq`, and `pass_index`. `schema` is `depot-admission-v2`. `decision` is `admit` or `deny`. `reason` is one of `ok`, `mac_fail`, `revoked`, `stale_epoch`, or `scope_exceed`; admitted rows always use `ok`. Status fields such as `mac_ok`, `revoke_hit`, `scope_ok`, and `epoch_ok` are JSON booleans.

## Capability semantics

Ticket MACs bind the catalog subject, not necessarily the presented principal. The bound text is `<subject_id>|<ticket_id>|<parent_id>|<ticket_epoch>|<scope_mask>` using the 32-byte depot capability key material. Hex comparison is case-insensitive.

Scope bits are `1` read, `2` write, and `4` admin. A row's effective scope is the bitwise intersection of the presented `scope_mask` with every ancestor scope in the catalog, walking from `parent_id` to the root. The action is covered when `(action_mask & effective_scope) == action_mask`.

A row is revoked when its ticket id, any ancestor ticket id, or its catalog subject is active in the visible revocation broadcasts for that row. `epoch_ok` is false when `ticket_epoch` is below `floor_epoch`.

Admission reason priority is: MAC failure first, then revocation, then stale epoch, then scope exceed, then admit. This priority applies even when several fields are false for the same row.

## Audit digests

Booleans encode as `0` or `1` in digest input.

Issuer row digest: `SHA256("issuer|" + session_id + "|" + row_id + "|" + subject_id + "|" + ticket_id + "|" + decision + "|" + floor_epoch + "|" + revoke_hit)`.

Gate row digest: `SHA256("gate|" + session_id + "|" + row_id + "|" + subject_id + "|" + ticket_id + "|" + decision + "|" + seen_seq + "|" + floor_epoch + "|" + revoke_hit + "|" + mac_ok + "|" + scope_ok + "|" + epoch_ok + "|" + effective_scope)`.

Fold digest: sort rows by `row_id`, then hash `fold|` plus the profile name, session id, row count, and for each sorted row `|row_id|ticket_id|decision|reason|gate_audit_hex`. Equivalent row sets for the same profile and session must have the same `fold_audit_hex` regardless of input order.
