# Request Semantics Contract

Normative manual for `/app/bin/proxy-local`, `/app/state/spool`, and `/output/request-trace.json`.

Version: 1.0

## 1. Terminology and representation model

This section defines normative requirements for `term` behavior in the local signed-request proxy. Implementations MUST comply with every MUST statement unless a profile-specific exception is explicitly documented.

§1.1 The proxy MUST treat the decoded entity body as the sole authoritative byte sequence bound by HMAC signatures for both current and legacy profiles. When applying terminology and representation model, operators MUST verify that live ingress, backend capture, spool seal, and trace entry `term-1-1` remain consistent across restart and catalog reload. Profile epoch transitions MUST NOT reinterpret sealed semantic state. Ambiguous duplicate singleton fields MUST yield reason code header_policy_violation before forwarding. For encoded targets, canonical_target MUST reflect documented normalization while wire_target may differ. Cache hits MUST only occur when tenant, key identity, key epoch, profile identity, profile epoch, and authority catalog digest are unchanged since the prior verification in the same process.

Example (term-1): A client sends method POST, profile current-2026, Connection: x-shadow, and X-Shadow: probe. The signed canonical message excludes x-shadow. The backend capture MUST exclude X-Shadow. Trace canonical_headers MUST match backend headers for signed fields.
