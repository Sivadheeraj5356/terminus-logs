We're building `rsx`, a small regex engine in pure Rust (std only, no crates) that compiles a restricted regex grammar down to a minimal DFA and later scans large inputs with it. The scaffold lives in `/app`: a Cargo project whose modules under `/app/src` are mostly empty stubs, and the exact grammar plus the canonical output format are pinned in `/app/docs/regex-spec.md`. Read that spec carefully and treat it as the contract; it covers literals, `.`, character classes with ranges, the POSIX-style named sets like `[[:hexdigit:]]`, class subtraction and intersection such as `[a-z--[aeiou]]` and `[a-z&&[^aeiou]]` (which the spec evaluates strictly left to right, so read that section carefully), escapes including `\xHH`, concatenation, alternation, `*` `+` `?`, bounded counts `{m,n}` including the `{0}` corner case, and the `^`/`$` anchors.

This first step is a data-transformation step: turn a pattern string into a canonical, byte-exact textual description of the automaton it denotes. After `cd /app && cargo build --release` produces `/app/target/release/rsx`, the command `rsx compile '<regex>'` must parse the pattern, build the automaton, minimise it, and print the canonical DFA description defined in the spec to stdout: the `states`/`start`/`accept` header followed by one line per state with its sorted, range-compressed byte transitions, using the deterministic BFS state numbering the spec describes so the output is stable and comparable. Dead states are pruned, with the one exception the spec calls out: the start state is always kept and numbered 0, so a pattern whose language is empty still compiles to a single lone start state (state count 1, no accepting states, no transitions) rather than to nothing. An invalid pattern must print nothing to stdout and exit with a nonzero status.

The whole thing has to be deterministic and run offline, and the canonical form matters down to the byte, so follow the rendering rules in the spec exactly (hex byte labels, range syntax, accept-line formatting, trailing newline).
