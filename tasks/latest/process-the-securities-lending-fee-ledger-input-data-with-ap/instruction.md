Process the securities lending fee ledger input data with /app/securities_lending_fee.go, compiled to /app/securities_lending_fee. It should read /app/input/lending_batches.csv, /app/input/borrowers.csv, and /app/input/fee_accruals.jsonl, then write /app/output/securities_lending_fee_report.json; if INPUT_DIR or OUTPUT_DIR is set, use those directories instead. lending_batches.csv has batch_id,cutoff_at, borrowers.csv has borrower_id,lending_desk,active_limit, and fee_accruals.jsonl has fee_id, lending_batch_id, borrower_id, accrued_at, loan_sequence, fee_type, fee_cents, and rebates_fee_id. Trim strings, treat missing strings as empty and missing numbers as zero, parse timestamps as RFC3339 instants, and emit JSON numbers as numbers.

Replay the load rows in a stable order: invalid timestamps first in input order, then valid rows by event time, sequence, and id. After every row, mark its id as seen even when rejected; a later same id is duplicate unless its own timestamp is invalid. Use the first matching rejection reason in this order: invalid timestamp, duplicate id, unknown batch, after watermark, unknown entity, invalid kind, negative amount, entity cap exceeded, state conflict. Rejected rows never change current records, accepted ids, entity totals, batch net amounts, reversal state, or trace rows; rejected_events in batch_audit counts only rejected rows with a known batch. A row is after watermark when its event time is later than its batch cutoff. Valid kinds are accrual and rebate. accrual rows need fee_cents at least zero and are rejected as entity cap exceeded when current active amount plus their amount would exceed that entity's active_limit. rebate rows ignore their amount and must point to an earlier accepted, unreversed accrual row for the same borrower_id; they remove that original record, subtract its amount from that entity, increase that entity reversal count, and subtract the amount from the reversing row's batch ledger.

The report is one JSON object with curated_records, entity_summary, batch_audit, entity_trace, rejected_records, and accepted_records. curated_records is final unreversed records sorted by record_id with record_id, entity_id, segment, batch_id, and amount. entity_summary includes every entity sorted by entity_id with entity_id, segment, current_records, reversal_count, active_limit, and net_amount after accepted reversals. batch_audit includes every batch sorted by batch_id with accepted_events, rejected_events, and net_amount from accepted rows assigned to that batch. entity_trace appends one row after each accepted row with record_id, batch_id, entity_id, current_records, active_amount, and reversal_count after that mutation. rejected_records is sorted by record_id with record_id and reason. accepted_records is accepted ids in canonical processing order. Empty arrays are valid and grading is exact after JSON parsing.
