A displacement field u(x, t) on the periodic interval x in [0, 1) obeys the damped wave equation u_tt + 2 g u_t = c squared times u_xx, with positive wave speed c and positive damping g. The interval wraps and the field starts from rest, so its initial time derivative is zero.

A C project in /app supplies the driver, parser, grid, profile sampling, and CSV writer, leaving only the time integrator. Implement scheme_advance, declared in /app/include/scheme.h and stubbed in /app/src/scheme.c, advancing the state in place between successive times. The state has length two N: the displacement in the first N entries and its derivative u_t in the next N, on the grid x_i = i/N. Build with make in /app, then run /app/solver /app/input/transport.json /app/output/field.csv, which writes rows t,x,u,v per snapshot time and grid point in increasing x. The input gives c, g, N, a Courant number nu, the final and snapshot times, and the initial profile.

At every snapshot the grid sum of the displacement times dx must stay within one part in a billion of its initial value, every value must stay finite, and a discrete energy must never increase between snapshots. The displacement must match the exact damped solution to a small relative L2 error that, as the grid is refined with the Courant number fixed, falls like the sixth power of the grid spacing, so any lower order scheme is rejected for both its error and its rate. Because the step shrinks in proportion to the spacing, this rate is joint: the spatial discretisation and the time integration must each be at least sixth order, so a high order spatial stencil advanced by only a fourth order time integrator stays fourth order overall and will not satisfy it. Advance on the grid from the initial time; do not write any closed form solution directly, and do not use spectral or FFT methods. The equation is linear, so scaling, adding, or translating the initial data does the same to the solution, checked directly.
