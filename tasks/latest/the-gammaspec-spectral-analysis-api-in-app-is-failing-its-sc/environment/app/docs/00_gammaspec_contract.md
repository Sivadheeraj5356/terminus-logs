# GammaSpec Compact API Contract

This short contract is the first-read map for the TypeScript service in `/app`. The full lab methods bundle remains `/app/docs/gammaspec_methods.md`; compliance matrix `source` fields must cite that full methods document as `/app/docs/gammaspec_methods.md#<requirementId>`. Implementation files belong in `evidence` and `verifiedBy`, not in `source`.

## Shared request and validation rules

All spectrum-like requests use `channels: number[]`, `counts: number[]`, `isotope: string`, `liveTimeSec: number`, and `realTimeSec: number`. Unknown isotopes, malformed numeric arrays, `liveTimeSec <= 0`, `realTimeSec < liveTimeSec`, invalid bootstrap iteration counts, and non-integer bootstrap seeds return HTTP 400 JSON. Bootstrap iteration counts must be integers greater than or equal to 2; missing, non-integer, or smaller iteration counts return HTTP 400 JSON. Optional `background` is `{counts: number[], liveTimeSec: number, label?: string}`; `background.counts.length` must equal `counts.length`, and `background.liveTimeSec` must be positive. The detector id is always `GS-ORION-17`.

All response `normalization` objects contain exactly these fields and no raw count arrays or nested background objects: `liveTimeSec`, `realTimeSec`, `deadTimeCorrection`, `backgroundSubtracted`, and `backgroundScale`. `backgroundSubtracted` is boolean; the other four fields are numeric. Canonical quality flags are emitted in this order when their condition applies: `tail-model-applied`, `background-subtracted`, `dead-time-corrected`, `high-reduced-chi-square`. The tail flag is emitted for the four-term fit, the background flag only when a background object is accepted, the dead-time flag when `deadTimeCorrection > 1.0005`, and the high chi-square flag when `reducedChiSquare > 3.0`. Diagnostics may append `residual-review` after those four.

## Numerical contract

For channel `c`, calibrated energy is `offset + slope*c + quadratic*c*c` from `/app/data/calibration.gamma.json`; the calibration file is loaded once and reused. ROI channels satisfy `abs(E - peak.energyKeV) <= peak.roiHalfWidthKeV`. `deadTimeCorrection = realTimeSec/liveTimeSec`. With background, `backgroundScale = liveTimeSec/background.liveTimeSec`; without background, `backgroundScale = 0`. Corrected observed ROI rate is `(counts_i - backgroundScale*background_i) * deadTimeCorrection / liveTimeSec`.

The weighted fit is in energy space with model terms exactly `['gaussian','lowEnergyTail','constant','linear']`. Rows are `[gaussian, lowEnergyTail, 1, E_i-center]`, with `gaussian = exp(-0.5*((E_i-center)/sigma)^2)` and `lowEnergyTail = exp((E_i-center)/tailDecayKeV)` for `E_i <= center` and `0` for `E_i > center`; the tail column is this standalone one-sided exponential basis, not a Gaussian multiplied by an exponential. Variance is `(max(counts_i,1) + backgroundScale^2*max(background_i,1) + readNoiseVariance) * (deadTimeCorrection/liveTimeSec)^2` with background, or `(max(counts_i,1) + readNoiseVariance) * (deadTimeCorrection/liveTimeSec)^2` without background. Solve `beta = inverse(X^T W X) X^T W y`; report `amplitude`, `tailAmplitude`, `background`, and `linearSlope` in that order. `degreesOfFreedom = roi.count - 4`, `reducedChiSquare = sum(weight_i*residual_i^2)/degreesOfFreedom`, and `covariance = inverse(X^T W X) * reducedChiSquare`.

Bootstrap uses the Mulberry32 generator from GS-BS-0441 with the frozen calibrated design matrix, frozen weights, and residual resampling in corrected-rate space. It is not Poisson raw-count resampling. Percentiles use sorted samples with linear interpolation at 0.16, 0.84, 0.025, and 0.975.

## Endpoint responses

`POST /fit` returns `detectorId`, `method: "poisson-readout-tail-wls-r4"`, `weighting: "poisson_readout_live_rate_inverse_variance"`, `calibrationApplied: true`, `modelTerms`, `roi`, `coefficients`, `covariance`, `degreesOfFreedom`, `reducedChiSquare`, `normalization`, `qualityFlags`, `fittedRates`, and `residuals`.

`POST /bootstrap` returns `seed`, `iterations`, `statistic: "amplitude"`, `pointEstimate`, and `confidence` containing numeric two-element `ci68` and `ci95` arrays.

`POST /batch-fit` returns top-level `detectorId`, `runCount`, `sortedBy: "runId"`, and `results` sorted by `runId`. When `includeResiduals` is false or absent, each result row contains exactly these six keys: `runId`, `roi`, `coefficients`, `normalization`, `reducedChiSquare`, and `qualityFlags`. Compact rows must not include per-row `detectorId`, `isotope`, `method`, `weighting`, `calibrationApplied`, `modelTerms`, `covariance`, `degreesOfFreedom`, `residuals`, `fittedRates`, or nested `fit`. When `includeResiduals` is true, each result row contains exactly the same six keys plus `residuals` and `fittedRates`; it still omits nested `fit` and per-row identity/method metadata.

`POST /diagnostics` returns top-level `detectorId`, request `isotope`, request `runId` when supplied, `method: "roi-hat-residual-diagnostics-r2"`, top-level `roi`, `normalizationRevision`, compact `fit`, `integrals`, `residualDiagnostics`, `decision`, and `qualityFlags`. The compact `fit` contains `coefficients`, `degreesOfFreedom`, `reducedChiSquare`, and `qualityFlags`. The `integrals` object contains exactly numeric `observedRateSum`, `fittedRateSum`, and `absoluteResidualRateSum`; `absoluteResidualRateSum` is the sum of `abs(observedRate_i - fittedRate_i)` across ROI points in corrected count-rate units, not a signed residual sum. `residualDiagnostics` contains exactly numeric `weightedMeanRate`, `weightedRmsRate`, `maxAbsInternallyStudentized`, `maxLeverage`, and `reviewThreshold`. `weightedMeanRate = sum(weight_i*residual_i)/sum(weight_i)` and `weightedRmsRate = sqrt(sum(weight_i*residual_i^2)/sum(weight_i))`, both in corrected count-rate units. Residual review uses internally studentized residuals with threshold `2.8`; `decision` is `review-required` when `maxAbsInternallyStudentized > 2.8` or `reducedChiSquare > 3.0`, otherwise `accepted`.

`POST /isotope-screen` returns `detectorId`, `method: "candidate-isotope-wls-aicc-screen-r1"`, `sortedBy: "aicc"`, `candidateCount`, and `candidates` sorted by AICc. Candidate rows include `rank`, `isotope`, `aicc`, `deltaAicc`, `amplitude`, `reducedChiSquare`, `qualityFlags`, and `roi`. AICc uses the WLS weighted SSE, not unweighted residual SSE: `weightedSSE = sum(weight_i*residual_i^2) = reducedChiSquare*degreesOfFreedom`, `k=4`, `n=roi.count`, and `AICc = n*ln(max(weightedSSE/n, 1e-12)) + 2*k + (2*k*(k+1))/(n-k-1)`.

## Compliance matrix

`/app/output/compliance_matrix.json` is an object with `task`, `auditCaptures`, and `entries`. `auditCaptures` is an array of exactly the string paths `/app/audit/strace-gammaspec.log` and `/app/audit/lsof-gammaspec.txt`. Required `entries[].requirementId` values are `GS-CAL-0328`, `GS-NRM-0417`, `GS-TAIL-0633`, `GS-WLS-0182`, `GS-BS-0441`, `GS-BAT-0726`, `GS-QC-0864`, `GS-DIAG-0911`, `GS-SCR-1034`, and `GS-MTX-0550`. Each entry has `source`, `fixSummary`, `evidence`, and `verifiedBy`; `fixSummary` is at least five words, while `evidence` and `verifiedBy` are non-empty arrays of absolute `/app/...` path strings. Every `source` cites the full methods bundle as `/app/docs/gammaspec_methods.md#<requirementId>`. The `GS-NRM-0417` evidence and verifiedBy arrays must include the legacy normalization module path `/app/src/normalization.ts`, because that file owns live-time, dead-time, and background-scale behavior.
