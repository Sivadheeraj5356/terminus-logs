The `/app` project is `channelgate`, the subscription authorization check on a sensor telemetry bus. It reads a JSON batch on standard input, where each request pairs a channel rule a tenant has configured with the channel a subscriber is asking to read, and it writes one JSON result object on standard output.

Keep the input schema exactly `{"requests":[{"rule":"...","channel":"..."}]}` and the output schema exactly `{"admitted":[true,false]}`. Each result says whether the rule admits the entire requested channel; rules that cannot be parsed must report `false`.

The supported rule syntax includes literal bytes, `.`, character classes such as `[abc]` and `[^a-c]`, grouping, alternation, greedy `*`, `+`, `?`, counted repetition `{n}`, `{n,}`, `{n,m}`, and numeric capture references `\1` through `\9`. Preserve whole-channel admit and deny behavior for valid rules, including capture references: a numeric reference compares against the exact channel segment the referenced group captured.

A tenant can configure a valid channel rule with nested repetition that consumes CPU for an effectively unbounded time when the channel is ultimately denied. Harden the gate so those batches finish promptly without changing the JSON interface or the rule syntax. Work has to grow polynomially with channel length, so a batch comes back in seconds rather than minutes. Rules carrying numeric capture references are part of that requirement too, including cases where the costly repeated clause sits beside a capture reference, inside a group whose capture is referenced later, or in a stretch no capture reference touches at all. The sources under `/app/src` are rebuilt from scratch when the gate is checked.
