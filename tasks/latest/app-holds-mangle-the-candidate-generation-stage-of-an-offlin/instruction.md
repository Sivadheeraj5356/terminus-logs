`/app` holds `mangle`, the candidate-generation stage of an offline password-cracking pipeline used for credential-strength auditing. A rule-based dictionary attack takes a wordlist of leaked or guessed base words and a set of mangling rules (the transformations attackers apply to turn `summer` into `Summer2020!`, `$ummer`, `SUMMER`, and so on) and enumerates the guesses those rules produce. Reproducing this stage exactly matters: an auditor has to generate the same guess set a real attacker's toolchain would, so that "this password survives the attack" is a sound conclusion and not an artefact of a rule the auditor implemented differently. Build it with `make` in `/app` (equivalently `cc -O2 -std=c11 -o mangle src/main.c src/wordio.c src/rules.c`) and run `mangle <rulefile> <wordlist>`: for every base word, in file order, each rule is applied in file order and every surviving guess is written to standard output followed by a newline. Some rules **reject** a word, which is how an attack prunes its own keyspace, and a rejected pair, like a malformed rule, produces no guess.

The rule interpreter in `/app/src/rules.c` is only a skeleton; the argument handling, file readers and driver loop in `/app/src/main.c` and `/app/src/wordio.c` already work. Implement `apply_rule` so it reproduces the mangling-rule language defined in `/app/docs/rules.md`, which is authoritative and self-contained: the case, edit, insertion, extraction, replacement, duplication, swap, byte-arithmetic and per-word memory functions that shape a guess, together with the reject functions that drop a word from the attack, the shared base-36 position/argument decoding, the `\xHH` escapes, and the exact behaviour of every function at and beyond the ends of the guess. The generated guess set must match the reference byte for byte, including guesses that contain non-printable bytes and pairs that emit nothing. A single divergent or missing guess is the difference between a credential the audit clears and one it silently misses.

`mangle` must be a general interpreter driven only by its inputs; it must not special-case particular rules or words or hard-code expected guesses. Keep the command line, the input files and the output protocol exactly as `/app/docs/rules.md` describes.
