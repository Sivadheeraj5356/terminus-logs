# Deployment Policy Adjudicator Contract

The adjudicator reads a policy bundle from an input directory and writes a single JSON document named `deployment_decisions.json`. The input files are `policy.json`, `runtime_state.json`, `test_runs.json`, `exceptions.json`, and `candidates.json`. The policy contains `current_time`, `reason_order`, `trusted_signers`, `envs`, `windows`, `services`, and `risk_weights`. Windows have `id`, `env`, `starts_at`, `capacity`, `risk_budget`, and `max_db_migrations`. Services have `priority`, `min_slsa`, `max_age_hours`, `min_coverage`, `allowed_signers`, `forbidden_licenses`, and `exception_required_for`. Candidates have `id`, `service`, `env`, `version`, `digest`, `built_at`, `signer`, `requested_window`, `attestations`, `features`, `sbom`, `exception_tokens`, `rollout_impact`, and optional `requires` and `conflicts_with` lists.

Every candidate appears exactly once in the output, either in `selected`, `deferred`, or `rejected`. Versions are numeric `major.minor.patch`. A candidate with no active runtime for its service/environment is treated as newer and receives version bonus `60`; otherwise its version bonus is capped at `60` from positive component deltas: major delta times `40`, plus minor delta times `8`, plus patch delta times `2`. `deployment_value` is service priority plus rollout impact plus version bonus. `risk_score` is the sum of noncritical vulnerability weights, true feature weights, and waiver weights. An SBOM severity of exactly `critical` is critical; `high` is not critical.

Rejected candidates report additive rejection reasons in `policy.reason_order`: `unknown_service`, `unknown_env`, `not_newer_version`, `already_active_digest`, `stale_build`, `untrusted_signer`, `weak_slsa`, `attestation_mismatch`, `critical_vuln`, `forbidden_license`, `missing_required_exception`, and `outside_window`. Service checks apply only when the service is known, so an unknown service does not also receive service-derived reasons such as stale build, signer, SLSA, attestation, vulnerability, license, or required-exception failures. Windows must exist, match the candidate environment, and start after `current_time`.

Exceptions waive only matching, non-expired service/environment/reason tokens listed by the candidate. They never waive `critical_vuln`, `untrusted_signer`, `weak_slsa`, `attestation_mismatch`, `unknown_service`, or `unknown_env`. Selected rows expose waived reasons as `waived:<reason>` warnings in reason order.

The selected set must be eligible and valid as a whole. It may include at most one candidate per service/environment, must not exceed each environment `max_approvals`, and must respect each selected window's `capacity`, `risk_budget`, and `max_db_migrations` count, where `max_db_migrations` counts selected candidates with `features.db_migration` true. `requires` entries name a service and optional environment defaulting to the candidate environment. A requirement's `min_version` must be satisfied at the required candidate's window time by the initial active runtime plus selected deployments in the same window or an earlier window; a selected deployment in a later window does not satisfy an earlier requirement. `conflicts_with` entries name a service and optional environment; both sides cannot be selected together.

Among valid sets, choose the set with highest total `deployment_value`, then lowest total `risk_score`, then highest selected count, then the lexicographically smallest comma-joined sorted candidate ids. Eligible candidates not selected are deferred with reason `lower_ranked_candidate` when another candidate for the same service/environment was selected, otherwise `capacity_or_budget`.

The output top-level object has exactly `selected`, `deferred`, `rejected`, and `summary`. Selected rows sort by `env`, selected window `starts_at`, `service`, then `candidate_id`, and contain exactly `candidate_id`, `service`, `env`, `window_id`, `deployment_value`, `risk_score`, and `warnings`. Rejected and deferred rows sort by `candidate_id` and contain exactly `candidate_id` and `reasons`. `summary` contains `selected_count`, `deferred_count`, `rejected_count`, `total_value`, `total_risk`, `by_env`, and `by_window`. `by_env` and `by_window` are sorted string-to-integer objects; empty maps are valid.
