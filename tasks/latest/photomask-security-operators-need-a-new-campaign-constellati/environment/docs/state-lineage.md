# State and lineage

The constellation has schema `threatcomp.campaign-constellation/v1`, `board_checksum`, `policy_fingerprint`, `epoch`, sorted campaigns, sorted contradiction cuts, sorted unassigned frontier, `payload_digest`, and `checksum`. Each frontier row uses the field name `observation_id` for the observation identifier and `reason` for the frontier reason. Campaign rows use `confidence_band` for the band label. Payload digest is SHA-256 over canonical constellation JSON with `epoch`, `payload_digest`, and `checksum` omitted. Checksum is SHA-256 over canonical constellation JSON with only `checksum` omitted.

Canonical JSON uses UTF-8, no insignificant whitespace, object keys sorted bytewise, array order preserved, decimal integers without leading zeroes, JSON escaping for quote, reverse solidus, and controls, and one trailing newline only for files. Chronicle lines are canonical JSON objects whose keys are exactly `epoch`, `payload_digest`, `board_checksum`, `campaign_count`, and `frontier_count`, and the chronicle file ends with a trailing newline after the last line. Changed payload gets previous epoch plus one. Identical payload preserves prior constellation bytes and does not append.
