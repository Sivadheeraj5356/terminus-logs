Bench CAN trace note, revision 3

`/app/cantrace` consumes a network JSON file and a binary frame file. The binary file is a sequence of 16 byte records; a file whose length is not a multiple of 16 is invalid, must make the CLI exit nonzero, and must not write the requested report. All integer fields in the record header are little-endian:

`uint32 timestamp_ms`, `uint16 can_id`, `uint8 dlc`, `uint8 flags`, then exactly 8 payload bytes. By default, `flags` is reserved and does not change decoding. A message may set optional `listen_only_flags` to `true`; for that message only, flag bit 0 is the listen-only bit. A message may set optional `counter_hold_flags` to `true`; for that message only, flag bit 1 is the counter-hold bit. A message may set optional `stats_reset_flags` to `true`; for that message only, flag bit 2 is the stats-reset bit. Other flag bits remain reserved.

The network file is JSON with `bus` as a string and `messages` as an array. Each message has `id` integer, `name` string, `expected_dlc` integer, optional `max_gap_ms` integer or null, `counter` object or null, optional `counter_group` string, optional `counter_reset` object or null, `checksum` object or null, optional `listen_only_flags` boolean, optional `counter_hold_flags` boolean, optional `stats_reset_flags` boolean, and `signals` array. Missing boolean flag settings are false. A counter object has `byte`, `mask`, `shift`, and `modulo` integers. A missing or empty `counter_group` scopes the previous counter value to this message only. A non-empty `counter_group` scopes the previous counter value to all messages with the exact same group string, in trace file order; the observed value and modulo for each check still come from the current message's own `counter` object. A `counter_reset` object has `byte`, `mask`, and `value` integers and only matters when the message also has a counter. A checksum object has `byte` integer, `mode` string, optional `seed` integer, and optional `final_xor` integer. Supported checksum modes are `sum8`, `xor8`, and `crc8`; missing `seed` and `final_xor` are treated as 0. A signal has `name`, `start_bit`, `length`, `endian`, `signed`, `scale`, `offset`, `unit`, optional `mux`, optional `invalid_raw` array, and optional `max_delta` number or null. `endian` is either `little` or `big`. `mux`, when present, has `byte`, `mask`, and `value` integers.

Frames are processed in file order. A frame with no matching message creates an `unknown_frames` entry with `timestamp_ms`, `id`, `dlc`, and reason `unknown_id`, and it is not considered by any message. For a known message, `frames` counts every frame with that ID. If `dlc` differs from `expected_dlc`, add one warning with reason `dlc_mismatch`; no checksum, counter, or signal work is done for that frame. If checksum is configured and the DLC matched, `sum8` is `(seed + sum(payload bytes 0 through dlc - 1, excluding the checksum byte)) % 256`. `xor8` starts from `seed` and XORs each payload byte from index `0` through `dlc - 1`, excluding the checksum byte, then uses the low 8 bits. `crc8` starts from `seed`, processes the same DLC-window bytes except the checksum byte, XORs each byte into the CRC, then runs 8 non-reflected rounds with polynomial `0x1d`: when the top bit is set, `crc = ((crc << 1) ^ 0x1d) & 0xff`, otherwise `crc = (crc << 1) & 0xff`. After all bytes, XOR with `final_xor` and use the low 8 bits. The checksum byte itself is read from the eight-byte payload; if `checksum.byte` is outside the DLC window but still between 0 and 7, exclude no byte from the checksum window and compare the computed value to that payload byte. An unsupported checksum mode or value mismatch adds reason `bad_checksum`; no counter or signal work is done for that frame.

Only frames that pass the DLC and checksum gates are valid frames. Valid frames increment `valid_frames`, update stale-gap state, update rolling-counter state, and may update signals. If `max_gap_ms` is an integer, compare the timestamp of each valid frame with the previous valid frame for the same message using `current_timestamp_ms - previous_valid_timestamp_ms` in file order. A positive difference greater than `max_gap_ms` adds reason `stale_gap`; a zero or negative difference does not. DLC and checksum failures do not refresh this previous-valid timestamp. `stale_gap` is additive to the valid frame and signals from that same frame are still decoded unless the frame is listen-only.

The first valid frame for a counter scope initializes that scope's counter and does not warn. After that, the expected counter is `(previous + 1) % modulo`; a different observed value adds reason `counter_jump` and the observed value becomes the new previous value for that same scope. If `counter_reset` is present and `(payload[counter_reset.byte] & counter_reset.mask) == counter_reset.value` on a valid frame, set that scope's previous counter to the observed counter value and do not emit `counter_jump` for that frame. A reset frame still counts as valid, still participates in stale-gap detection, and still decodes signals unless it is listen-only. Counter warnings are additive to the valid frame; signals from that same frame are still decoded unless the frame is listen-only. If both `stale_gap` and `counter_jump` apply to the same frame, emit `stale_gap` first and `counter_jump` second.

When a message has `counter_hold_flags: true` and a valid frame for that message has flag bit 1 set, append one warning with reason `counter_hold` after any `stale_gap` warning from that same frame and before any `listen_only` warning. A counter-hold frame still counts as valid, still updates stale-gap timestamp state, and still decodes signals unless it is listen-only. It does not check the rolling counter, does not emit `counter_jump`, does not update the previous counter value, and does not apply a `counter_reset` marker from that frame. If `counter_hold_flags` is missing or false for the message, flag bit 1 remains reserved.

When a message has `stats_reset_flags: true` and a valid frame for that message has flag bit 2 set, append one warning with reason `stats_reset` after any `stale_gap`, `counter_jump`, or `counter_hold` warnings from that same frame and before any `listen_only` warning. Stats reset clears all aggregate fields for every signal on that message: `count` becomes 0 and `min`, `max`, `last`, and `last_timestamp_ms` become null. The reset happens before decoding signal samples from the same frame, so a stats-reset frame that is not listen-only can immediately become the first sample in the new aggregate window. DLC or checksum failures do not reset stats. If `stats_reset_flags` is missing or false for the message, flag bit 2 remains reserved.

When a message has `listen_only_flags: true` and a valid frame for that message has flag bit 0 set, append one warning with reason `listen_only` after any `stale_gap`, `counter_jump`, `counter_hold`, or `stats_reset` warnings from that same frame. A listen-only frame still counts as valid, still updates stale-gap timestamp state, still updates rolling-counter state including reset markers when the frame is not also counter-hold, and still uses DLC/checksum gates normally. It does not update any signal stats, including non-muxed signals. If `listen_only_flags` is missing or false for the message, flag bit 0 remains reserved and does not emit `listen_only`.

Signal bits use payload bit 0 as the least significant bit of payload byte 0 for `little` signals. A little-endian signal value is built from increasing bit positions starting at `start_bit`, with the first bit becoming raw bit 0. For `big` signals, `start_bit` is an MSB-first linear position where bit 0 is byte 0 bit 7, bit 1 is byte 0 bit 6, through bit 7 as byte 0 bit 0, then bit 8 as byte 1 bit 7; read `length` positions in increasing order and shift them into the raw value from most significant to least significant. If `invalid_raw` is present and the unsigned raw bit pattern is listed there, skip that sample for that signal and emit no warning. Signed signals use two's-complement over `length` bits after the raw value is built and after the `invalid_raw` check. The physical value is `raw * scale + offset`. A muxed signal is decoded only when `(payload[mux.byte] & mux.mask) == mux.value`; skipped muxed signals do not affect counts and do not create warnings. Non-muxed signals are decoded from every valid frame. If a decoded signal has numeric `max_delta` and it already has at least one decoded sample in the current aggregate window, compare `abs(current_physical - previous_decoded_physical)` before updating the signal stats. A difference greater than `max_delta` appends one warning with reason `signal_jump`; the sample is still included in the stats and becomes the new previous decoded value. Signal-jump warnings are emitted in signal array order after any `stale_gap`, `counter_jump`, `counter_hold`, and `stats_reset` warnings from the same frame. DLC failures, checksum failures, listen-only frames, mux-skipped samples, invalid raw samples, and the first decoded sample after a stats reset do not emit `signal_jump`.

Output files are written to the requested report path. If any parent directory of the output path does not exist, the CLI must create it before writing.

The report is one JSON object:

`bus` is the input bus string.

`messages` is an array in the same order as the network file. Each item has `id`, `name`, `frames`, `valid_frames`, `warnings`, and `signals`. `warnings` stays in trace order and each warning has `timestamp_ms`, `reason`, and `detail`; `detail` must always be the empty string `""`. `signals` stays in network signal order and includes every configured signal; a message may have an empty `signals` array. Warning reasons are `dlc_mismatch`, `bad_checksum`, `stale_gap`, `counter_jump`, `counter_hold`, `stats_reset`, `listen_only`, and `signal_jump`. A signal item has `name`, `unit`, `count`, `min`, `max`, `last`, and `last_timestamp_ms`. For a signal with no decoded samples, `count` is 0 and the last four fields are null.

`unknown_frames` is an array in trace order. Empty arrays are valid. Use lowercase reason strings exactly as shown here.
