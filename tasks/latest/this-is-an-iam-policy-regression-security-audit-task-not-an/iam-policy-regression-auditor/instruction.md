This is an IAM policy-regression security audit task, not an application-building task: read `/app/task_file/policy_case.txt`, write `/app/task_file/output/policy_regression_report.json`, and include `/app/task_file/output/policy_regression_analyzer.rs` as a general Rust analyzer that compiles with `rustc --edition 2021 -C opt-level=3`, accepts `<input_path> <output_path>`, and computes the exact answer for any valid same-schema input within 120 seconds without test-harness, shell, Python, or hardcoded-case shortcuts.
Verifier inputs have at most 10 principals, 16 actions, 14 resources, 7 request-context keys, 6 session-tag keys, 70 statements per bundle, and 8 invariants. The analyzer must compare every request in the finite universe formed by all principals, actions, resources, every `CONTEXT` value combination, and every `SESSION_TAG` assignment where each session tag is absent or has exactly one listed value.
Rows are whitespace tokens: `PRINCIPAL id tags_csv|-`, `ACTION id`, `RESOURCE id value tags_csv|-`, `CONTEXT key values_csv`, `SESSION_TAG key values_csv`, `COND id op key values_csv`, `STMT bundle id layer effect principal_patterns_csv action_patterns_csv resource_patterns_csv condition_ids_csv|-`, and `INVARIANT id principal_patterns_csv action_patterns_csv resource_patterns_csv condition_ids_csv|-`. Bundles are `BASE` and `PATCHED`; layers are `IDENTITY`, `BOUNDARY`, `RESOURCE`, and `SCP`; effects are `ALLOW` and `DENY`.
Tags are `key=value` pairs. Condition keys are `principal.<tag>`, `resource.<tag>`, `request.<context_key>`, or `session.<session_tag_key>`. Condition ops are: `StringEquals` (key present and value equals one listed value), `StringNotEquals` (key absent or value equals none of the listed values), `StringLike` (key present and value matches one listed glob), `Bool` (same as `StringEquals` but values must be `true` or `false`), `Null` (listed value `true` means key absent, `false` means key present), and `IpAddress` (key present IPv4 address is inside one listed CIDR such as `10.0.0.0/8`; `/32` is allowed).
Statement and invariant principal/action/resource pattern lists use comma-separated glob patterns where `*` matches any string and `?` matches one byte. A pattern item starting with `!` is a negative pattern. A list matches an id only if the id matches at least one positive pattern, or there are no positive patterns and the implicit positive is `*`, and the id matches no negative pattern.
For one bundle and one request, a statement matches when its principal/action/resource pattern lists match and all referenced conditions are true. The effective decision is deny if any matching `DENY` statement exists in any layer. Otherwise it is allow only when at least one matching `ALLOW` statement exists in `IDENTITY` or `RESOURCE`; if the bundle has any `BOUNDARY` statement whose principal pattern list matches the request principal, at least one matching `BOUNDARY ALLOW` is also required; if the bundle has any `SCP` statement whose principal/action/resource pattern lists match ignoring conditions, at least one matching `SCP ALLOW` is also required. All matched statement id lists in output use input row order.
A regression request is denied by `BASE` and allowed by `PATCHED`. A blocked request is allowed by `BASE` and denied by `PATCHED`. An invariant is violated when any request matching that invariant is allowed by `PATCHED`. The minimal request for each category is the first request in canonical enumeration order: principal row order, action row order, resource row order, then `CONTEXT` rows in input order with each row's values in listed order, then `SESSION_TAG` rows in input order where absent comes before listed values.
The output JSON top-level keys must be exactly `classification`, `base_allow_count`, `patched_allow_count`, `regression_count`, `blocked_count`, `regression_counterexample`, `blocked_counterexample`, and `violated_invariants`. `classification` is `mixed` if there is at least one regression or invariant violation and at least one blocked request, `regression` if there is at least one regression or invariant violation and no blocked request, `safer` if there is no regression or invariant violation and at least one blocked request, otherwise `equivalent`.
Counterexamples are either `null` or an object with exactly `principal_id`, `action_id`, `resource_id`, `request_context`, `session_tags`, `base_decision`, and `patched_decision`; context objects use input key order and session tags include only present tags in input key order. A decision object has exactly `allowed`, `matched_deny_statement_ids`, `matched_allow_statement_ids`, and `missing_gate_layers`; `missing_gate_layers` can contain `BOUNDARY` and/or `SCP` in that order. `violated_invariants` is a list in `INVARIANT` row order, each object having exactly `invariant_id` and `counterexample`, where the counterexample is the minimal request violating that invariant.
