A data platform must plan one overnight backup window. Jobs include snapshots, validations, compactions, and cross-region replications. Some jobs are mandatory, some are optional but improve restore coverage. Jobs form a dependency DAG and consume worker CPU, global network, and scratch storage over time. The jobs are in `/app/task_file/input_data/jobs.jsonl`; workers, capacities, dependencies, conflicts, and dataset freshness targets are in `/app/task_file/input_data/config.json`.

Finish the skeleton Rust program in `/app/task_file/backupplanner/` so that, built with `cargo build --release` and run as `/app/task_file/backupplanner/target/release/backupplanner`, it reads the current input files at runtime and writes `/app/task_file/output_data/plan.json`. The binary must use those absolute task paths and work from any current working directory.

The output is a JSON object with an `assignments` array. Each assignment has `job`, `worker`, and integer `start_time`. Every mandatory job must be scheduled exactly once, optional jobs may be skipped, and any scheduled job requires all of its dependencies to be scheduled and completed first. If a mandatory job depends on an optional job, that dependency becomes required. Worker CPU, global network, and scratch storage capacities may not be exceeded at any minute, conflicting jobs may not both be scheduled, and all ids must come from the input.

Each job row has `id`, `dataset`, `kind` (`snapshot`, `validate`, `compact`, or `replicate`), `duration`, `earliest_start`, `deadline`, `priority`, `cpu`, `network`, `scratch_gb`, `mandatory`, `produces_restore_point`, `restore_value`, `replication_value`, and `optional_value`. Config has `planning_start`, `planning_end`, `network_capacity`, `scratch_capacity_gb`, `workers` (`id`, `cpu`), `dependencies` (`before`, `after`), `conflicts`, and `datasets` (`dataset`, `target_time`, `weight`).

A job runs on `[start_time, start_time + duration)`. CPU and network are checked at each integer minute. Scratch for a job is held from its start until the later of its own finish or any scheduled direct dependent validation job's finish. Jobs may extend past `planning_end` only within the scorer's allowed bounds.

The scorer evaluates priority-weighted deadline lateness, dataset restore freshness, replication coverage, network peak smoothing, scratch efficiency, worker balance, and optional-job value. Public gates include `total_score >= 0.90`, lateness `>= 0.90`, freshness `>= 0.88`, replication `>= 0.84`, network `>= 0.82`, scratch `>= 0.80`, balance `>= 0.78`, weighted lateness `<= 620`, and no network/scratch capacity violation. `/app/task_file/scripts/model.py` is the authoritative scorer. The binary must derive its plan from the current input files, including compatible variants with renamed ids, changed capacities, tighter scratch limits, and different optional-job values. Do not modify any input file or `model.py`.
